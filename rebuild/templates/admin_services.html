How this is known. The web process cannot see the worker process, and does not claim to. core.jobs.mark_stale moves any job running longer than {{ processing.staleness_minutes }} minutes into reconciliation, and it runs on every pass of the worker loop — so a job that has outlived that bound establishes that the reaper has not run. An empty queue proves nothing either way, and the panel says so rather than showing green.

Backup and recovery

Backup state is computed by a privileged process and published into the database for this page to read. It is not read from disk: the admin service runs as a different identity and its unit carries InaccessiblePaths=…/rebuild/.runtime, so every backup state file is masked from its mount namespace. A view that read those paths would report “unavailable” on a perfectly healthy host.
