Welcome credits & balances

Read-only record

Balances are not adjusted from this console. Ledger entries are immutable by design, so “adjusting” a balance can only mean appending a compensating entry, and who may mint credit is a policy question this deployment has not settled. {% if welcome_credit_label %}The {{ welcome_credit_label }} personal welcome credit is granted automatically on verification{% else %}No welcome credit is granted (QUILLMD_WELCOME_CREDIT=0){% endif %}; paid funds arrive only through an explicit Stripe checkout by the account holder.

Every request spends the requester’s personal promotional credit first and only then the paying balance — that user’s own paid wallet, or the organization’s when the department is set to organization-pays. Promotional funds are never transferable and never become a shared balance. Each ledger row below names the balance it moved.

Refunds

Read-only record

Refunds are issued in Stripe, not here, and that is deliberate. This application holds a Checkout-write-only credential, so a button on this page could only move QuillMD’s ledger while no money moved — manufacturing exactly the divergence the signed-event design prevents. The supported path is the operator’s own Stripe access; the refund then arrives here as a signed event and the paid balance is debited automatically. A row below that does not say “succeeded” means no money has moved yet.
