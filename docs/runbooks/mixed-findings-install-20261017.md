## Declared baseline gate

The plan format is `quillmd-mixed-findings-native-install-v1`. Its closed fields
are `format`, `base`, `candidate`, `source_sha256`, `source_worktree`,
`evidence_directory`, `environment_before_sha256`, `environment`, `static`,
`baseline_path` and `baseline_sha256`. Environment must be `{}` and static must
be `[]`. The evidence directory must be unused beneath a private owner-only
parent. The source worktree must be the clean exact candidate executing the
operator. Source publication still verifies the full committed delta and every
listed SHA-256, not merely a filename list.

Capture the fresh read-only full native baseline before preparing the real plan.
Scope validation permits an uncreated canonical baseline target and a placeholder
hash for this read-only capture preparation only; execution requires the actual
private baseline file and exact SHA-256. The captured JSON binds installed base,
candidate, source worktree and source manifest, original changed-source hashes,
environment hash, full database snapshot, configuration, foreign-service
identities, clinical files, static inventory, capture start/end and read-only
provenance flags. Execution refuses pending work, mismatched purpose, future
timestamps or a capture started more than one hour earlier. A stale observation
requires a fresh read-only capture and new plan/declaration binding.

Under the operation and activation coordination locks, the controller captures
another complete baseline before stopping any unit. It re-reads and re-hashes the
declared baseline, compares every watched field, and checks the installed base
HEAD, clean tracked tree/index, original file proofs, original environment bytes
and absence of newly introduced paths. Only a same-row-count fingerprint refresh
of `core_servicehealth` may differ between the earlier observation and this
locked baseline; all other table fingerprints, migration/catalog/sequence/pending
metadata, files, static, configuration and foreign-service identities must match.
The declaration must name this narrow pre-lock refresh explicitly. The snapshot
fingerprint does not itself prove which health-column values changed, so the
independent judge must retain that precise limit.

The locked baseline is retained before comparison. Any discrepancy refuses before
the first owned-service action or source publication. The earlier observed
`fwupd.service` disappearance on the prior installation remains a failed wider
baseline-preservation claim with unknown time/cause; this prospective gate neither
waives nor retrospectively repairs that evidence. A similar pre-stop disappearance
now refuses this act. It is not treated as an implicitly permitted idle service.

The new controller imports only the audited bounded read-only snapshot primitive
from the unchanged coordinated controller; it never calls that controller's
activation. The snapshot contract remains
`sha256-sorted-jsonb-row-sha256-count-v1`: complete public-schema rows become
sorted fixed 32-byte SHA-256 digests, duplicates are retained, and a domain-separated
fold includes the row count. A named cursor fetches at most 128 hashes per batch;
there is no whole-table JSON concatenation or client hash list. The sort has 4 MB
`work_mem` and may spill. One individual row still requires serialization memory.
All tables, watched catalog/function properties, sequences, migration ledger and
pending-work observations share one read-only repeatable-read transaction.
Watched catalog properties are explicitly bounded, not every PostgreSQL property.

Strict equality of all database fields, including service health, starts with the
locked baseline and continues after stopping and immediately before resuming.
Clinical files, static, configuration and unrelated services remain fixed. Only
the existing doctor, admin and worker units restart. Strict database/file equality
ends before resume and separately authorized browser activity; later ordinary
health/audit updates need honest classification, not a retroactive pre-lock waiver.

Failure receipts keep operation stage, sanitized exception class, valid SQLSTATE,
fixed connection category and operator locations; they omit exception messages,
SQL, credentials and clinical text. A missing SQLSTATE is null. Failure before stop
leaves services untouched. After stopping but before any publication attempt,
original-release recovery requires original clean HEAD/index/file/environment
proofs and absent new paths. Once publication is attempted, automatic recovery is
forbidden even if HEAD remains old: a failed fast-forward can already alter files
and index. Any failure after new-unit startup begins attempts every owned-unit stop
and verifies inactivity under the locks. Failed stops remain explicit. There is no
automatic retry, overwritten attempt or clinical restoration.
