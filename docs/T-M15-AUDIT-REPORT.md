## Executive Summary

**Top 5 concerns blocking launch:**

1. **HIPAA compliance gaps** — no "delete my account" and no "export my data" in `apps/transcribe-md/src/app/settings/`. These are legal requirements for any PHI-handling product in the US/EU; launching without them invites regulator attention and user complaints. (CRITICAL × 2)
2. **No forgot-password flow** anywhere in the launch app — no endpoint, no UI link, no token table, no recovery email. Every user who forgets their password becomes a manual support ticket and risks data loss if support can't reach them. (CRITICAL)
3. **Zero rate limiting on `apps/transcribe-md`** — the meddoc-pro app has a `@/lib/rate-limit` module used on its routes, but the launch app imports none of it. Login, signup, upload, and `/api/client-errors` all accept unbounded requests per IP. Combined with a 500 MB upload limit and $0.0145/min Deepgram cost, one abusive client can drive real spend. A 5-attempt-per-user login lockout exists (correctly, 15 min cooldown in `apps/transcribe-md/src/lib/nextauth.ts:74-91`) but it's per-account, not per-IP. (HIGH)
4. **Deployment knowledge lives in this session, not the repo** — root README is unmodified Next.js boilerplate, `.env.production.example` is missing 33 env vars actually referenced in code (including REDIS_URL, MINIO_*, RESEND_*, MINIO_ORPHAN_CLEANUP_*, OPENAI_EMBED_*), no runbook documents first-time deploy / rollback / restore-from-backup. A fresh operator cannot reproduce the environment. `docs/BAA_CHECKLIST.md:36` even references a `docs/ROTATION_RUNBOOK.md` that doesn't exist. (CRITICAL × 3)
5. **Host memory headroom is gone** — `free -h` shows 1.5 Gi used / 1.8 Gi total with **1.9 GB of swap consumed**. All 8 containers are individually modest (~300 MiB aggregate), so this is host-baseline + OS. No container has `mem_limit` or `cpus` configured in `docker-compose.yml`. One runaway PDF render + parallel sign + worker attempt could OOM-kill postgres. No `mem_limit` is a compose-wide gap. (HIGH × 2)

## Section 5: Security Audit

### CRITICAL (see Exec Summary)
- 3 HIPAA-adjacent surface gaps: delete account, export data, forgot-password.

### HIGH
- **[5.2] No rate limiting on transcribe-md** — see Section 2. Reiterating because it's both a DoS/cost vector AND an auth brute-force vector.
- **[5.5] Caddy in MODE A has no security headers** — HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, CSP are all commented out and only live in MODE B (HTTPS). Current active mode is MODE A (IP-only, plaintext). `Caddyfile:104-110`. Next.js `next.config.ts` adds NO `headers()` override either. Every response lacks defense-in-depth.
- **[5.3] Live transcript PHI in console** — `apps/meddoc-pro/src/lib/hooks/useRealtimeSession.ts:334,342` does `console.info('[realtime] assistant transcript done:', transcript?.slice(0, 120))` / `'[realtime] user transcript:', transcript?.slice(0, 120)`. **120 chars of raw transcript into stdout**, which means Docker logs, which (at minimum) sit on disk unredacted. `redactPhi` exists in `@meddoc/ai` but is only bolted onto meddoc-pro's Sentry config, not applied to these log calls. This is in meddoc-pro, not the launch app, but same VPS, same containers, same log pipeline.

### MEDIUM
- **[5.3] Raw `err` in email-export console.error** — `apps/transcribe-md/src/app/api/visits/[id]/export/email/route.ts:87` does `console.error('[api:visits:export:email] send failed:', err)`. Resend errors can carry the recipient email. Wrap with `redactPhi(err)`.
- **[5.4 LOW] Seed scripts print password** — `apps/meddoc-pro/scripts/seed-admin.ts:38-39`, `seed-e2e-admin.ts:66-67` emit bcrypt-plaintext-input to console. Dev-only, but easy accident to paste into a bug report. Harden or gate behind `NODE_ENV !== production`.

### LOW / INFO
- **[5.1] AUTH_SECRET has dev-fallback** — `packages/auth/src/index.ts:94` `|| 'dev_secret_change_in_production_min_32_chars_xyz'`. Currently `AUTH_SECRET` IS set in `.env`. Harden by throwing when unset in production.
- **[5.1] Session TTLs differ by app**: transcribe-md = 7 days (`apps/transcribe-md/src/lib/nextauth.ts:29`), meddoc-pro = 8 hours, shared config default = 8 hours. The 7-day choice is deliberate per the comment ("solo consumer surface, not a PHI-heavy clinical tool"), but transcribe-md DOES store PHI (patient names, clinical notes). Worth revisiting for HIPAA alignment. LOW — debatable, not strictly non-compliant.
- **[5.1 INFO] bcrypt rounds = 12** everywhere — modern standard.
- **[5.1 INFO] Single-session enforcement** via UserSession (T-M2) is working: new login revokes prior sessionToken; expired sessions fall through the jwt() callback's validateSession.
- **[5.4 INFO]** No hardcoded `sk-proj-`, `sk-ant-`, `ghp_`, `xoxb-`, `AIza*` in any `.ts/.tsx/.js/.json` file. Grep clean.
- **[5.4 INFO]** `.env`, `.env.local`, `backups/` all gitignored. Verified via `git check-ignore -v`.
- **[5.2 INFO]** Anti-enumeration: API routes return 404 for "missing" and "not yours" equivalently. T-M11 pattern.

## Things that surprised me

1. **Transcribe-md has login lockout but no rate limiting** — a 5-attempt-per-user cooldown exists (`apps/transcribe-md/src/lib/nextauth.ts:74-91`). It just doesn't extend to per-IP or to non-auth endpoints. The UI+API sub-agent flagged "no account lockout" as a concern — **they were wrong**; the lockout is real, but the missing piece is IP-level throttling. Worth flagging because sub-agent analysis and my own crossed on this one.
2. **Meddoc-pro has Sentry + rate-limit module, transcribe-md has neither** — Not partial adoption; it's binary. These modules were built into the older app and never replicated. The newer launch app is the one without guards.
3. **`redactPhi` exists but is applied to only ONE surface** (meddoc-pro's Sentry client). The name promises PHI scrubbing; the implementation is good. But 53 server-side `console.*` calls in transcribe-md never go through it.
4. **BAA_CHECKLIST.md references a file that doesn't exist** (`ROTATION_RUNBOOK.md`). Finding this took 10 seconds (docs agent opened the file); not finding it before would have been embarrassing if a prospect asked to review BAA prep.
5. **Doctor_edit_patterns at 0 rows** — expected, but it means T-M14.1 hasn't actually been exercised by a real sign yet. The pipeline could throw on the vector INSERT path and we wouldn't know. A single manual sign in the next week would validate the whole chain.
6. **1.9 GB of swap is already in use on the host** — before any real traffic. The containers themselves are small; the Node.js + Caddy + Docker runtime + OS baseline is the load. There's essentially no headroom for burst.
7. **Root README is unchanged Next.js boilerplate** — after 14 milestones, it's impressive that no one needed to touch it. That also tells you no one new has joined the repo, which is relevant for bus-factor planning post-launch.

## Conclusion

Launch-readiness: **4 / 10** today → **7 / 10** after CRITICAL → **9 / 10** after HIGH.

The architecture is solid. T-M1 through T-M14.1 each landed with tests, clear commits, and durable patterns (T-M11 error wrapper, T-M13 resume, T-M14.1 capture hook). The issues in this audit are overwhelmingly **missing features** (HIPAA surfaces, forgot-password, rate limit, runbook, docs) rather than bugs in shipped code. That's a good place to be — additive work, not rework.

The single most important pre-launch action is the CRITICAL block: HIPAA trio (delete + export + forgot-password) + docs sprint. Without these, launching with PHI is a compliance bet. With them, most of the HIGH items are standard operational hardening that can happen in parallel with early customers.

No single finding is worth stopping to fix mid-audit. No CRITICAL bug was found; every CRITICAL is a gap, not a defect.
