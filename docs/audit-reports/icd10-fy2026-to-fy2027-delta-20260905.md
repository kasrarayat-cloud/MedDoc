3. **CMS's own addenda**, quoted verbatim from `icd10cm_order_addenda_2027.txt`:

## The set difference, and why it does not equal the addenda's numbers

| | |
|---|---|
| codes in FY2027 present in neither FY2026 set | **238** |
| codes gone from FY2027 entirely | **21** |
| **billable → header** | **15** |
| header → billable | **0** |

The addenda counts 253 additions and 36 deletions. The difference is the flips,
and it closes exactly: **253 − 15 = 238** and **36 − 15 = 21**. A flip is
recorded by CMS as a delete from one set and an add to the other, so it inflates
both without being a new or a removed code.

## ⚠️ THE VISIBLE-CHANGE ROW — 15 codes stop being billable on 2026-10-01

These are not obscure. `I42.0` is dilated cardiomyopathy, `M72.2` plantar
fascial fibromatosis, `Z68.1` a BMI code — all routinely dictated. From
2026-10-01 each is **refused** and, under ruling #180, the refusal names the
billable child to use instead via `header_use_billable_child`.

## ⚠️ AND A SECOND CLASS: 15 codes vanish outright

`S23.420A/D/S` · `T52.8X1A/D/S` · `T52.8X2A/D/S` · `T52.8X3A/D/S` · `T52.8X4A/D/S`

Billable in FY2026, absent from FY2027 in **both** sets. Unlike a flip, such a
refusal **cannot name a replacement** — CMS removed the concept, so there is no
child to point at. Correct behaviour, and harsher for the doctor.

The FY2026 billable set partitions exactly: **74,689 unchanged + 15 flips + 15
deleted = 74,719.** ⚠️ The two fifteens are a coincidence over disjoint sets, not
one event counted twice.

⚠️ **AND STORED `children` ARE A WRITE-TIME SNAPSHOT.** Every
`header_use_billable_child` drop record written before the switch carries FY2026
descendants. A reader that can reach `billableDescendantsOf` should prefer a
fresh derivation from `code`. Whether the record should carry an edition stamp
is undecided and owner-shaped — filed with #180, unresolved here.

## What is NOT done in this branch, deliberately

The allowlist still imports FY2026 and the FY2026 data files are untouched. This
branch carries the **dataset and its evidence**; the switch itself — repointing
`icd10-allowlist.ts`, retiring the FY2026 files, and re-deriving every gate that
pins `74_719` / `23_467` / `98_186` and the T8 partition — is performed on the
date against whatever `main` is then, because a 26-day-old switch branch is the
long-lived divergence the branch-cadence rule exists to prevent.

⚠️ **AND MERGING THIS EARLY IS CAUGHT, NOT SILENT.** With both editions'
provenance present, `check-icd-edition-current.sh` returns **2 — ambiguous**,
naming both files and refusing to give a staleness verdict. That is the intended
behaviour and it is the reason this branch is safe to hold in the open.
