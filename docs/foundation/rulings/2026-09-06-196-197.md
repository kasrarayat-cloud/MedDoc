## #196 — ADMIN-2 IS THE SUBDOMAIN MODEL

**`<practice>.quillmd.com` per practice**, served by the shared host nginx with
**per-subdomain HTTP-01 certificates**.

**Customer-owned apex domains are NOT in scope.** They file as **ADMIN-2b**,
later.

### What this buys, and it is the reason for the shape

The apex route needs **DNS-01**, which needs a **DNS API token** — money/keys,
STANDING AUTHORITY class **(d)**, and recorded absent. The recon named that as
the decision that *"sets the entire cost"*. The subdomain model **removes the
class (d) dependency entirely**: HTTP-01 proves control of a name over port 80,
which this host already terminates.

**The owner's one manual act, stated so nobody waits on the wrong thing:** a
**wildcard DNS record** (`*.quillmd.com`), added **once**, when the build is
ready. It is not a token, not a credential in the app, and not a recurring cost.
**Ask for it through the war room at that point** — not before, because a
wildcard pointed at an app that cannot yet serve it is a dangling name.

### ⚠️ THE CARRIER ALREADY EXISTS — MEASURED, AND IT CHANGES THE COST

The recon recorded **0 domain/host/subdomain/hostname columns across 592 public
columns**, and that is true *for domain columns*. It is misleading for **this**
ruling:

    schema.prisma:676  model Practice
    schema.prisma:679  /// URL-safe handle. Used for SUBDOMAIN ROUTING,
                       /// deep-linked invites, and "which practice am I on?"
    schema.prisma:681  slug String @unique

**`Practice.slug` is the subdomain key, it is `@unique`, and its own comment
already names subdomain routing as its purpose.** Under #196 the data layer
needs **no new column and no migration** — which is the opposite of what a
reader of the recon alone would budget for. The work is host→practice
resolution, reconciled against the session, plus unpinning the hardcoded app
URLs.

### ⚠️ AND THERE IS A LIVE BLOCKER ON THE CHOSEN ACME PATH — VERIFIED ON THIS HOST

HTTP-01 for a **new** name resolves through whichever server block nginx treats
as the default for an unmatched `Host`. Measured on the VPS today:

    /etc/nginx/sites-enabled/  ->  dealhunter  dealmason  leathererp
                                   quillmd  quillmd-staging  voice.kasitcorp.com

    grep -rn "default_server" sites-enabled/ conf.d/
      -> ONE hit, and it is a COMMENT in `quillmd`:
         "# Specific server_names + NO default_server → cannot hijack co-tenant traffic."

    grep -rln "acme-challenge" sites-enabled/   ->  quillmd   (only)

**No vhost declares `default_server`, so nginx falls back to the first-loaded
server block — `dealhunter`, alphabetically first — and only `quillmd` serves
`acme-challenge`.** A challenge for a brand-new `<practice>.quillmd.com` would
therefore be answered by a co-tenant's vhost and fail.

⚠️ **THE PROPERTY THAT CAUSES THIS IS A DELIBERATE SAFETY PROPERTY, NOT A BUG.**
That comment is load-bearing: refusing `default_server` is what stops QuillMD
hijacking co-tenant traffic on this shared host. **The fix is therefore NOT to
claim the default** — it is a `server_name *.quillmd.com` block that serves
`acme-challenge` and nothing else, which is narrow enough to keep the co-tenant
guarantee intact.

**EVERY INGRESS LEG BELONGS TO THE DEPLOY OWNER**, as ADMIN-2's row already
says. This is recorded as the blocker's *shape*, not as a licence to edit host
nginx.

## #197 — ADMIN-3 IS A MODEL, NOT A FILTER

**Specialty is a property of the practice** — `Practice.specialty`, optionally
overridable per clinician — and it **selects prompts, vocabulary and template
defaults**. The hard-coded one-member imaging set becomes **data**.

### ⚠️ THIS DOES NOT TOUCH R3.8, AND THE DISTINCTION IS THE RULING

R3.8 removed a **visits-board filter**. That stays gone. A saved filter over one
queue and a property that selects which prompts run are different things at
different layers: one is a view over rows, the other decides what the pipeline
generates. **Reading #197 as permission to restore a board filter would reverse
a standing ruling** — it does not, and this paragraph exists so nobody derives
that.

### The substrate, measured

    packages/shared/src/specialties.ts:115-117
      export function isImagingReportSpecialty(id: string | null | undefined): boolean {
        return id === 'ultrasound';
      }

**A literal one-member set**, consumed at `worker.ts:948` and `:978`,
`visits/[id]/page.tsx`, and `note-shape.ts` — which itself records that this
conjunction *"lived in SEVEN places, one of them spelled differently"* and that
the original bug in the area was exactly that. **Turning it into a catalog row
is the point of the ruling**: a new imaging type becomes a ROW, not an edit to a
boolean with many consumers.

⚠️ **`Practice.specialty` DOES NOT EXIST — measured 0 in `model Practice`.** So
unlike #196, **#197 carries a migration.** Per SPEC §3 and ADMIN-1's worked
example, a value added only to a TypeScript union is silently discarded by the
fire-and-forget writer; the column and any enum labels land in a real migration,
declared under §2.5 with author rows at PR-open.

⚠️ **AND THE PER-CLINICIAN OVERRIDE IS "OPTIONALLY", NOT "ALSO".** It is a
second axis and a second nullable column; shipping it in the same change as the
practice property would be two claims wearing one diff. It lands after, or the
row says why it could not.
