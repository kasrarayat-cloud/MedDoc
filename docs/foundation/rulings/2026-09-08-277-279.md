## #277 — OWNER-RULING — **MATERIAL-1: `clinicallyMaterial` IS DERIVED FROM THE CONCEPT'S CLASS**

**STANDING. This lane's item, and it runs AFTER the sequence.**

> `clinicallyMaterial` is **derived from the concept's class**:
>
> - **administrative** — identity, credentials, addresses, boilerplate,
>   **#194(a)** — → **`false`**
> - **clinical** → **`true`**
>
> **Retiring the constant at all twelve sites.**

**THE ARM:** *the production census moves **only** the administrative rows.*

⚠️ **WHY THIS IS A RULING AND NOT A TIDY-UP.** `critical` is
`field.criticality !== 'routine' || field.clinicallyMaterial`, and
`clinicallyMaterial` is hard-coded `true` at all twelve compiler emission sites.
Measured on production: **238 of 238 rows carry `true`**, and **238 of 238 carry
`required = false`**. So `critical` is a **constant true**, and every `||` after
it in `needsInputBlocks` is dead weight — a field's own `required` flag has never
once decided anything.

**#157(d) already named the class** — *"a qualifier that is always true is a
comment"* — and #272's implementation is the case where that comment did real
harm: it is why a record-derived blank withheld the document regardless of
whether anybody had marked the control required.

⚠️ **AND THE ARM IS THE HARD HALF, NOT THE DERIVATION.** *"Only the
administrative rows move"* is falsifiable in exactly one direction that matters:
if a **clinical** row flips to `false`, a field that should block stops blocking,
and nothing in the suite is shaped to notice. The census is taken **before** the
change, from production, and the comparison has one correct answer fixed while
the outcome was unknown — the §2.5 discipline applied to a code change.

**IT RUNS AFTER THE SEQUENCE.** It touches the compiler at twelve sites and
changes a value that gates document withholding; landing it beside the re-issue
act would put two clinical-surface changes in one deploy, and a deploy discharges
only the declaration whose author ran the comparison.

## #278 — OWNER-RULING — **THE TWO CI-ONLY REDS ARE HANDLED BY KIND, AND THE KINDS ARE NOT THE SAME**

**STANDING.**

⚠️ **THE POINT IS THAT "TWO INTERMITTENT REDS" IS NOT A CATEGORY.** They differ
in what the test itself knows, and the correct response differs with it.

### `five narrative shapes` — UNEXPLAINED, so it gets a REPRODUCTION

`gate-157b-denial-contract.test.ts:1023` —
*"(1b) RULE (1) HOLDS ON EVERY polarityBehavior — FOUR behaviours × five
narrative shapes"*. It red in CI on a branch that touches nothing near it and
passes locally.

> **A reproduction attempt under the CI COMMAND, in a SANDBOX, before any merge
> that touches its file.**

The CI command is `npm run test:unit -w transcribe-md` — the whole suite, not the
one file — because *"passes locally"* was measured with a filter and a filtered
run is a different universe. If it does not reproduce, that is recorded as a
failed reproduction and **the finding stays open**; it is not retired.

### `rounds-c1` — SELF-DIAGNOSED, so it gets FILED

`rounds-c1.spec.ts:353-357` fails on its **own** assertion message:

> *"not on the login form — /login redirected us, so the signup session survived
> `clearCookies()`. **This is the flake; it is not a slow render.**"*

> **A TEST THAT SAYS SO IN ITS OWN ASSERTION IS A TEST ASKING TO BE FIXED.**

Its author already did the diagnosis and wrote it into the failure, precisely so
the next reader would not re-derive it. **Filed to Design/Admin (rounds UI), with
the assertion quoted** — quoted rather than summarised, because the sentence is
the finding.

⚠️ **NEITHER IS DISMISSED, AND THAT IS #275 RESTATED WITH TEETH.** *"Probably a
flake"* is the sentence that retires a finding without evidence. One gets an
experiment; the other gets an owner. Neither gets a shrug.

## #279 — DESIGN/ADMIN FILING — **YOUR-BLANKS-2: THE PANEL LISTS EVERY REFUSED CONTROL, NOT ONLY SCAFFOLDED NARRATIVE ONES**

**STANDING. Design/Admin's filing, recorded here because it is the SURFACE HALF
of #272 and this lane built the other half.**

> The *"Your blanks"* panel lists **every control whose fill was refused with a
> named reason** — record-derived refusal, ambiguous age, `manual` — **not only
> scaffolded narrative controls**, with a **kind-aware input** (a **number**
> field for age).

⚠️ **THIS CLOSES A GAP THIS SESSION FLAGGED AND COULD NOT CLOSE.** #272 orders a
refused control *"routed to the doctor's own fill (the Your blanks surface),
exactly as a manual field"*. Measured: the panel is gated by
`scaffoldDefaultOfferable`, which requires `scaffolded === true`, non-empty
`scaffoldText`, and `kind === 'narrative_text'`. **An age control has no scaffold
wording, so it can never appear there as built** — the ruling's arm was
deliverable and its surface clause was not.

**The two halves are now explicit:**

| half | where |
|---|---|
| the document RENDERS, blank, with the reason in the manifest | **#272**, this lane, built |
| the doctor can SEE and FILL that blank | **#279 / YOUR-BLANKS-2**, Design/Admin |

⚠️ **AND THE `manual` CASE IS IN SCOPE, WHICH IS WIDER THAN #272 NEEDED.**
`manual_source_not_filled` renders blank today and reaches no surface either —
the same invisibility, predating the age work. A panel keyed on *"was this fill
refused for a named reason"* covers both, and keying it on the REASON rather than
on the field's scaffolding is what makes it survive the next refusal token
somebody adds.
