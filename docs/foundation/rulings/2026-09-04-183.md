**OWNER-RULING, 2026-09-04. STANDING. Blocking-class.**

⚠️ **THIS RULING WAS MADE ONCE BEFORE AND NEVER RECORDED, SO IT WAS NEVER
EXECUTED.** That is the generalisable half and it is written first. The ceiling
was ruled earlier in the same programme — *"the canon INDEX moves OUT of
AGENTS.md into `docs/canon/INDEX.md`"* — and because no row was written into
`RULINGS.md`, `docs/canon/INDEX.md` did not exist and nothing pointed at the
gap. It surfaced only when a session adding two canon entries tripped the size
gate and went looking for a precedent.

**The rule that would have caught it is already standing:** a ruling is recorded
by the receiving session in its FIRST commit, before anything is built on it.
This is the second instance of that rule failing in a single day — #179 was also
recorded late, by the same session — which is [canon
93](../../canon/93-a-rule-that-depends-on-remembering-has-a-failure-rate.md)'s
argument arriving twice in one shift.

## THE MEASUREMENT

| | |
|---|---|
| `AGENTS.md` before | **122,771 chars** |
| the CANON INDEX section | **56,815 chars — 46% of the file** |
| the size budget | 120,000 (hard read limit 150,000) |
| headroom on `main` | **~220 characters** |

**So the next canon entry anybody wrote would have failed the gate**, and the
gate's own printed advice is *"the fix is the SPLIT rule, not a trim"* — advice
that could not be followed, because everything was already split. The index
itself had become the thing that needed splitting.

## THE RULING

1. The index moves to **`docs/canon/INDEX.md`**, verbatim. Nothing is rewritten
   and no body moves; only the rows change address.
2. **A reader sweep ships with it** — [canon
   60](../../canon/60-a-census-proves-content-not-reachability.md): a census
   proves content, not reachability, and every ledger split ships with its
   reader sweep.
3. The size gate continues to cover **`AGENTS.md` proper**.
4. `AGENTS.md` keeps a **pointer**, not a silent deletion.

## WHAT THE SWEEP FOUND, AND THE PART WORTH REMEMBERING

Readers of the index, found by grep: `gate-172-arm-hygiene.test.ts`,
`gate-agents-md-size.test.ts`, `scripts/check-agents-md-size.sh`,
`scripts/check-read-budget.sh`, `docs/canon/README.md`,
`docs/foundation/MASTER.md`, `docs/foundation/rulings/README.md`.

⚠️ **THE SWEEP FOUND `gate-agents-md-size.test.ts` AND THE FIRST PASS REPOINTED
ONLY `gate-172`.** Four arms then failed — row→file, file→row, the
duplicate-number check and the count reconciliation — each reporting **zero
rows**, because they were still slicing a region of `AGENTS.md` that no longer
existed.

**Finding the readers is not the same act as repointing them**, and the gap
between the two is where a split leaves a reader behind. Worse, the failure
shape is not always loud: an arm that greps an empty region can report *every
entry missing* — or, if its non-vacuity floor is weak, find nothing to check and
**pass**.

Two consequences of the move itself, both caught by the arms rather than by
inspection:

- `INDEX.md` now lives in `docs/canon/`, so the orphan check counted it as a
  body nothing points at. It is excluded alongside `README.md` — the index is
  not an entry.
- The header's stated entry count is a claim, and it was 144 against 146 actual
  rows. *Arithmetic that does not reconcile is a finding.*
