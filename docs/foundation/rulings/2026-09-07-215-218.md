## #215 — OWNER-RULING — FIELD IDENTITY SALTS WITH A CANONICAL **CONTENT** SHA, NOT THE ZIP CONTAINER

**STANDING. FILED — the build is its own change, with its own migration and its
own adversarial pass.** Supplies the fix for the hazard #209's provenance record
could only name and defend against.

> **A field's identity is derived from the DOCUMENT, not from the archive that
> happened to carry it. The salt is a CANONICAL CONTENT sha over the OPC parts'
> bytes — deterministic, container-independent — so that *"identical bytes"*
> means *the same document*, not *the same zip file*.**

### ONE VALUE IS DOING TWO JOBS, AND IT IS RIGHT FOR ONE OF THEM

`package-security.ts:177` computes the value everything hangs off:

    sourceSha256: createHash("sha256").update(zip.source).digest("hex")

`zip.source` is **the container's bytes**, and it is then used for two entirely
different purposes:

| use | site | correct here? |
|---|---|---|
| **INTEGRITY** — *is the IR I hold describing this exact uploaded file?* | `renderer.ts:330`, `roundtrip-verify.ts:554` (both refuse on mismatch) | **YES.** The question is literally about the file. Keep it. |
| **IDENTITY SALT** — *what is this field called, for all time?* | `compiler.ts:836`, `:997`, `:1241` (`fieldId`), `:1070` (`tableId`), `:1483` (`nodeId`) | **NO.** A name that changes when the zip's clock changes is not a name. |

**Five identity derivations, at four call sites, on a salt chosen to answer a
different question.**

### THE MEASUREMENT, ALREADY IN THE RECORD

From `docs/foundation/forms/53-CONTROL-CONSULT-FORM-PROVENANCE.md` — not restated
here as new evidence:

- two runs produced a **byte-identical `word/document.xml`** (`ecb81703…`);
- they compiled to **different** `structureSha256` (`6b58f00f…`, `32c421f3…`);
- three attempts to pin JSZip left **2, then 2, then 14** bytes moving, all of
  them **DOS-time fields in zip headers**.

> **The document was the same every time. The archive never was.** Field identity
> was keyed to the half that moves.

The provenance doc's *"THE FORM IS PRODUCED ONCE"* section is a **workaround for
this defect**. A rule that says *do not run this program twice* is a defect
wearing a procedure's clothes.

### WHY IT IS MIGRATION-SHAPED, WHICH IS WHY IT IS FILED

Changing the salt **re-mints every id**, and ids are the primary key of two
tables — `schema.prisma:3208` `@@unique([compiledVersionId, fieldId])` and
`:3475` `@@unique([visitId, fieldId])`. **185 field rows exist in production.** A
naive landing breaks no test and silently orphans all of them.

The build owes: the canonical content sha (OPC parts' bytes, fixed part order,
container excluded); **a migration carrying certification across the id change**;
a proof that compiles twice and asserts equal ids; its own adversarial pass.
⚠️ **The migration is the FIRST half, not a follow-up.**

⚠️ **AND #217 IS INDEPENDENT OF THIS ONE** — `conceptScope` is keyed by `fieldId`,
not by the salt, so it neither waits for #215 nor is invalidated by it.

## #216 — OWNER-RULING — A SCAFFOLDED CONTROL IS ALWAYS `narrative_text`

**STANDING. Answers the defect this session found in the pinned 53-control
artifact, and rejects both workarounds it offered.**

> **Kind inference by label regex is a CONTENT-CLASSIFYING HEURISTIC. It applies
> to short furniture labels, and NEVER to a control whose default content is
> prose — where the alias IS the sentence.**

### THE DEFECT IT ANSWERS

Control #13 `ros_gi_weight`, alias *"The patient denies unintentional weight loss
or change in appetite"*, compiles to **`kind: measurement`**. `compiler.ts:1573`
takes `identity.alias` as the label; `compiler.ts:1585` tests
`/\b(?:measurement|height|weight|length|width|diameter|temperature)\b/` against
it, and the sentence contains **weight**. Measured with a discriminating control:
the other five GI-ROS clauses infer `narrative_text` correctly; only this one
trips — **and it is the GI alarm feature.**

### THE RULED FIX — A SCOPED COMPILER CHANGE

**Not a per-field override. Not a new form.**

1. The kind moves **only for scaffolded controls**, of which **production has
   ZERO** — so no existing template's kinds move.
2. **ARM:** a census of the four production compiled versions' kinds is
   **byte-identical before and after**, and the six GI ROS clauses compile
   `narrative_text`.
3. **The regenerated artifact RECOMPILES under the corrected compiler and is
   RE-PINNED BY DOCUMENT SHA** — `word/document.xml` `ecb81703…`, which is the
   deterministic half, exactly as #215 argues. The form itself is not reproduced.

## #218 — OWNER-RULING — THE DE-SLUG HAPPENS AT EMISSION, AND THE VERBATIM NEVER RECEIVES AN IDENTIFIER

**STANDING. Lands in #985.**

`encounter-facts/index.ts:745` is `item.finding_verbatim ?? readableFinding(item.finding)`.
`readableFinding` is the only de-slugger and has **exactly two references in the
tree**, so whatever takes the left branch is printed raw — and
`03-extract-entities.ts:308-309` fills that field with **the model's own
identifier** whenever the resolver changed the finding.

Two shapes reach a patient document, neither of which can arise on `main`:

- a real token filed under a system the lexicon does not carry it under
  (`endocrine`/`weight_loss`) prints **`weight_loss`**;
- `finding: 'other'` with no verbatim prints the literal word **`other`**.

**THE THREE-PART FIX:**

1. **de-slug at EMISSION** — the value that leaves the projector is de-slugged
   whichever branch produced it;
2. **the verbatim NEVER receives an identifier** — `finding_verbatim` is the
   doctor's words or nothing, never `item.finding`;
3. **the guard stops skipping `ROS_OTHER`** —
   `gate-179-no-machine-token-in-document.test.ts:68` does
   `if (token === ROS_OTHER) continue`, which is the case it must cover.

⚠️ **ARM IT ON THE SHIPPED FIXTURE'S OWN ROW.** `sample-preview-transcript.ts:84`
emits `{ system: 'neurologic', finding: 'other', polarity: 'denied' }` with no
`finding_verbatim` — the defect is already in the repository's own demo data, so
the arm has a real input and does not need an invented one.
