# RULING #199 — THE ROWS GATE GETS ITS OWN SCOPE, AND IT IS NARROWER

## THE QUESTION, AND WHAT FORCED IT

PR #1022 mechanizes `ADMIN1-ROWS-AT-PR-OPEN.md`: a runtime PR must carry
`docs/foundation/deploys/rows/PR-<n>.md` or the required `test` context fails.
It reuses the deploy gate's `DECLARATION_NONRUNTIME_RE` — `^(docs/|[^/]+\.md$)`
— under an explicit *"one definition, change one change both"* comment, so that
one regex answers two different questions.

**Measured over ALL 53 open PRs before the ruling was asked for: 42 would go
RED on their next `pull_request` event — 21 dependabot, 21 human.** The eight
oldest human PRs carry 88 to 100 runtime files each. Eight of the last twenty
merged PRs would also have been red, including **#1001, whose only runtime file
is one Playwright spec**, and **#1009, a reaper script plus its own gate test**.
Neither can reach production, and both would have been required to declare
visit, patient and signature counts.

⚠️ **AND THE FIRST COUNT REPORTED TO THE OWNER WAS WRONG — 26 of 40.** It came
from a `gh pr list` truncated at its default page size, and it was passed
upward before being checked. The corrected figure was measured by enumerating
every open PR and re-running the gate's own predicate over each one's file
list. *An instrument pointed at a truncated universe answers correctly about
the wrong set*, which is the WATCHED-SET failure this house has now recorded
five times in a week.

## THE RULING

**The ROWS gate stops borrowing the deploy gate's regex and gets a
purpose-named predicate of its own: `VERIFY_REQUIRED_RE`.**

**(a) "RUNTIME" FOR THE ROWS GATE MEANS *SHIPPED* RUNTIME** — application and
package source, `prisma/migrations`, Dockerfiles, compose files. **Tests-only
and scripts-only PRs owe no rows.** The deploy gate's drift regex keeps
counting scripts and tests unchanged, because it answers a different question:
*what has moved since the declared commit*. Two questions, two predicates, and
neither is the other's definition.

> ⚠️ **THIS DELIBERATELY BREAKS THE "ONE DEFINITION" INVARIANT, AND THAT IS THE
> POINT.** A shared definition is only a virtue when both callers are asking
> the same thing. They are not. The comment that binds them must be replaced by
> one that says why they are separate, or the next session will helpfully
> re-merge them.

**(b) DEPENDABOT GETS AN AUTO-GENERATED STANDARD ROWS FILE, NOT AN EXEMPTION.**
The gate itself writes it: lockfile-only diff, npm-audit gate green, image
builds, suite green. **A bumped library ships.** An exemption would have said
*this class of change needs no declaration*; the ruling says the opposite —
the declaration is real, standard, and machine-authorable, so nobody is asked
to hand-write sixteen identical files.

**(c) THE THREE-DIRECTORY WATCHED SET IS FIXED.** §2.5 declarations live in
`docs/deploy-reports/`, `docs/foundation/deploys/` and
`docs/deploy-declarations/`; `DEPLOYMENT_RUNBOOK.md` §2.5 names two, under the
emphatic heading *"AND THE DECLARATIONS LIVE IN TWO DIRECTORIES. SEARCH BOTH,
BY NAME."* The gate as written counts **one**.

⚠️ **SO THE GATE WOULD MECHANIZE THE EXACT MIS-REPORT IT WAS BUILT TO PREVENT.**
ADMIN-1's PR #1004 **did** carry author rows —
`docs/deploy-declarations/admin1-seats-20260905.md`, committed `476cfdbc`, in
the same commit as the irreversible `ALTER TYPE` migration — and this gate
would have called it *"11 RUNTIME FILES AND NO §2.5 ROWS FILE"*. A rule that
mis-reports a session which did nothing wrong does not become discipline; it
becomes noise that the next session learns to route around.

**(d) THE DOCS-ONLY BYPASS IS CLOSED, AND THE DIRECTION OF THE CHECK IS THE
FIX.** Today the gate returns early when the runtime count is zero, and a rows
file is itself `docs/`-prefixed — so a PR whose entire diff is rows files is
classified docs-only and **its rows-file identity is never checked at all**.
The misnumber refusal, which the PR body calls its central fix, is unreachable
for exactly the PR shape that lands rows files. Two merged PRs already have
that shape.

> **A rows file's presence is checked AGAINST THE PR'S RUNTIME DIFF, never the
> other way round.**

**LAND WHEN A PR THAT DID NOTHING WRONG CANNOT GO RED.** That is the acceptance
condition, and it is falsifiable: re-run the predicate over the open set and
over the last twenty merges, and no PR without shipped-runtime files may be
red.

## WHAT THIS RULING DOES NOT DO

It does not weaken the ask. A migration-carrying PR still owes rows, and #198's
`declaration_strictness_for_migrations` is still unused by this gate — filed,
not decided here. It does not bless the gate's remaining false-greens: a
zero-byte rows file still passes, an empty diff still reports green rather than
cannot-tell, and nothing checks that the rows file existed **before** the
runtime code, so the *"AT PR-OPEN"* in the gate's own name is not yet a
property it measures.

# RULING #200 — #195 BINDS ADMIN-5'S INVARIANT AND ITS PROOF, NEVER ITS MECHANISM

## THE QUESTION

Ruling #195 filed ADMIN-5 and named its guard shape: *"a partial unique index
or a SERIALIZABLE transaction, NEVER a count read then acted on"*. The
implementation on `feat/admin-5-owner-demotion` uses **neither**, and says so —
it measured both defective for this particular invariant and chose a third. It
then routed the correction *"to the owner in the PR"*, and no PR was ever
opened, so the question sat unasked while 1,583 finished lines sat unreviewed.

## THE RULING

**#195 binds the INVARIANT and its PROOF. It does not bind the MECHANISM.**

| what is binding | what is not |
|---|---|
| a practice never drops below one OWNER | which lock achieves it |
| enforced inside ONE transaction, against concurrent demotions | the two shapes #195 happened to name |
| proven by a concurrency E2E with a NEGATIVE CONTROL | — |

**Both named shapes are measured wrong for a MINIMUM invariant, and a third
shape is therefore acceptable.**

- **A partial unique index bounds a MAXIMUM.** It can force *at most one* row
  with a property. This invariant is *at least one*, and no uniqueness
  constraint expresses a lower bound.
- **SERIALIZABLE falsely aborts.** It would roll back demotions in *unrelated
  practices* that merely touched overlapping read sets, and it delivers the
  last-owner refusal to the caller as a **retry**, not as an answer. A doctor
  told to try again is not told they are the last owner.

**THE EXPECTED MECHANISM, stated so the builder is not left guessing:** a
**practice-row lock** — `SELECT … FOR UPDATE` on the practice row — with the
owner count and the demotion **in the same transaction**, **scoped to that
practice** so unrelated practices never abort.

## WHY THIS IS RECORDED AS A RULING AND NOT A CODE REVIEW

The obvious reading of #195 is that its two named shapes are the permitted set.
A session holding that reading would have sent this implementation back to be
rebuilt around a constraint that cannot express the invariant — **shipping a
guard its own author had measured as wrong, in the name of obeying a ruling.**
The distinction between an invariant and a mechanism is the thing that has to
be written down, because it is what the next such disagreement will turn on.

⚠️ **AND THE ROUTING FAILURE IS THE OTHER HALF, WORTH AS MUCH AS THE ANSWER.**
*"I will raise this with the owner in the PR"* is not a route to the owner
until the PR exists. Finished work that carries an owner-class question is not
parked; it is **invisible**, and the question is unasked rather than pending.
The habit this earns: **the artifact that carries the question opens before the
work is called done**, even when nothing is ready to merge — a draft PR is a
route, a local branch is not.

## THE CONDITIONS ON MERGING

ADMIN-5 merges only after **its own adversarial pass over the FINISHED DIFF**
and its own §2.5 rows, per the standing clinical-path and PR-open rules. The
probe matrix that measured both named shapes defective
(`docs/foundation/evidence/admin5-last-owner-guard-probes.md`) and the chosen
mechanism go at the TOP of the PR body, not in a comment, so a reviewer meets
the deviation before the diff.
