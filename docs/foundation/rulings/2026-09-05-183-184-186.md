## #184 — THE COMPOSED DEPLOY JUDGEMENT

**STANDING. The deploy discipline for a multi-passenger `main`.**

> **ONE deploy of `main`. Each passenger's OWNING session supplies its §2.5 rows.
> Judge the UNION. Every row names its author. A passenger without rows is a
> FINDING, not a pass.**

**The premise is already canon** — *a declaration is bound to a CHANGE; a deploy
ships a TREE* — and the reference case is R5, which reached production inside a
deploy judged "16 of 16" where **not one of those sixteen rows could have
detected an R5 regression.** #184 is that entry turned into a procedure.

**Standing practice landed with it:** `scripts/union-gate.sh` — every gate file
touched by the deploy range runs on the MERGED tree.

⚠️ **THE SCRIPT'S FIRST VERSION HAD THE DEFECT IT EXISTS TO PREVENT.** It listed
six `packages/ai/**` gate files, ran only the twelve under the app, and printed
*"every passenger's gates pass"* — six gates belonging to the largest passenger
never executed. Now it converts out-of-app paths, REFUSES anything it cannot
address, and asserts gates-found equals gates-run. **A union gate that silently
drops a passenger is worse than no union gate**, because it produces the exact
sentence the ruling asks for while measuring less than each passenger's own CI.

⚠️ **FIRST APPLICATION, AND IT IMMEDIATELY FOUND WHAT IT WAS BUILT TO FIND.** On
the deploy of `ef515f5f`: **eight runtime passengers, ZERO authored rows.** The
board request went out and nothing came back, so every row is derived by the
deployer — and PR #967 rides wholly unjudged. Recorded as findings in

## #186 — CI MECHANISMS, AND TWO PASSENGER FIXES

**STANDING.**

### The two passenger fixes — shipped as PR #969, riding the composed deploy

Both are gaps this session **recorded in #182's own body as shipped defects**
before they were fixed, which is why they were findable at all:

**(a) `SessionUnverifiableError` mapped to a real HTTP 503.** The class declared
`readonly status = 503` and **nothing read it** — `withApiHandler` fell through
to the catch-all 500. A doctor whose session could not be verified got *"an
unexpected error"*; they now get 503 + `Retry-After: 2` and the true statement
that they have not been signed out.

**(b) `recordLogoutAttempt` passes `success` explicitly.** It never passed the
field and `logAudit` defaults `?? true`, so **a failed sign-out would have been
filed in the audit log as a successful one.** ⚠️ The direction is what makes it
serious: the failure mode is a security event recorded as its own opposite, in
the table used to establish what happened.

### The three CI mechanisms

1. **axe-core runs on every PR regardless of base** — an a11y gate that skips by
   base branch is a gate with a hole shaped like whoever chose the base.
2. **`retire-branch.sh` refuses to delete a branch that is the base of an open
   PR** — deleting it closes that PR's diff silently.
3. **The deploy-candidate marker** — `main`'s in-flight runs block a merge only
   when that commit is a *declared deploy candidate*, read from a tracked marker
   by `merge-pr.sh`. Today every in-flight run on `main` blocks every merge,
   which is strictly safe and costs the programme hours; the marker makes the
   block precise instead of universal.

⚠️ **AND (3) NARROWS A GUARD, SO IT CARRIES A HIGHER PROOF BURDEN THAN THE OTHER
TWO.** The merge side already has the worse record of the two doors — a 3-of-4
citation on a deployed commit, and a run killed at 33m39s that another session
was deliberately waiting for. Narrowing it must not re-open either. The refusal
arms are proved by asserting `gh pr merge` was never invoked, not by reading the
exit code.
