## #226 — OWNER-RULING — ARCHIVE THE SIX, AS A RULED MUTATION

**STANDING. CLASS (d), DECIDED.**

> **The six test practices and their seven inactive users are ARCHIVED** — a
> ruled mutation with a **committed declaration**, executed **through the
> audited admin path**, **restorable: soft archive, never hard delete**. The
> declaration **names each practice by id and its classification.**

**Same act:** the five users carrying `isActive = false` with
`deactivatedAt IS NULL` are **reconciled to one truth** — ruling #221's
divergence caught in real rows rather than in a predicate.

### ⚠️ TWO MEASURED FACTS THAT BEAR ON EXECUTION

Recorded here, in the ruling, so the next reader does not rediscover them.

**1 · NO ADMIN PATH WRITES A PRACTICE ROW.** Measured: zero
`prisma.practice.update|updateMany|delete|deleteMany` in `apps/transcribe-md` or
`apps/meddoc-pro` outside tests. The admin API exposes `users`, `audit-logs`,
`usage`, `system`, `hipaa`, `threats` — **no practices**. And there is no
`PRACTICE_ARCHIVED` among the **156** `AuditAction` values.

⚠️ **Adding one is IRREVERSIBLE** — Postgres has no `ALTER TYPE … DROP VALUE`,
which PR #1015's own §2.5 rows record as a permanent cost. So *"through the
audited admin path"* is not a matter of calling something that exists; it is a
decision about whether to build one, and that decision carries an irreversible
schema act for a bookkeeping cleanup of six test rows.

**`USER_DEACTIVATED` already exists** and honestly covers the seven users.

**2 · NOTHING READS `practices.isActive`.** The only `isActive` reads in the
tree are on the **USER** row (`apps/transcribe-md/src/lib/auth.ts:69`); no query
filters practices by it.

> **So a practice archive by that flag is a MARKER, not an enforcement, and it
> must never be described as disabling anything.**

That is not an objection to the ruling — these six hold no live member and no
visit, so there is nothing to disable, and a marker is exactly what a
bookkeeping archive needs. It is a constraint on **what may be claimed
afterwards**.

### WHAT MAKES IT A RULED MUTATION

`scripts/run-ruled-mutation.sh --declaration <path> -- <command…>` is the only
door, and it requires the declaration to be **TRACKED, UNMODIFIED and
COMMITTED** — so the commit timestamp provably precedes the rows, and the record
cannot be composed once the outcome is known. That is the whole product §2.5
buys, and B7's backfill is the reference case for losing it by one minute
fifty-seven seconds.

## #227 — OWNER-RULING — THE RESIDUAL CLOSES BY DECLARATION, NOT JUDGEMENT

**STANDING.**

The derived-dimension arm checks **mentioned in code**, not **varied**. A
property written once at a constant satisfies it. I named that residual and left
it open, on the ground that deciding which constants are deliberate is a product
judgement rather than a test fix.

> **It is a product judgement — and a DECLARATION is how a product judgement
> gets written down instead of inferred.**

**The matrix declares its intentional constants in an explicit allowlist, with a
one-line reason each:**

    rowPrototype: false   — "prototypes never offer"

**The arm reds on any property the mirror reads that is neither varied nor on
the allowlist.**

### ⚠️ THREE STATES, NONE SILENT

| state | verdict |
|---|---|
| varied across the cross-product | **pass** |
| declared constant, with its reason | **pass**, and the reason is on the record |
| neither | **RED** |

**An allowlist entry is a claim somebody made on purpose. An undeclared constant
is an oversight wearing the same clothes.** The arm could not tell them apart;
now it can, and the cost of the distinction is one line of prose per constant.

## #229 — OWNER-RULING — BOTH PRs STAY DRAFT; ROUND FIVE; THEN THE COMPOSED DEPLOY

**STANDING.**

Round five runs on **#1018's fixes** and **#1036's remaining findings**. They
leave draft **on a clean round** — the condition, not a count of rounds served
(#223).

### ⚠️ "WITH THEIR ROWS" IS THE HALF THAT IS EASY TO DROP

**A declaration is bound to a CHANGE. A deploy ships a TREE.** Two changes
reaching `main` before either ships leaves one **silently unjudged** unless the
deploying declaration names the **full diff**.

Each PR carries its own §2.5 rows — `PR-1018.md` and `PR-1036.md` — and **both
must appear by name in the composed declaration.** The R5 reference case is a
deploy judged *"16 of 16"* against a declaration that could not have detected a
regression in the other change it shipped: a true sentence doing misleading work.
