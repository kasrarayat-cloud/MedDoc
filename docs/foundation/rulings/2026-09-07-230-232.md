## #230 — OWNER-RULING — NO NEW ENUM VALUE FOR SIX TEST ROWS

**STANDING.** Answers the one question this session surfaced rather than took.

> **The act follows the `gate0` precedent exactly.**

`scripts/execute-gate0-deactivation.sql` is this repository's shape for an
owner-ruled one-shot, and it is followed line for line:

- **one raw-SQL one-shot**, in a single transaction;
- **the declaration committed FIRST**, in `docs/deploy-declarations/` — ⚠️ **not
  `docs/foundation/deploys/`**, which `declaration_resolve` scans and where a
  filename whose last segment is not a commit sha returns **rc=2 and blocks the
  next production deploy** (`scripts/lib/declaration.sh:126,134`);
- **pre-guards bound to the declared population** — the act refuses if the world
  is not what the declaration says;
- **post-verification that ROLLS BACK** on any mismatch.

### THE USERS

- `deactivatedAt` reconciled to the **audit-trail timestamp, RE-DERIVED AT RUN
  TIME** — and the act **refuses if the witnesses disagree**. A literal that had
  drifted from its own evidence is the fabrication this exists to prevent.
- **`updatedAt` untouched, and ASSERTED untouched.** It is `@updatedAt`, so a
  Prisma write would bump it and **destroy the corroborating witness to the very
  timestamp being recorded**. It is not named in the UPDATE, and a post-verify
  arm fails if it moved.
- `deactivatedBy` = **the ruling identifier** — the established practice in that
  column. The other two users in this same population read
  `gate0-ruling-2026-08-05`. **The actor for a ruled one-shot is the RULING**,
  and the column has no FK precisely so it can say so.

### THE PRACTICES

`practices.isActive = false`, **as a MARKER, and stated as a marker in the
declaration.** Nothing reads it today — measured, the only `isActive` reads in
the tree are on the USER row (`auth.ts:69`). It disables nothing and is not
claimed to.

**The record is the declaration commit plus the users' existing
`USER_DEACTIVATED` rows.**

### ⚠️ AND THE DEFERRAL IS THE DECIDED PART

> **A real `PRACTICE_ARCHIVED` action arrives with practice-lifecycle work in the
> ADMIN arc, with its own migration. These six get their rows then.**

Adding an `AuditAction` value is **irreversible** — Postgres has no
`ALTER TYPE … DROP VALUE`, a permanent cost PR #1015's own §2.5 rows record. An
irreversible schema act is not spent on a six-row bookkeeping cleanup **and the
cleanup is not held hostage waiting for one.** Both halves of that sentence
matter: the deferral is not a refusal, and the archive is not blocked.

## #231 — OWNER-RULING — #227 RATIFIED AS BUILT

**RATIFIED.** And what is ratified is specifically the part that looks like a
defect and is not:

> **The arm rejecting its own author's drafts is THE POINT.**

Two rejections, on the first draft of the table it guards:

| rejection | why it was right |
|---|---|
| **a FALSE CLAIM on the allowlist** — `rendererBinding` declared a constant | it is **varied**, through a loop variable one level in (`rendererBinding: { …, bindingType }`). Declaring it to silence the arm would have put a false claim on the allowlist, the one thing an allowlist must never carry. |
| **a STALE entry** — `unmentionedPolicy` | the mirror **does not read it**, so the exemption covered nothing while sitting there looking load-bearing. |

### ⚠️ AND THE CAST-FORM READ DETECTION

Testing the new RED state, the probe was written
`(field as { criticality?: string }).criticality` — and the arm stayed
**37/37 GREEN**, because `field.` never appears literally in that text so the
property was never counted as read.

> **That is the `as any` admin-door shape** — six doors written
> `(prisma.user as any).update` and invisible to the obvious grep.

`READS_RE` now matches both spellings. **A cast is exactly how the first form is
written when the property is not on the declared type — which is precisely when
a new, unwatched input arrives.** The instrument was wrong in the direction that
hides new inputs, which is the only direction that matters.

**Lands with #1018 after #1040 merges.**

## #232 — OWNER-RULING — THE ORDER IS THE RULING

**STANDING.**

> **#1040 on citation → the #226 one-shot on production under its declaration →
> JUDGE → round five on #1018.**

The judgement is: **five timestamps equal the witness; six practices flagged;
nothing else moved.**

### ⚠️ EACH ARROW IS A GATE, NOT A STEP

- **The declaration cannot be committed before #1040 lands.** The pre-commit
  hook refuses source citing an unrecorded ruling — and it is *correct* to; this
  session met that refusal twice tonight and did not override it.
- **The one-shot cannot run before its declaration is committed.** The runner
  refuses an untracked, modified or uncommitted declaration. B7's backfill lost
  exactly this distinction by **one minute fifty-seven seconds** — 175
  irreversible rows landed *before* the declaration describing them, and every
  declared quantity matched, and the record still could not tell an honest
  declaration from one composed once the outcome was known.
- **The judgement is not the act's exit code.** It is a separate re-derivation
  against the declared rows. An act that reports its own success has not been
  judged.

> **A step skipped here is not a shortcut. It is the removal of the thing that
> makes the act auditable.**
