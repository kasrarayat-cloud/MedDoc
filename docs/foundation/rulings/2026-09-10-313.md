## #313 — ONE ITEM PER BULLET

**STANDING.**

> **When a form repeats one list-valued control as bullets, each dictated item
> goes on its own bullet. Nothing is dropped, and nothing is printed twice.**

### WHY — MEASURED ON THE FORM THAT IS ACTIVE TODAY

Acceptance row 1 of the owner's eleven-row acceptance is *"distribution one per
bullet"*. The certified, active version of his consult form (`18a7ae19`) does
the opposite. Every repeated control resolves on its own and receives the
**whole** joined list. This is its stored round-trip proof:

| controls | each one prints |
|---|---|
| Past Medical History ×3 | `Hypertension; Type 2 diabetes mellitus` |
| Impression ×4 | `Stable chronic conditions with no acute change` |
| Plan ×5 | `Continue current medications; Follow-up in three months` |
| the four HPI intro lines | the chief complaint |

The confirm (#312) adds Past Surgical History ×3 to that list. So #313 is a
**precondition of activating the re-issued form** (amendment to #312), and a
correction of a defect that is already live.

### WHERE THE PASS RUNS — ONE SEAM, EVERY PATH

It runs in `prepareTemplateTwinFill`, **after the bridge overlay and before
clinician overrides**. Every path converges there: the certification round
trip, the visit fill, the on-demand export, the sign-time re-fill, the pre-sign
preview and the insert-default door. The pass mints no facts, so the fact-set
sha is unchanged. It is order-independent and returns its input order.

Running before the overrides is what keeps a doctor's own edit winning. The
blank-only rule for the doctor's scaffold default (#194) then judges the state
after distribution, which is the same state the preview and the door see.

### WHAT IS A BULLET GROUP — NARROW, AND REFUSED IN FULL WHEN IN DOUBT

A group has at least two members, and every member:

- is a plain `narrative_text` content control, not a table cell or a repeating
  row, and not laterality-critical;
- shares the same part, and the same **declared** alias and tag (the label
  comes from the alias);
- **is the only control in its paragraph, with no visible text outside it.**
  This is a new compiler-set IR property, `soleParagraphControl`, stripped from
  structural identity the way #191's was. **If the property is absent there is
  no group**, so every stored IR keeps exactly today's behaviour;
- sits in one unbroken run of display order;
- has the same scaffold text;
- has a list-valued mapping, **identical on every attribute**. The compared
  keys are derived from the mapping schema itself.

A doubt about any member refuses the **whole** group, returning today's output
byte for byte. It never splits a group. This refuses the shapes where a shared
alias carries a different meaning: "Right leg: [ ] / Left leg: [ ]",
"Mother: [ ] / Father: [ ]", a ROS paragraph of six controls, the two
total-time lines, fixed grids and repeating rows.

### HOW ITEMS ARE PLACED

The pass acts only when every member came out of the resolver identical:
`supported`, the same joined value, the same cited facts. **Anything else
(conflict, denial withheld, needs input, practice default, record-derived) is
left exactly as it is.**

Items are the cited, affirmed facts, grouped by the same derived text the join
already deduplicates on. There are K items and N bullets:

| case | placement |
|---|---|
| K = 1 | bullet 1 gets today's resolution **byte-identically**; the rest are unused |
| 2 ≤ K ≤ N | one item per bullet; the rest are unused |
| **K > N** | bullets 1..N−1 get one item each, and **bullet N gets the remainder joined** |

Each placed bullet cites only its own facts. Its value is composed by the same
functions the validator re-derives with, so the validator accepts it unchanged.
A denied fact in the group rides on bullet 1, so the mixed-polarity warning
fires once rather than N times. **Before anything is emitted, the pass
re-validates its own output. On any doubt it collapses to "bullet 1 = today's
resolution, the rest unused", and that collapse always validates. The pass can
never be the reason a document is withheld.**

An unused bullet is `not_mentioned`, reason **`list_item_slot_unused`** (the
only new token). It is **cleared**, and counted in its own optional
`slotsUnused` bucket, so it is not in "N still blank — nothing dictated". A
required member's unused slot is exempt from `REQUIRED_FIELD_NOT_MENTIONED`
**only** when it sits after every member that carries an item. The validator
gains three group checks, all run over the stored manifest so certification
re-verification holds:

- an item dropped, blocking;
- an item printed twice, a warning, which also blocks certification;
- an unused slot anywhere it is not legitimate, blocking.

The resolver and validator versions are bumped in the same commit.

### THE FIVE CALLS MADE ON THE OWNER'S BEHALF — AND WHY

| # | question | decided | principle |
|---|---|---|---|
| O1 | Unused bullets print as **empty paragraphs**. The dash is the control's own scaffold, so filled bullets print without "- ", exactly as today's joined value already does | **accepted** | *the machine never prints an undictated default*: a "- ____" placeholder is not a finding. ⚠️ **The owner's eye on a render is still owed** (class c) and is reported as what remains |
| O2 | More items than bullets | **join the remainder into the last bullet** | *never withhold, never drop*: collapsing would put all of them on bullet 1 anyway, and refusing would lose an item's own line |
| O3 | Offer "insert your default" on an unused bullet? | **withdrawn** | the offered text would be the template's own underscores, which is noise and not a default |
| O4 | The four HPI intro lines are mapped to `chief_complaint`, which is one fact | line 1 fills and **lines 2–4 are empty**, where today the complaint prints four times | a consequence of the confirmed mapping, not of distribution; reported so the owner is not surprised |
| O5 | The new IR property must reach the re-issued draft `d2120cdd` | **a ruled, declared, in-place write to that DRAFT's compiled IR**, identity-safe because the property is stripped from both structural hashes. **The certified, active `18a7ae19` is NOT touched**: it is replaced on activation, and a certified row is immutable anyway | an irreversible act gets a committed declaration first |

### WHAT IT DOES NOT DO

It changes no stored IR at deploy, so no existing form's output moves until its
IR carries the property. It changes no per-field resolver outcome. Only the pass
decides placement, and only on a group the grouping rule accepts.

## AMENDMENT — 2026-09-11 · ROUND ONE, AND THE ROLLBACK FLOOR RESTATED

**Appended; nothing above is rewritten.** A four-lens refutation pass over
`b7c0a190` ran, with every finding independently verified.

**What held.** Across 32 cases (N = 2–5 bullets, K = 0–7 items), the rendered
bullets joined back equal the pre-#313 joined value exactly, with no loss, no
repeat, and no denied fact turned affirmed. On the pinned form, `structureSha256`,
`staticContentSha256` and every fieldId are unchanged, and an IR without the
property fills byte-identically. The backfill door could not be broken. The
re-issued form still certifies: 22 filled against a floor of 10.

**What was broken, and fixed by NARROWING only**, so by #304's exit rule there
is no further round:

1. **A withheld document** (the one blocking finding). The doctor inserts the
   scaffold default on EVERY bullet over an ambiguous or conflicting fact.
   `LIST_ITEM_DROPPED` then counted the uncertain fact as dropped and withheld
   a document that rendered before #313. The group checks now skip a group in
   which no bullet carries a dictated item. An all-unused-slot group is still
   refused by `LIST_SLOT_UNUSED_ILLEGITIMATE`.
2. **A stale proof.** The backfill now also refuses a draft that holds a stored
   synthetic proof. Such a proof would fail re-verification under the new IR,
   with a blocker that blames unchanged mappings. `d2120cdd` holds none.

⚠️ **THE ROLLBACK FLOOR WAS STATED WRONGLY, AND THIS IS THE CORRECTION.** The
ruling and the first commit said the floor arms when the backfill writes the
draft's IR. **It arms earlier: at the first compile after the deploy of ANY
form that has a control alone in its paragraph.** That covers any practice's
upload, `ingestTemplateTwin`, and `uploadNativeTemplateAction`, and it
typically comes before the backfill. From then on, code below #313 cannot parse
that IR.

**Checking whether the floor has been crossed, read-only:**

    SELECT count(*) FROM template_twin_compiled_versions
     WHERE "compiledDocumentIr"::text LIKE '%soleParagraphControl%';
    -- 0 means a rollback below #313 is still available

After the floor is crossed, a rollback needs a declared mutation that strips the
key from every such IR first. The deploy declaration carries this paragraph.

**Named and not fixed:** the Allergies pair on the re-issued form is refused by
G7, because its two mappings differ on `polarityBehavior` AND `approvedSynonyms`.
So both bullets keep today's whole list, and the certification's
printed-twice blocker cannot see a refused group. It is FILED. Reconciling those
mappings would edit transferred certified rows, which is a new decision.
