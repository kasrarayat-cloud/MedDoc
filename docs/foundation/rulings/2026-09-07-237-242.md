## #238 — OWNER-RULING — THE `practiceId` COMPARISON, CLOSED IN THE DATABASE

**STANDING. FIRST, and it is first because it is the only remaining door.**

`users_no_orphan_member`'s UPDATE early-return omits the
`NEW."practiceId" = OLD."practiceId"` comparison its sibling guard carries three
functions up. So a live member can be **MOVED** into an ownerless practice: the
removal guard exempts the row (a CLINICIAN was never an active owner), the
orphan arm exempts it (it was already a live member), neither takes the advisory
lock, and the end state is **exactly** what arm 14 refuses on INSERT.

> **Identical end state, opposite verdicts, decided only by how the member
> arrived.**

**CLOSED IN THE DATABASE, not at a door.** That is #210's whole premise and it
applies to its own defect: the guard must not depend on remembering which
surface writes `practiceId`.

⚠️ **AND THE VERIFICATION IS THE PART TO COPY.** The verifier applied the
one-line fix, **asserted it had landed in the DATABASE** —
`position('NEW."practiceId" = OLD."practiceId"' in prosrc)` — rather than in the
file, and re-ran the shipped proof: **33/33, unchanged**. It also established the
negative that makes this the *only* door: under the shipped trigger the forbidden
state is reachable by **no other legal write**.

⚠️ **REACHABILITY, STATED HONESTLY:** no runtime writer of `users.practiceId`
exists today. **Latent, not live** — and fixed anyway, because this migration's
stated rationale is enforcement that does not depend on doors nobody has written
yet, and the schema comment names that future door by name.

## #239 — OWNER-RULING — ONE PREDICATE FOR "LIVE MEMBER", AS FOR "ABLE OWNER"

**STANDING.**

`wouldStrandPractice` counts members with a **bare row count**; the trigger counts
them with `users_is_live_member`. The two layers therefore disagree on real
production practices, and the friendly refusal **permanently blocks a write the
trigger allows**, telling the doctor to do something impossible.

> **The app layer DERIVES its definition from the trigger's. It never keeps a
> second count.**

This is #221's rule — `activeOwnerSql` as the ONE predicate for *able owner* —
applied to the other half. **A rule with two readers drifts**, and this one
drifted inside the very change that exists to end that class.

⚠️ **A refusal naming a remedy that cannot be performed is worse than no
refusal**, because the doctor spends the afternoon trying to perform it.

## #240 — OWNER-RULING — THE PROOFS ARE REPAIRED BEFORE THEY ARE TRUSTED AGAIN

**STANDING. Five repairs, and each is a case of an instrument that cannot fail.**

**(a) EXEMPTION 1 GETS AN ARM THAT REDS WHEN IT IS REMOVED.** It is invisible to
all 33 arms — *including arms 28–32, the five written to protect it*. Five arms
pointing at a clause none of them can see is the sharpest possible statement of
the problem.

**(b) `t210_try` DISTINGUISHES A SETUP FAILURE FROM A REFUSAL.** It credits a
refusal raised by an arm's **own SETUP** to the arm, so a REFUSED arm whose
fixture was never built passes — and reports **0 vacuous** while doing it.

**(c) THE LOCK-ORDER ARM STRIPS COMMENTS.** It is satisfied by a `/* */` block,
so the advisory lock — the one ruling #220 ratified *because it was proven
load-bearing* — can be DELETED with the gate 14/14 and all 33 arms green.

**(d) THE RACE HARNESS READS ITS OVERLAP WITNESS ON THE CELL #220 RESTS ON.**
`OW` is computed, printed, and **never read** on the WITH-lock cell. A witness
nobody reads is decoration.

**(e) EXIT 2 STOPS BEING A FREE PASS, AND THE CONDITION IS NAMED.**

> **CI turns exit 2 into a pass ONLY when the witness says the race genuinely
> did not occur. A DEAD CONTROL IS A FAILURE.**

That is the precise line canon 125 was reaching for: *a green step whose success
is compatible with cannot-tell must be read, not trusted.* "Cannot tell because
the two sessions did not overlap" and "cannot tell because my instrument is
dead" are different facts, and only the first is survivable.

## #241 — OWNER-RULING — THE TWO RECORDS ARE CORRECTED TO SAY WHAT IS TRUE

**STANDING.**

**(a) THE STALE COMMENT SAYS WHAT THE CODE DOES, AND WHY.**
`migration.sql:138-140` asserts *"Suspension DOES count"*; the function three
lines below excludes suspended rows. ⚠️ **THE CODE IS RIGHT.** The exclusion is
deliberate and **test-pinned by name** — counting a suspended member would make
suspending a solo practice owner impossible, which is a legitimate operations
action. So the COMMENT is the defective artifact and the comment is what changes,
**with the reason attached** so the next reader does not re-open it.

⚠️ **AND THE ADVERSARIAL PASS GOT THIS ONE BACKWARDS**, which is why the
verification step exists: a lens reproduced the behaviour exactly and then named
the wrong artifact defective. **A correct observation with an inverted diagnosis
is the most expensive kind of finding**, because acting on it would have made
the product worse — the measured alternative breaks solo-owner suspension.

**(b) THE §2.5 ROWS SAY ZERO, WITH THE SECOND QUERY.** *"Six practices are
already in the state this trigger forbids creating"* is **FALSE**. Production has
**ZERO** practices with a live member and no able owner; the six are inert, every
member `isActive = false`, and the PR's own board file says so on its first line.

⚠️ **THIS IS CANON 124 UNAPPLIED ONE FILE FROM WHERE IT WAS WRITTEN.** *An
alarming count without its second query is not a finding.* The board file asked
the second question and got the reassuring answer; the rows file quoted the
alarming first number as though it were the finding. **Both were written by the
same session, the same day.** Writing a lesson down is not obeying it.

The correction carries the second query, not just the corrected number.

## #242 — OWNER-RULING — THE ORDER

**STANDING.**

1. **#1036's five repairs, in the order given** — #238, then #239, then #240,
   then #241a, then #241b.
   ⚠️ Written `#241a` and `#241b`, with NO PARENTHESES. A number followed by a
   parenthesised letter is this ledger's AMENDMENT form, and
   `gate-amendment-reachability` requires every amendment appearing in an
   archive to RESOLVE from the head. These are sub-parts of ONE ruling, not
   amendments to it. The gate caught the first draft using the wrong form —
   and then caught the SECOND draft too, because the sentence explaining the
   mistake spelled the wrong form out as an example. ⚠️ **A scanner cannot tell
   prose about a citation from a citation**, which is the same lesson the
   pre-commit hook taught this session two batches earlier with three invented
   ruling numbers in a comment.
2. **A FRESH ROUND on #1036.**
3. **ROUND SIX on #1018**, over today's fixes — which are themselves a finished
   diff.
4. **BOTH LEAVE DRAFT ON CLEAN ROUNDS ONLY.** A clean round is the condition, not
   a count of rounds served (#223). Round two on #1036 returned **25 of 27
   surviving**; round five on #1018 returned **15 of 20**. Neither number is an
   argument for stopping, and neither is an argument for continuing — **the next
   round's result is.**
