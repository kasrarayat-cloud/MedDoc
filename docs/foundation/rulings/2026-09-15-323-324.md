Recorded by the receiving session in its first commit, before building.

## #323 — OWNER-RULING (REGISTRY-3) — the colonoscopy-specific concepts are registered, each fully wired

**STANDING.** The colonoscopy operative note's specific fields become first-class
registered concepts:

- `procedure.anesthesia` (ALREADY registered — the template),
- `procedure.bowel_prep` (carries a **BBPS score**),
- `procedure.extent_of_exam`,
- `procedure.specimens` (a **LIST**),
- `procedure.estimated_blood_loss`,
- `procedure.complications`.

Each new concept is wired across ALL FIVE dimensions, the same checklist an
existing colon concept satisfies:

1. **L3 field** — the extraction fact L3 produces (`encounter-facts`, and L3's own
   schema/prompt if it must learn the field).
2. **guidance** — the mapping proposer's clinical guidance so a label maps to it
   (`semantic-mapping`), accurate enough that auto-certify does NOT decline on a
   wrong mapping (the earlier Findings→exam.vascular failure).
3. **projector** — how a resolved fact becomes the field VALUE
   (`field-value-derivation`); `specimens` projects a LIST; `bowel_prep` carries
   the BBPS score.
4. **self-test sentence** — the synthetic round-trip proof sentence so the
   auto-certify synthetic test round-trips (`verification-encounter`).
5. **partition** — the registry membership (`concept-registry`: REGISTRY_CONCEPTS,
   sub-concepts, record-derived, experiencer, synonyms as applicable).

**`"Electronically signed by"` is RECORD-DERIVED — the signing doctor.** Its label
maps to a record-derived concept filled from the visit record (the signing
doctor's name), never dictated; it does not fill synthetically in the round-trip
(the record-derived exemption, like `procedure.surgeon`). ⚠️ Own adversarial pass
(the clinical-generation path).

## #324 — OWNER-RULING (S2 affordance amendment) — a bold heading + empty multi-line gap is ONE multi-line control

**STANDING.** Amends the S2 blank-affordance rule (#320): a **bold heading followed
by an empty MULTI-LINE GAP** — CONSENT, DESCRIPTION OF PROCEDURE on the colon form,
free-prose sections with a labelled heading and blank space beneath — derives **ONE
multi-line control**. A heading with **NO gap** stays prose (unchanged). This
closes the twin-completeness gap S2-4 surfaced: those free-prose sections were
left as prose (no affordance) and so absent from the twin export; now the twin
fields them and the doctor's page fills them.

The affordance is the empty vertical gap beneath the heading (down to the next
line box / bottom margin); it materialises so the hardened S1 `deriveProseTwin`
classifies ONE `blank`/`label` control whose value flows BELOW (a block control,
matching S2-4's block placement). A heading with the next line immediately below
(no gap) is a section header with inline content, not a fill region — prose.
