# RULING #198 — A MIGRATION-CARRYING DEPLOY REQUIRES THE STRICT DECLARATION

**Owner ruling, 2026-09-05. RENUMBERED from #188 on 2026-09-06 — see below.**

## THE RULING

A migration is **irreversible**, so its declaration must be **COMMITTED BEFORE
THE ACT** — the mutation-gate standard. Code-only deploys keep the ancestor
carry-forward path: **strictness is proportional to reversibility**, so #96(b)
is applied one level finer rather than overturned.

⚠️ **SPECIMEN.** Five August declarations were committed *after* their act began,
**two of them after an irreversible migration had already FINISHED** (+4m42s,
+5m46s). The gate accepted all five correctly by its own rules — which is the
finding. Evidence recoverable, gate not.

## ⚠️ WHY THE NUMBER MOVED, AND WHY THAT IS THE INTERESTING PART

**This ruling was recorded as #188. So was T4's** — *"the five clipboard formats
survive, the safety caption stays"* — and **T4's is the one that reached `main`.**
Both lanes claimed the same number on the same day, each correctly following the
protocol of claiming at record time, because **the protocol reads a file that
neither lane could see the other editing.**

The collision is not a typo. It is what a claim-at-record-time rule does when two
sessions record concurrently against branches, and it is invisible on each branch
individually — the shape a per-branch invariant cannot catch, because the
conflict exists only in the union.

⚠️ **AND IT HAD ALREADY HAPPENED FIVE TIMES BEFORE ANYBODY NOTICED.** Measured on
`main`: **#106, #109, #115, #116 and #131 each carry two rows.** This one was
caught only because a live citation started pointing at the wrong ruling.

## WHAT THE RENUMBER HAD TO REPAIR

Three citations on `main` said `#188` and meant *this* rule — the deploy
declaration for `832f8e81`, PR #999's rows file, and ruling #192's sequence.
Each now reads `#198`. A fourth mention of `#188` in ruling #195 is left alone:
it genuinely means **T4's** ruling, and rewriting it would have been the
mirror-image error.

⚠️ **THE CITATIONS ARE THE DAMAGE, NOT THE ROW.** A duplicate row is untidy; a
citation resolving to somebody else's ruling is a reader being confidently
misinformed — and `#188` was cited in a live deploy declaration for a
production migration.
