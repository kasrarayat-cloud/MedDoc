# Ruling #319 — 2026-09-12 (REGISTRY-2, the operative-note family)

Recorded by the receiving session in its first commit, before building.

## #319 — OWNER-RULING — REGISTRY-2: the closed registry gains `procedure.*`

**STANDING.** The colon operative-note twin (#317) could not certify because the
closed concept registry had no operative-note concepts, so the model mis-mapped a
colon note onto vascular-exam / plan concepts (the F5-i hazard, caught by the
auto-certify decline). This ruling adds the operative-note family so the mapping
is correct by construction.

**New canonical concepts (each with an L3 extraction field, prompt guidance, a
projector, self-test sentences, and its SINGLE/ACCUMULATES partition; polarity is
STATED by L3, never inferred, for the lists):**

| concept | partition |
|---|---|
| `procedure.performed` | SINGLE |
| `procedure.preop_diagnosis` | SINGLE |
| `procedure.findings` | **ACCUMULATES** (a list) |
| `procedure.consent` | SINGLE |
| `procedure.description` | SINGLE |
| `procedure.recommendations` | **ACCUMULATES** (a list) |
| `procedure.anesthesia` | SINGLE — only if dictated |

**Record-derived (`visit_record` class — filled from the record at fill time,
never by the model):**
- `procedure.surgeon` = the **signing doctor's name**. ⚠️ A clinician's name is
  PERMITTED here and this does NOT violate #127: #127 forbids the MODEL asserting
  a name/laterality; this is RECORD-DERIVED (the signing doctor is a fact of the
  visit record), the same class as `visit_metadata.patient_name`.
- `visit_metadata.date_of_service` = the visit date.
- `patient_id` = the record's MRN when present; **blank with a named reason**
  otherwise (TOKEN-1 decline discipline).
- `DD` / `DT` = system timestamps (dictated/transcribed), not model output.

## THE MAPPING OF 5091c82c'S 17 FIELDS

Patient Name → `visit_metadata.patient_name`; Patient DOB → record-derived DOB
(or blank-with-reason); Patient ID → `patient_id` (MRN/blank); Date of Surgery →
`visit_metadata.date_of_service`; Surgeon → `procedure.surgeon`; Procedure →
`procedure.performed`; Preoperative Diagnosis → `procedure.preop_diagnosis`;
Consent → `procedure.consent`; Description of Procedure → `procedure.description`;
Findings 1–3 → `procedure.findings` (accumulates); Recommendations 1–3 →
`procedure.recommendations` (accumulates); DD → `DD`; DT → `DT`.
