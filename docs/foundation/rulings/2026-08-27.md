| 2026-08-27 | **#154 — THE ICD REJECTION REASON IS A CLOSED VOCABULARY OF TOKENS, NEVER FREE TEXT** — 🟡 **PROVISIONAL — loop ruling, awaiting war-room review** — built by the loop, run `20260827-041645-b1` session 02, branch `feat/f8-s2-coding-view` | **THE QUESTION.** Ruling #153's acceptance walk for F8-S2 requires *"reject one code **WITH A REASON**"*. A reason therefore had to exist, and nothing in `RULINGS.md` had ever decided its SHAPE — grepped across the head and all five archives, **0 hits for "rejection reason", with a positive control (`ICD_CODE_REJECTED`) returning 2 from the archives and 0 from the head**, so the zero is a real absence and not the head-only-grep trap. The question is ruling-shaped because it decides what a clinician-authored field may CONTAIN in a column that is read by client components and mirrored into audit metadata. **RULED (a): THE REASON IS AN ENUM — `not_supported_by_note` · `not_this_encounter` · `wrong_specificity` · `duplicate_of_another_code` · `other`.** Validated by `z.enum` at the route boundary AND re-checked in the pure layer, so free prose cannot reach the column even from a hand-written client. **RULED (b): AND THE ARGUMENT IS PHI, NOT TIDINESS.** #148(d) stores `{code, fromState, toState}` and nothing else, reasoning verbatim that `07a-icd-coding.ts:471-473` records that a free-form description *"can carry patient context"*; #149(d) forbids storing a model-authored string for the same reason. **A doctor-typed reason is the identical hazard wearing the clinician's hand instead of the model's** — *"not relevant, patient's mother had this not him"* is a sentence a real physician would type, and it would land in a JSONB column the browser reads and an audit row that outlives the visit. A token cannot carry a patient detail, it aggregates, and widening the set later is a visible edit. **RULED (c): PRESENT ON `rejected`, FORBIDDEN OTHERWISE — A BICONDITIONAL, BOTH HALVES ENFORCED.** `reason_required` is obvious; `reason_not_allowed` exists because a stored `{state:'accepted', reason:'not_supported_by_note'}` is a record that CONTRADICTS ITSELF, and a reader cannot tell a stale artefact from a decision meaning the opposite of its own state. **RULED (d): A REASON CHANGE IS A REAL CHANGE, NOT A NO-OP.** `rejected(not_supported_by_note) → rejected(wrong_specificity)` is a different clinical statement about the same code; a state-only comparison would report `changed:false`, write nothing, emit no audit row, and discard the doctor's correction while the UI reported success — the silent-no-op class this repository has already shipped once. **RULED (e): THE NARROWER ENFORCES IT ON READ, ASYMMETRICALLY, AND THE ASYMMETRY IS THE CONSIDERED PART.** A `rejected` record with a missing or unknown reason is DROPPED — which returns the code to UNDECIDED so it surfaces to the doctor again, over-shooting toward the edge that has a fence, whereas inventing a reason would assert a rationale nobody gave. An `accepted` record carrying a stray reason KEEPS THE RECORD and drops the FIELD — its state is well formed and is a real clinical decision, and deleting it would destroy a doctor's accept in order to punish an annotation beside it. **⚠️ HONEST LIMIT, STATED RATHER THAN DESIGNED AROUND:** `other` records that the reason was none of the four, and the actual reason is then NOT RECONSTRUCTABLE. That is the accepted cost of refusing a free-text field — an unrecoverable *reason* is cheaper than an unrecoverable *disclosure*. **⚠️ AND THE BACK-COMPAT QUESTION IS EMPTY BY MEASUREMENT, NOT BY ASSUMPTION:** `icdDecisions` **does not exist on production** — `information_schema.columns` returns **0** for it and **1** for `icdCodes` as a positive control — because S1's migration is held under #153(g). There are ZERO stored decisions anywhere, so tightening the narrower damages no back-catalogue. **REVERSAL PATH.** Every clause is reversible in the SAFE direction and none is a migration. (a) widening the vocabulary is appending to `ICD_REJECTION_REASONS`; (c),(d),(e) are REFUSALS and tighten only. Reverting (a)/(c) means deleting the `reason` field from `IcdDecisionRecord` AND from `ICD_DECISION_RECORD_KEYS` — a two-place edit that S1's own `_NoFieldUnwritten` compile-time assertion makes impossible to half-apply, **demonstrated here by mutation: removing the key alone fails `tsc` with `Type 'true' is not assignable to type 'never'`.** `gate-f8-s2-decision-reason.test.ts` then reddens; the mutation table is in the RELAY row. **NOTHING ELSE IS BUILT ON THIS** — the reason is written, read and rendered by F8-S2 alone, and no export, note or EHR format reads it. ⚠️ **OWNER ANNOTATION, 2026-08-27 — ✅ RATIFIED.** The PHI argument is **decisive, not tidy**: a free-text rejection reason is a sentence a physician types PHI into, landing in a JSONB column the browser reads. **Closed enum only**, and the asymmetry stands exactly as designed — a malformed rejection **DROPS** (the code returns to undecided and the doctor sees it again, failing safe *toward* re-review) while a stray reason on an accept is **stripped and the decision survives**. The provisional wording above is KEPT rather than swapped, per the standing rule that corrections are appended. | RELAY §F8-S2 · `lib/icd-decisions.ts` · `icd-codes/decision/route.ts` |
