| 2026-08-27 | **#152 — THE SIGNED DOCUMENT CARRIES THE LEVEL THE DOCTOR ATTESTED, AND THE FREEZE IS GATED ON `emApplies` ALONE** — 🟡 **PROVISIONAL — loop ruling, awaiting war-room review** — built by the loop, run `20260827-041645-b1` session 01, branch `fix/f12e-em-freeze-parity` | **THE QUESTION.** F12-e was filed as *"a shape flip leaves the signed document with no E/M while the screen showed one"*, and the filing named `cptCodes.emSuppressed` as *"exactly the hook a fix needs"*. Building it, both halves turned out to be narrower than the defect. **RULED (a): THE GATE IS `emApplies` ALONE; `emBlob &&` WAS THE DEFECT, NOT THE GUARD.** `sign/route.ts` froze `cptCodes.em.signedCode` only when L7b had emitted an `em` blob. But the level the doctor REVIEWS is not that blob — `visits/[id]/page.tsx:649` seeds `emScoredCode` from `initialEmScore.override ?? suggestedCode`, and that seed sits INSIDE `if (!emNotApplicable)`. So the rail displays a level on a visit whose `cptCodes.em` is null, `emBlob === null` skips the freeze, `projectEmForDisplay(null, …)` returns null at `visit-export.ts:107`, and **the signed PDF, DOCX and every EHR clipboard format print no E/M at all.** E/M PARITY (#315 obs#2) already rules that the artifact prints the level the doctor reviewed and attested; keeping `emBlob &&` made a standing ruling contingent on whether a model happened to return a field. **RULED (b): `emSuppressed` IS NOT THE HOOK, AND IS DELIBERATELY NOT CONSULTED.** It distinguishes *why* the blob is absent; the freeze does not care. The current verdict on the note being signed is `emApplies`, and that is the whole gate — which also means the fix does not depend on a marker written by a layer that may not have run. **RULED (c): ⚠️ NOT MERELY ARMED BY F12-c — LIVE IN PRODUCTION TODAY, AND MEASURED.** Read-only on prod, 2026-08-27: **12** visits carry `cptCodes.em = null` AND a non-null `emScoredCode`, **10 of them SIGNED**, all `bariatric-surgery` / `gastroenterology`, **zero** imaging. Positive-controlled (28 rows carry `cptCodes`, 27 an `em` key, 17 `em = null`, 32 SIGNED), so the count discriminates. **Established WITHOUT READING ONE BYTE OF NOTE TEXT**: because the `emScoredCode` seed is inside `if (!emNotApplicable)`, its presence is *structural proof* the predicate said E/M APPLIES. The filing's attribution to F12-c is corrected: F12-c widens the population, it did not create it. **RULED (d): ⚠️ THE FIX INTRODUCED A SECOND DEFECT AND ITS OWN ADVERSARIAL PASS FOUND IT — `99214 — undefined`.** Freezing on a visit with no `em` blob synthesises `{ signedCode }`, carrying no `description`; `CptEm.description` was declared REQUIRED, so `ehr-formatters.ts:231` and `docx-generator.ts:259` interpolated it blind. **That exact string has reached an EHR once already** (`projectDisplayedEmCode`'s own comment records it). Unrepaired, the fix would have traded an ABSENT field for a WRONG one, which this house ranks worse. **RULED (e): NO PROSE IS INVENTED — THE CODE ALONE IS THE HONEST ARTIFACT.** There is no non-AMA descriptor set in this repository and authoring a billing string is what #149(d) forbids, so the separator is conditional at both sites and **`CptEm.description` becomes OPTIONAL** — the load-bearing half, because it makes a future renderer fail to TYPECHECK rather than print `undefined`. It immediately surfaced a third consumer (`codes-tab.tsx:148`) that a grep-led sweep would have had to find by hand. **REVERSAL PATH.** (a)/(b): restore `emBlob &&` at `sign/route.ts` — one conjunct; the gate `gate-f12e-em-freeze-parity.test.ts` then reddens 4 of 11 and names why. (d)/(e): restore the two unconditional interpolations and re-require `description`; `gate-f12e-frozen-level-prints-no-undefined.test.ts` reddens 5 of 8 across four EHR formats and a real rendered DOCX. **NOTHING IS BUILT ON THIS.** ⚠️ **AND WHAT IT DOES NOT DO: it is FORWARD-ONLY.** The 10 already-signed rows keep their absent E/M; changing a signed clinical record is owner-class and is NOT attempted here.
