# RULING #193 — KEEP IS NEVER MODEL-AUTHORED AND NEVER AUTO-CONFIRMED

**Owner ruling, 2026-09-05. Amends #192.** Recorded at claim time, before the
code that implements it.

## WHY IT EXISTS

#192 said `unmentionedPolicy` is an explicit per-field declaration, **never
inferred from content**. That was aimed at the RENDERER. The adversarial pass
demonstrated the same inference arriving through a channel the ruling never
considered:

> **`ModelSemanticMappingSchema` EXTENDS `SemanticMappingSchema`, and the tool's
> `input_schema` is generated from it.** Adding the field silently handed the
> MODEL a settable enum deciding whether a template's own sentence prints on a
> signed note — with no mention in the system prompt.

Measured end to end, **no human anywhere and validation GREEN**: 11 of 11
proposals returned `keep`, and a control whose content is the literal string
`Enter assessment` rendered that string into the note. `planAutoConfirm` spreads
the whole mapping into `status: 'certified'`, so the **default** path would have
certified a model-authored render policy.

⚠️ **THE MODEL INFERS FROM CONTENT TOO.** "Never inferred from content" is a
constraint on every producer, not on the renderer alone.

## THE RULING

**1 · THE OFFER COMES ONLY FROM COMPILED SCAFFOLD METADATA.** Deterministic: a
control with non-empty default content. Shown with **its sentence** as the
reason, so a doctor confirming `keep` sees exactly what will print.

**2 · THE MODEL SCHEMA OMITS THE FIELD ENTIRELY.** Stronger than forcing it to
null beside `practiceDefault`: the field never appears in the tool schema, so
there is no value to choose and nothing to re-assert after parsing.

**3 · AUTO-CONFIRM NEVER CONFIRMS A KEEP.** A policy that prints template prose
on a signed note requires a **HUMAN** confirmation. The doctor's single
confirm-list covers it — one click for all offers — so the cost is a click, not
a workflow.

**4 · ARM IT:**
- a planted MODEL proposal carrying `keep` is **rejected**;
- a `keep` reaching `certified` without a human confirmation **reds**.

## ⚠️ WHAT THIS RULING DOES NOT DO

It does not make scaffoldedness a render input. `scaffolded` / `scaffoldText`
remain compiled metadata outside `structureSha256`, informing the **offer** and
nothing else. The render still consults only the confirmed declaration, and an
unconfirmed or rejected offer leaves the column NULL — the bounded clear, which
is fail-closed.
