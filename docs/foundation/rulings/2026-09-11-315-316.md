# #315 TOKEN-1 and #316 PANEL-1 — from the owner's first real visit

**Owner rulings, 2026-09-11.** On the owner's first real visit, an HPI-intro
control printed its scaffold `{patient} is a pleasant {age}-year-old presenting
for …` with the braces UNRESOLVED. The owner issued two rulings and a
prerequisite forensic.

## The forensic prerequisite (filed as `board/WHY-1-SCAFFOLD-BRACES-PRINTED.md`)

The braces printed because the "Your blanks" panel's *Insert my default* action
wrote the control's scaffold text — braces and all — as a `scaffold_default`
override, and the renderer emitted that stored value verbatim
(`clinician-override.ts` scaffold_default arm → resolution value →
`renderer.ts` `displayValue` narrative_text, no token handling). It was NOT an
unfilled render: an unfilled scaffolded content control is CLEARED by the
renderer (ruling #194 deleted the keep/default_kept branch). The two rulings
meet here: TOKEN-1 makes the inserted value safe; PANEL-1 stops the unsafe offer.

## #315 — TOKEN-1

Scaffold text carrying a CLOSED, REGISTERED token set (`{patient}`, `{age}`
today) is substituted **deterministically from the visit record at fill time,
never by the model**. An unresolvable token **renders the field blank with a
named reason**. The manifest records each substitution. The certification
self-test covers it. A **gate arms on the export bytes** that no brace
placeholder reaches a rendered document.

**Design, as built:**
- The closed set and the string-shape predicates live in a pure zero-import leaf
  `src/lib/template-twin/scaffold-text.ts`; the resolvers (which need the age
  arithmetic) in `token-substitution.ts`.
- Substitution happens in the `scaffold_default` arm of `applyClinicianOverrides`
  — a pure string operation on `insertedText`, at fill time, so the substituted
  value flows through the renderer and the round-trip verifier unchanged and the
  manifest records what actually printed.
- It keeps the minted fact's `sourceType: 'clinician_correction'` and reads
  name + `ageAtDateResolved` from the record directly — it mints **no
  `visit_record` fact**, so ruling #247's `assertNoRecordDerivedFacts` holds on
  the certification path.
- ⚠️ **Reading of "renders blank with a named reason": FIELD-level.** If any
  registered token in a scaffold is unresolvable, the whole scaffold-default
  insert **declines** (the field stays blank), rather than emitting a
  half-substituted sentence like "… is a pleasant -year-old …". A malformed
  clinical sentence in a medical record is worse than a blank the doctor fills.
  This is a judgment on ambiguous wording; **the owner may reverse it** to
  token-level (empty substring) if preferred.
- The gate (`residual-token-scan.ts` → `residualPlaceholdersInDocx`) scans the
  rendered bytes across document + headers + footers, throws `RESIDUAL_TOKEN` in
  the cert self-test, and is positive-controlled in `gate-token1-substitution`.

## #316 — PANEL-1 (REVIEW-DEFAULTS)

The "Your blanks" panel: (a) never offers a control whose scaffold is FURNITURE
(underscores/dashes/whitespace only); (b) merges identical scaffold texts into
one row with a count; (c) renders collapsed by default as a single line
"N blanks — review" with "Insert all my defaults" as the primary action; (d)
drops controls TOKEN-1 fills (token-only scaffolds). The per-visit, per-field
click stays — an undictated exam is never printed automatically, one audit row
per field.

**Design, as built:**
- (a) furniture is an early-return in `scaffoldDefaultOfferable` — the one
  predicate the panel offer AND the write door share, so offer and write cannot
  disagree. It reads `field.scaffoldText` off the passed object so the omit-door
  read-tracer follows it.
- (d) "drops controls TOKEN-1 fills" is served by the EXISTING blank-filter, not
  a scaffold-shape drop: a control TOKEN-1 fills WITHOUT the doctor is a
  record-derived (visit_metadata) concept, which fills from the record and is
  never blank, so it is already out of the offer. ⚠️ The adversarial pass showed
  that dropping a token-BEARING *dictation* scaffold by shape
  (`isTokenOnlyScaffold`) would leave a fillable control permanently blank
  ("never withhold"), so it is KEPT — it inserts safely now, TOKEN-1 substitutes
  on insert, and the door's residual gate refuses anything that would still
  print braces. `isTokenOnlyScaffold` remains as a documented predicate but is
  not used to withdraw an offer.
- (b) grouping by identical `scaffoldText` and (c) collapsed default live in the
  builder (`preview-visit-document.ts`) and the client (`your-blanks-panel.tsx`);
  the cache `KEY_VERSION` bumped v8→v9 for the shape change.
- The furniture and token-only predicates are the SAME leaf functions TOKEN-1
  uses (`scaffold-text.ts`), so the panel and the gate cannot drift.
- A per-group insert loops the per-field action once per fieldId — the per-field
  audit row (ruling #194 doctrine) is preserved; nothing auto-inserts.
