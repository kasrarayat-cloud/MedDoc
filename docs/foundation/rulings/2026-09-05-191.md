# Ruling #191 — THE SCAFFOLDED-FIELD POLICY

| 2026-09-05 | **#191 — THE SCAFFOLDED-FIELD POLICY: `unmentionedPolicy` on a control that ships with default content** — ✅ OWNER RULING — **STANDING.** A scaffolded control (non-empty default at compile) carries `unmentionedPolicy: 'keep' \| 'omit'`, default `keep`. KEEP → no matching fact ⇒ `default_kept`, citing the facts evaluated. OMIT → no matching fact ⇒ the resolver yields a null the renderer patches via the proven **structure-keep clear**, reason `omitted_unsupported_default`. A matching fact fills it either way. ⚠️ **NOT `practiceDefault: ''`** — that is a VALUE pretending to be a POLICY. ⚠️ Distinguished from #163 by MECHANISM: that failure was the renderer WALKING the document and deleting carriers for a field it could not fill; this is a DECLARED per-field policy consumed by the resolver, rendered by the same bounded operation as any emptied field — no walk, no carrier enumeration. |

## Why this is not #163 wearing a new hat

⚠️ **THE DISTINCTION IS THE WHOLE RULING, SO IT IS STATED FIRST AND PLAINLY.**

[Canon 77](../../canon/77-clearing-by-deletion-is-a-four-times-falsified-instrument.md),
recorded by owner ruling #163, closed *"when a field is unfilled, the renderer
clears its content"* after **four falsifications** — and layer 2 of those
**erased a patient's allergy line**. Nothing here reopens that.

| | #163's failed instrument | #191 |
|---|---|---|
| what decides | the RENDERER, at fill time, for any field it could not fill | a DECLARED per-field policy, set at mapping time and reviewed |
| how it clears | **walks** the document enumerating carriers to delete | the **structure-keep clear** — replace one `w:sdtContent` subtree |
| what bounds it | a list of carrier element types, which never closed | the document's own element, which cannot be incomplete |
| blast radius | anything the walk reached, including unrelated clinical text | exactly the control named |
| scope | every unfilled field | only controls a human marked `omit` |

The clearing operation is **the one already proven**: the same bounded
`w:sdtContent` replacement every emptied field uses, earning the
source-byte-identity proof. What is new is *who decides* and *for which
control* — and both are declared, not inferred.

## The mechanism

**A SCAFFOLDED control is one whose compiled default content is non-empty** —
the consent sentence, an exam value, a ROS sentence. An empty underscore run is
not scaffolded; there is nothing to keep or omit.

    unmentionedPolicy: 'keep' | 'omit'      // default 'keep'

- **`keep`** — no matching fact ⇒ resolution `default_kept`, citing the facts
  that WERE evaluated. This is the #179 path and it is the default, so no
  existing template changes behaviour.
- **`omit`** — no matching fact ⇒ the resolver yields a null, and the renderer
  patches it through the structure-keep clear with reason
  `omitted_unsupported_default`.
- **A matching fact fills the control either way.** The policy governs only the
  unmentioned case.

⚠️ **`practiceDefault: ''` IS REFUSED AS THE MECHANISM.** It is representable —
`z.string().max(500).nullable()`, no minimum — and it would work. It is still
wrong: a value pretending to be a policy. Nothing in the record would say WHY
that field is empty, the reason token would be a practice default rather than
an omission, and the next reader would find an empty string with no argument
attached to it.
