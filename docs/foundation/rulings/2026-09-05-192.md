# RULING #192 — KEEP IS AN EXPLICIT PER-FIELD DECLARATION, NEVER INFERRED FROM CONTENT

**Owner ruling, 2026-09-05. Amends #191's keep half.** Recorded before any code
was written for it.

## WHY IT EXISTS

#191 made `keep` the DEFAULT for a "scaffolded" control, where scaffoldedness
was to be derived from the control's own content. Three formulations of that
derivation were falsified:

| formulation | how it died |
|---|---|
| a text heuristic on Word's `"Choose an item."` | blocked **28 of 28** dropdowns of the only real customer template; the English-only repair blocked all 28 again in fr/de/es (canon 83) |
| `w:showingPlcHdr`, the signal the DOCUMENT declares | present **28/28** on that template and **0/53** on the regenerated form, which read as conclusive — it is a **POPULATION FACT, NOT A PROPERTY OF THE FORMAT** |
| the same, generalised | this repository's own synthetic template carries `Enter assessment` **and** `Choose an item.` with **no such flag**. Activating keep printed **"Enter assessment"** onto a rendered note — an instruction to the user, on a document a doctor signs |

That is the clearing-rule family's fourth falsification, and the standing answer
is to escalate rather than build layer four.

## THE RULING

**1 · `unmentionedPolicy` HAS NO CONTENT-DERIVED DEFAULT.**

| value | behaviour |
|---|---|
| **absent** | today's behaviour — the bounded clear on a null. **Fail-closed: a prompt can never print.** |
| **`keep`** | `default_kept`, and the renderer's early return (no patches) — the one line that demonstrably worked |
| **`omit`** | the bounded clear with its reason token |

The counterexample arm stays **inverted**: a control WITHOUT a declared keep
never keeps.

**2 · THE MAPPING PROPOSER MAY PROPOSE KEEP.** For a control whose default
content reads as a clinical sentence, at CONFIRMATION time, with the sentence
shown as its reason, confirmed by the doctor or by auto-confirm under the
existing confidence rule. **Scaffoldedness stays compiled metadata** — outside
`structureSha256` — and only informs the PROPOSAL, never the render. Same
pattern as `conceptScope`: proposed, confirmed, never decided at render.

**3 · THE OWNER'S FORM** declares keep on the sixteen ROS/exam controls and omit
on telehealth **explicitly**. The heuristic was never needed for his form.

**4 · SEQUENCE**, no check-ins: finish #999 on this rule → the
migration-carrying deploy (strict declaration, #198) → transfer/certify the
53-control form → rows 2/1/8/9/7 → row 6 → re-certify → fresh export → the
eleven-row diff → 🟢. R4 later inherits it: prose conversion creates scaffold
controls and PROPOSES keep with the sentence as reason.

## ⚠️ AND THIS RULING FALSIFIES ONE THING RATIFIED ALONGSIDE IT

The same message ratified *"the carried column with keep canonicalized as absent
(no certified sha moves)"*. That canonicalisation was correct under #191, where
`keep` and absent were **semantically identical** — both readers tested only for
`'omit'`, so nothing could tell them apart.

**Rule 1 makes them opposites.** Absent clears; `keep` keeps. Hashing them the
same would mean a doctor's declared `keep` could be removed from a certified
mapping **without moving the attestation sha** — the certificate would attest to
behaviour it never saw.

**The stated goal survives by a better mechanism.** The column becomes
**nullable with no default**, so every pre-existing row is NULL rather than
`'keep'`; NULL contributes nothing to the hash, so **no certified sha moves**,
and both explicit values do move it — which is correct, because both are
declarations that change what the document says.

The migration was **not yet applied in any environment** when this was found, so
the column shape was corrected rather than patched.

## THE HEAD'S ROW, CARRIED HERE VERBATIM

⚠️ **A row and its body must each be reachable from the other, and
`gate-ledger-reachability` asserts BOTH DIRECTIONS.** It caught this body
landing without its row: 146 head rows against 145 archived ones. A census
proves content; only this proves a reader can still get from one to the other.
