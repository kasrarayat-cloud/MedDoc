## #187 — A MIGRATION-CARRYING DEPLOY REQUIRES THE STRICT DECLARATION

**Answers the question the August retrospective raised, and answers it by
splitting the gate rather than tightening it everywhere.**

> **If the deploy's range contains a migration: `strict` — the declaration must
> be TRACKED, UNMODIFIED and COMMITTED before the act.**
> **If it does not: `present`, with the ancestor carry-forward path unchanged.**

**The reasoning is #96(b)'s own, applied one level finer.** Strictness is
proportional to reversibility. A code-only deploy is answerable by an image
rollback, so requiring a prior commit there would refuse every deploy whose
author lands the declaration in the same PR — a real habit, and halting the
programme to fix the weaker case. **A migration is not answerable by a
rollback.** It is the same irreversibility that already made
`run-ruled-mutation.sh` strict, so it takes the same standard.

### The specimen, and it is why this is a rule and not a preference

| | migration finished | declaration committed | gap |
|---|---|---|---|
| `079b9205` | 2026-08-09 00:01:00 | 00:05:42 | **+4m42s** |
| `50b02832` | 2026-08-11 09:06:35 | 09:12:21 | **+5m46s** |

In both, the irreversible act had **already completed** when the declaration
landed — so the record cannot distinguish an honest declaration from one
composed once the outcome was known, which is the entire product §2.5 buys.
Three further August declarations were committed after their deploy STARTED but
before the numbers existed: late, not tainted, and recorded as the lesser thing.

⚠️ **The gate accepted all five, correctly, by its own rules.** That is the
finding. Nobody bypassed anything.

## #188 — THE CONFIGURED MODEL ID IS VALIDATED AT STARTUP

**The fail-closed refusal is kept. Its TIMING moves.**

`shouldOmitTemperature()` refuses any model matching neither the stripped nor
the accepted family list, at three request-building sites. That refusal is
right: a wrong guess is a 400 on the clinical path or an undeclared change to
sampling.

**What is wrong is where it lands.** `TRANSCRIBE_MD_CLINICAL_MODEL` is read by
production code, and **every** clinical layer passes a temperature — L2 `0`,
L4 `0.2`, L6 `0.1`, L7a `0`, L7b `0`, L7e `0.3`, 04b `0`, 06b `0`. So a
one-character typo does not fail fast; it throws uncaught on the first clinical
request, **inside the pipeline, wearing the costume of a generation failure.**

> **A CONFIGURATION ERROR MUST NOT MASQUERADE AS A CLINICAL ONE.** The two are
> diagnosed by different people, in different places, at different hours.

**Small, armed, its own PR.**

## #189 — THE FAN-OUT ADVERSARIAL PASS OVER #179 IS OWED

**The sequential self-run pass is recorded as insufficient by the session that
ran it, and the owner has ratified that reading.**

`AGENTS.md`'s argument for the pass is that it **does not share the author's
context**. The pass over #179's finished diff was run by the author of the arms
it examined, sequentially, because the resource pre-flight ruled out a fan-out.
It found something real — #188 — and it is still not the pass the rule
describes.

> **BLOCKING: PR #985 stays DRAFT, and the regenerated form's certification does
> not merge, until a fan-out pass with DISTINCT LENSES in ISOLATED WORKTREES has
> run.**

**Its stated precondition is headroom**, not urgency: after the housekeeping PRs
land, with tab 4 paused and the deploy done. Worktrees are created through
`setup-worktree.sh`, so each lens resolves `@meddoc/*` locally — a lens on a
tree that resolves to somebody else's packages reports `NOTHING FOUND`, which is
the most reassuring sentence available and would be about code that is not there.
