## #317 — OWNER-RULING — SLICE-0 COLON OPERATIVE-NOTE TWIN

**STANDING.** The owner's colon operative-note form is made to work end-to-end as
a native DOCX Template Twin, certified through the real path, exactly as the GI
(WM IOV) form was.

**Controls (one content control each), reproducing the form's layout faithfully:**
- **Labels (5):** Patient Name, Patient DOB, Patient ID, Date of Surgery, Surgeon.
- **Section bodies (6):** Procedure, Preoperative Diagnosis, Consent, Description
  of Procedure, DD (dictated), DT (transcribed). *(The source prints `DD:`/`DT:`
  as two distinct lines; kept as two controls, faithful to the form.)*
- **Numbered slots (6):** Findings 1–3, Recommendations 1–3. *(These are the
  `POSTOPERATIVE FINDINGS` and `RECOMMENDATIONS` sections, split into three
  numbered slots each. The compiler's `fieldId` is salted by structural
  position, not label, so three slots sharing a label compile to three distinct
  fields — `compiler.ts` `stableId`.)*

**⚠️ SOURCE SUBSTITUTION, RECORDED.** The owner named `colon_questions_only.pdf`.
That file was **not present on the box** — it was not retained by the upload path
(see the measurement note `board/PDF-UPLOAD-NOT-RETAINED-20260912.md`). The owner
confirmed building from the committed blank form `colon_blank_answers.pdf`, whose
extracted structure is **identical** to the enumerated field set above
(OPERATIVE NOTE · PATIENT NAME/DOB/ID#/DATE OF SURGERY/SURGEON · PROCEDURE ·
PREOPERATIVE DIAGNOSIS · POSTOPERATIVE FINDINGS · CONSENT · DESCRIPTION OF
PROCEDURE · RECOMMENDATIONS · DD:/DT:). The twin is built to the structure above;
`colon_blank_answers.pdf` is the faithful reference.

**Proof burden:** the artifact is produced ONCE and pinned by sha (`fieldId` is
salted with the whole-package sha256 and JSZip is not a reproducible-archive
writer — regenerating mints a new identity that no longer matches its own
certificate, per the 53-control provenance). **Five additive proofs** accompany
it (build-time, deterministic, no AI/DB), each catching one way the build stops
being faithful/additive; the script exits non-zero and writes nothing on any
failure, every edit occurrence-asserted. ⚠️ *"Five additive proofs" is the
established pattern from `regenerate-consult-form.ts` / the 53-control provenance
doc; it is not owner-quoted enumeration.* Certification is through the real path
(`createTemplateTwinDraft` → confirm mappings → synthetic round-trip test →
`certifyAndActivateTemplateTwin`), never a shortcut.

## #318 — OWNER-RULING — TEMPLATE-CHOICE-1 (a practice chooses among its certified templates)

**STANDING, AND IT RE-OPENS A RULING.** The owner directs: **a practice may hold
several CERTIFIED templates; the visit shows a picker (default = the practice's
default template); the chosen template is recorded on the visit; the fill uses
the chosen twin.**

⚠️ **THIS RE-OPENS the 2026-09-04 RULED doctor-scoped `note_templates` decision**
(`rulings/2026-09-04.md`: *"colleagues cannot share a note format … changing it
means re-opening a ruling"*; `gate-practice-scope.test.ts` GATE 0.3 / SPEC §4.3).
The owner is entitled to make this product call and has: for **CERTIFIED**
templates, choice is **practice-scoped**, not doctor-scoped. Scope of the
re-open, stated precisely so it is not read wider than it is:

1. **Already practice-scoped, unchanged:** the worker's honor of
   `visit.noteTemplateId` (`worker.ts` re-validates `practiceId=visit.practiceId`
   OR system-default, per #302) and the fill's twin resolution
   (`fill-engine`/`native-export` require CERTIFIED + `sourceArtifact.practiceId
   == tenant`). The visit column (`TranscribeVisit.noteTemplateId`) already
   exists and already carries the choice.
2. **Widened doctor → practice (this ruling):** the request-context **picker**
   list (`/visits/new`) now lists the practice's **CERTIFIED** templates
   (`practiceId`-scoped + certification filter), and the **persist guard**
   (`resolveRequestedTemplate` in `visits.ts`) validates a pick by `practiceId`,
   not `doctorId`, so a co-tenant's certified template no longer silently
   degrades to auto.
3. **Still doctor-scoped:** authorship and the per-doctor "my active note format"
   resolution (`resolveActiveTemplate`) remain as the fallback. This ruling makes
   certified templates **choosable**, not co-authored.

**The practice default** is net-new: a nullable `Practice.defaultNoteTemplateId`.
The picker defaults to it when set; when unset it falls back to today's
per-doctor resolution. It is set by a practice **OWNER** (role-gated on the
sign-route pattern: DB read → fail-closed on NULL → refuse by name → audit),
because *who administers a practice-wide default* is an OWNER capability. Deeper
integration into the admin console (a members/settings surface beyond the
minimal owner setter) is the **admin lane's** (relates to ADMIN-1); filed there,
not built past the minimal setter here.

`gate-practice-scope` is updated in the same change to reflect the re-open (the
certified-template picker read is practice-scoped; the doctor-scoped WRITE and
the unscoped-read ratchet at 0 stand), with the reason recorded at the change.
