# Ruling #320 — 2026-09-14 (S2 PDF blank-affordance amended; preview never empty)

Recorded by the receiving session in its first commit, before building.

## #320 — OWNER-RULING — a PDF blank affordance is EITHER a colon/number label with an empty writable span, OR a drawn rule line; and the preview never renders an empty page

**STANDING.** The owner uploaded `Colonoscopy_Operative_Template.pdf` (a
single-page operative note: header labels, section labels, numbered slots). The
Note-format page showed "7 sections · your own PDF page" with a **blank white
preview**.

### What was MEASURED first (the owner's explicit instruction)

- **Path.** The upload took the "Bring a note" PDF path → a `note_template`
  (draft, `.pdf` source, content-addressed). S2's `pdfToProseDocx` extracted the
  text layer fine (21 lines), but `deriveProseTwin` returned **0 controls** →
  `NO_FILLABLE_FIELDS` quarantine → **no twin** → the upload fell to the flat
  "your own PDF page" candidate.
- **Why 0 controls.** Every extracted line is a **bare `LABEL:`** (colon, no
  underscore run) or a bare numbered marker (`1.` `2.` `3.`). S1's affordance rule
  deliberately treats a bare `LABEL:` as a heading/lead-in (its own hard-won
  anti-over-detection guard), so nothing derived.
- **Why the premise needed correcting.** The form draws **NO visible rule
  lines**: of 48 horizontal vector segments, **46 are white** (`#ffffff` field-box
  backgrounds, invisible on white paper) and only 2 are black (the page frame).
  The blanks are conveyed by the **colon label + empty writable space**, not by a
  drawn line. The header is **single-column** (all labels at x≈29), not
  two-column. So a "detect black vector rule lines" rule would still derive ~0 on
  this exact file — the owner confirmed the corrected rule (below) after
  measurement.
- **Blank preview.** The flat-PDF confirm sample (`previewPdfTemplateFill` →
  render) matched **0 anchors** and the client render came out blank white, while
  the server returns a valid, non-blank PDF (raw pdfjs renders the labels). Once
  the form derives controls it becomes a twin and the preview is the twin's
  filled sample; the never-empty guarantee (below) covers the residual
  0-control / render-fail case.

### The ruling

**(1) A blank affordance in a PDF is EITHER:**
  - **(a)** a **colon-terminated label** (`PATIENT NAME:`) OR a **numbered/bulleted
    slot** (`1.` `2.` `3.`, the S1 marker set) that is **followed by an empty
    writable span** — the rest of its own row is empty to the right text margin,
    OR the line(s) immediately below it before the next label are blank; **OR**
  - **(b)** a **horizontal rule line** (a drawn vector segment OR a text underscore
    run) following a label on the same row or the next line.

  "Never invent a blank" is amended to **"never invent one without an
  affordance"** — the measured empty span (or the drawn line) IS the affordance.
  **Two-column rows yield two controls in reading order** (left, then right).

**(2) The preview never renders an empty page.** If a form yields no controls, or
  a render fails, the surface shows **the reason and the derived control count** —
  never a silent blank.

**(3) Re-derive the owner's upload** under the amended rule and report the control
  count against the form's visible blanks (owner counts ~22).

### How it is built (faithful, minimal, reuses the hardened S1)

The PDF→prose step (`pdf-to-prose-docx.ts`) becomes **geometry-aware**: it groups
the text layer into line-boxes (keeping each line's bounding box), detects the
affordance per (1), and **materialises it as an underscore run** appended to the
line — so S1's existing, 14-defect-hardened `deriveProseTwin` derives exactly one
control per affordance, self-verified by the keystone re-compile. Underscore-text
lines already flow through S1 unchanged. Drawn vector rule lines are extracted
best-effort (fail-safe to none) from the operator list. This is the same
"materialise the affordance, let S1 derive" bridge S2 already uses — no change to
S1, the compiler, the mapping proposer, or certification.

Precision is layered: the geometry layer decides WHERE a blank span exists; S1's
own label-shape guards (≤48 chars, label charset) reject a sentence-shaped
"label" even with underscores appended; the keystone rejects any malformed twin;
and the confirmation step is the human backstop (the arc thesis — "confirm what
the machine cannot decide"). A generously-derived spare field is pruned at
confirm; an under-derived blank costs the doctor a manual add — so the rule errs
generous, within the owner's ~22 count.

Target reference: ruling **#317** hand-built this same colon operative-note twin
(17 controls: 5 header labels + section bodies + 6 numbered slots). This ruling
makes the **automatic** upload path derive the equivalent, so the doctor need not
have a twin hand-authored.
