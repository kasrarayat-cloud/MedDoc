## #246 — OWNER-RULING — TEXT SCANNERS ARE RETIRED AS PROOFS OF BEHAVIOUR

**STANDING.**

> **Where a round showed a source-reading arm defeated, it is replaced by a
> RUNTIME instrument. Text reads remain only for prose and docs.**

The record that forces this is three defeats of the same class, on the same
files, in consecutive rounds:

| what was read | how it was defeated |
|---|---|
| the advisory lock, by `indexOf('pg_advisory_xact_lock')` | a `--` comment; then, after the fix, a **NESTED** block comment — SQL block comments nest and a non-greedy stripper stops at the first `*/` |
| the mirror's read set, by regex over two hardcoded source regions | a guard **refactored into a helper** — the module's own idiom — silently dropping two watched inputs, 48/48 green |
| a predicate's presence, by grepping the function body | a comment naming it |

⚠️ **EACH FIX CLOSED A SPELLING AND LEFT THE CLASS OPEN, AND THE SECOND FIX WAS
WRITTEN BY SOMEBODY WHO HAD JUST READ THE FIRST.** That is the argument: the
defect is not any particular regex, it is **asking a question about TEXT when the
claim is about BEHAVIOUR.**

**THE THREE REPLACEMENTS, NAMED:**

1. **The lock is asserted via `pg_locks` under the running function** — take the
   write, then read `pg_locks` for the advisory entry with the expected
   `classid`/`objid`. A commented-out lock holds no lock; no spelling survives
   this, because nothing textual is consulted.
2. **The mirror's read set is recorded by a PROXY TRACER** that logs property
   accesses during execution. No regex; it **follows helpers by construction**,
   including imported ones, because it observes the read rather than the source.
3. **The matrix is sampled with a FIXED SEED under an EXPLICIT TIMEOUT.** The
   #234 widening took it to 82,944 rows with no timeout at 40–60% of vitest's 5s
   default, and it was **observed to time out** — a arm that flakes is an arm
   whose green nobody can rely on. A seeded sample is reproducible, bounded, and
   states its own coverage.

## #247 — OWNER-RULING — THE WITNESS IS AUTONOMOUS

**STANDING. The sampler is retired.**

Two witnesses have now failed on the same cell, in opposite directions:

- the **in-transaction** witness could never say YES, because the guard's refusal
  rolled its own evidence back (canon 129);
- the **`pg_stat_activity` sampler** that replaced it can never say NO, because
  it counts the `pg_sleep` synchronisation wait as overlap — **4091 of 4209
  instants were both racers asleep; 16 had both inside the conflicting
  statement.** A sampler killed 1.4s before either racer executed still reported
  *"12/12 runs genuinely overlapped"* and PASSED.

> **THE WITNESS MUST BE AUTONOMOUS: each racer records its own phase markers over
> a channel THE REFUSAL CANNOT ROLL BACK** — a second connection per racer, or
> `dblink` — **stamped at statement ENTRY and EXIT, not during the sleep.** The
> harness then asserts, from COMMITTED markers, that both racers were inside
> their conflicting **STATEMENT** simultaneously.

⚠️ **AND THE CONTROL IS SPECIFIED WITH IT, BECAUSE BOTH FAILURES WERE INVISIBLE
UNTIL SOMEBODY KILLED THE INSTRUMENT:**

> **A control that kills the witness must turn the cell into CANNOT-TELL, never
> into a pass.**

## #248 — OWNER-RULING — THE CODE FIXES, ALL SEVEN, IN ONE REPAIR

**STANDING.**

1. **#238 in BOTH places.** `members_left := members_left + 1` must not count
   `NEW` into the practice it just LEFT. Today, emptying a practice by MOVING its
   solo owner is refused with a message stating a false fact, while emptying it
   by DELETE is allowed — the same asymmetry #238 was written to remove,
   surviving in the sibling function.
2. **`FOR UPDATE` on every LIVE MEMBER row, not only owners.** The lock is taken
   and then `members_left` is counted over rows nothing locked.
3. **`underVisitLock` carries `deletedAt`.** It re-asserts `status` and drops the
   predicate its own resolver applied, so all three doors write onto a
   soft-deleted visit.
4. **The harness reaps its fixture on EVERY exit path** — including the exit-2
   path, which is a **CI PASS** that then seeds and runs the whole E2E suite.
5. **#241 applied everywhere the "six" appears** — the migration, the runtime
   lib, and the board filing, not only the rows file. ⚠️ **A correction applied
   to one of four readers is the same defect as the one it corrects.**
6. **The remaining process rows closed as §2.5 OBLIGATIONS** — C3's VERIFY, N3's
   baseline, the rollback, C4's procedure. They were never claimed fixed; they
   are owed.
7. All of it **in ONE repair**, so the next round judges one finished diff rather
   than a sequence of partial ones.

## #249 — OWNER-RULING — ONE ROUND EACH, AND THE EXIT CONDITION MOVES

**STANDING. This AMENDS #223.**

#223 said *a clean round is the condition.* Six rounds on one branch and three on
the other have converged: the surviving findings are now overwhelmingly about
**instruments**, not about what ships.

> **If a round finds only INSTRUMENT defects and no CODE defects, the PR LEAVES
> DRAFT with those instruments repaired.**
>
> **The code is the deliverable. The proof must be honest, not infinite.**

⚠️ **THIS IS NOT A LOOSENING OF THE PROOF BURDEN AND MUST NOT BE READ AS ONE.**
The instruments are still repaired — the ruling says *"with those instruments
repaired"*, not *"despite them"*. What changes is that an instrument defect no
longer holds working code hostage indefinitely, which is the failure mode a
sixth round starts to become.

⚠️ **AND THE DISTINCTION IS LOAD-BEARING, SO IT IS JUDGED HONESTLY OR NOT AT
ALL.** A finding is a CODE defect if it changes what the product does to a
doctor, a document or a row. It is an INSTRUMENT defect if it changes only what
the proof can SEE. **"No arm can detect X" is an instrument defect; "X is wrong"
is a code defect** — and a finding that says both is a code defect.

## #250 — OWNER-RULING — ONE SANDBOX PER AGENT, VERIFIERS INCLUDED

**STANDING.**

The refutation rounds assigned a write-refusing sandbox to each **LENS** and none
to the **VERIFIERS**, so every verifier for a lens shared that lens's directory —
with the lens and with each other.

**MEASURED:** a verifier found markers it had not written (`MUT_VERIFIER_SIXTH`,
a `clinicallyMaterial` clause) and watched a foreign dirty set move across five
files over ~20 minutes. It **read the contamination as contamination**, discarded
its first build, rebuilt every input from the pristine `git show <head>:` blob,
and ran in a private copy — which is why its verdict stands.

⚠️ **NOTHING ESCAPED, AND THAT IS LUCK RATHER THAN DESIGN.** All eleven sandboxes
came back pristine apart from their own `.lens-env.sh`, no markers survived, and
both branches were byte-identical on `origin` afterwards. **The sandbox stopped
the writes from leaving; it never promised to stop siblings colliding inside it.**

> **ONE SANDBOX PER AGENT. VERIFIERS INCLUDED.**
