## ⚠️ LATENCY — PRE-STATED PER FIX, WHICH IS WHAT REMOVES THE EXCUSE

**No fix in this range mutates stored data. Not one.** Every change is on a
path that runs when a doctor next acts.

| fix | takes effect | retroactive effect on stored notes |
|---|---|---|
| caption validation (`table-caption.ts`, `note-table-edit.ts`) | the next **note edit** | **NONE** |
| the second caption reader (`claim-prose.ts`) | the next **render** | **NONE** |
| twin-supplied ordinal (`intent.ts`, `prompt.ts`) | the next **chat-edit turn** | **NONE** |
| the ordinal's caller wiring (`chat-edit-visit.ts`) | the next **chat-edit turn** | **NONE** |

> **THEREFORE: not one stored note may differ at deploy time, and no clinical
> count may move. If any does, that is THE FINDING — there is no fix in this
> range with a story that explains it.**

This is the whole product of pre-stating latency: a code-only deploy of
edit-path fixes has no legitimate mechanism for changing a record, so the
usual after-the-fact excuse ("the change touched that path") is unavailable.
