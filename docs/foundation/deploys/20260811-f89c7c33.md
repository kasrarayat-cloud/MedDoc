## WHAT WOULD MAKE THIS CHECK FAIL

Said plainly, so the check can actually fail:

- **A font count that is not 8**, or any of the six expected byte sizes missing
  from `.next/static/media/`. In particular: **still 32** means the layout change
  did not reach the build; a number between 8 and 32 means one of the six
  families is still resolving through `next/font/google`.
- **Any of the six sizes present but altered** — that would mean something
  re-processed a file the declaration says is copied verbatim.
- **`api_usage_events` > 1325.** Even by one. A row appearing during a
  code-only deploy falsifies the inertness argument for the metering merges, and
  it is a finding whatever explanation is available afterwards.
- **Any clinical count moving at all.**
- **`marketing` or `gotenberg` image ids moving** — the script does not name
  marketing, and gotenberg's context is untouched.
- **`app /api/health` not 200**, or any co-tenant leaving its baseline code.
- **Migrations not 96 of 96** after step 4's assertion.

## WHAT THIS DEPLOY DOES NOT CLAIM

- **It does not prove any meter works in production.** Nothing here makes a
  vendor call; the four metering merges ship unexercised, by design, and the
  `api_usage_events` arm above is what says so.
- **It does not close B4.** `tm_anchor_entailment` is still UNPROVEN on a mocked
  run (`32706453`'s own ledger row).
- **It does not remove the repository's last `next/font/google` import.** It
  removes it from everything the gates and this deploy build. Seven live imports
  remain — `apps/meddoc-pro/src/app/layout.tsx` and six under
  `landing-monolith/` — none of which any workflow or deploy step builds. See the
  RELAY note filed with this deploy.
- **It does not change marketing's runtime font sourcing.** `next/font/google`
  self-hosts at build time too, so `quillmd.com` was never fetching fonts from
  Google at runtime and still is not. What the fix removes is the **build's**
  reach, and for marketing that lands whenever marketing is next rebuilt.
