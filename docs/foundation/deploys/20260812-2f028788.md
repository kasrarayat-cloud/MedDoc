## What would make the post-deploy check FAIL

Stated now, so it cannot be reinterpreted afterwards:

1. **`ledger_entries` > 0.** The writer executed. Nothing at this commit should
   be able to call it.
2. **Any clinical count moves.** No code in this range writes a visit, a patient
   or a signature.
3. **Migration count ≠ 100.** There is no migration here; a change means
   `db-migrate` applied something this range does not contain.
4. **`BILLING_ENFORCED` present in either container.** The flag is not part of
   this deploy and enabling it is a separate, later, owner-gated decision.
5. **A co-tenant status changes.** They share this host and are untouchable.
6. **`practices` ≠ 197 or active-member ≠ 175.** The step 3c backfill is
   declared against 175; if this deploy moves either number, the population
   under the *next* declaration was never the one that was measured.
