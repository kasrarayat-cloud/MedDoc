## WHAT THIS CHANGE DOES, IN ONE LINE

L7b stops writing an office-visit E/M code into `transcribe_visits.cptCodes.em`
for visits where E/M does not apply (imaging reports and operative/procedure
notes), and the incompleteness detector is told so it does not report the
deliberate absence to the doctor as a failed layer.

## ⚠️ IT IS FORWARD-ONLY, AND THAT IS THE SHAPE OF THIS DECLARATION

The change runs inside the **pipeline**, at visit-processing time. It cannot
reach a row that has already been processed. **So the honest expectation is that
NOTHING IN THE DATABASE MOVES**, and every clinical count is a MUST-NOT-CHANGE
row rather than a MUST-CHANGE one.

⚠️ **A DECLARATION WHOSE MUST-CHANGE COLUMN IS EMPTY IS NOT A DECLARATION**, so
the MUST-CHANGE rows here are STRUCTURAL: the shipped image must carry the new
predicate, and — per the over-permission rule — must NO LONGER carry the old
permissive shape. A presence-only declaration passes just as happily on the
broken version, which is exactly why the ABSENCE rows below exist.

throws its answer away — `const emApplies = true;` followed by a bare

is wired**, and this declaration's own text argues that a presence-only row
passes just as happily on the broken version — a principle it had applied to two
of three files.

Rows 1-4 are read with `docker exec … grep -c` inside the **worker** container
(the app image ships a BUILT Next application and does not contain this source —
a zero read there would be the instrument, not the system; see the recorded
two-zeroes-one-broken-instrument case). **Row 4 is the one that discriminates:**
rows 1-3 pass on a version that ADDED the gate and left the old assignment
beside it.

⚠️ **AND EVERY GREP CARRIES A TRAVERSAL CONTROL** — a count of `.ts` files under
`/app/apps/transcribe-md/src/worker/` must be non-zero in the same command run.
A probe that cannot see the tree returns 0 for every needle and looks identical
to a clean pass.

declaration and its own door (`run-ruled-mutation.sh`).

ship and operative notes are getting *"Auto-coding incomplete — cpt-coding: no
E&M code emitted. Click Retry to reprocess"*, which Retry can never clear.

## WHAT WOULD FALSIFY THIS DECLARATION

- any row 6-18 moving
- rows 1-3 reading 0, or row 4 reading non-zero, in the shipped worker
- a traversal control reading 0 (⇒ the probe is broken; the result is
  CANNOT-TELL, never a pass)

## WHAT THIS DEPLOY DOES **NOT** CLAIM

- **That any PDF or DOCX was rendered and read.** No clinical export was
  produced. The document-level proof is the E2E byte assertion inside the
  citation.
- **That a real visit was run through the pipeline.** The suppression is proved
  at the unit seam and by the shipped predicate; production verification here is
  structural by standing law, and a real doctor's visit is never a smoke target.
- **That the four existing operative-note E/M blobs are gone.** They are not.
- ⚠️ **That "forward-only" means only already-processed rows.** It is wider:
  `hasContent` treats ANY non-null `cptCodes` object as a completed L7b
  checkpoint and `retry/route.ts` does not clear the column, so a RETRY skips
  L7b entirely. Every row with a non-null `cptCodes` keeps whatever it holds.
- ⚠️ **That a shape flip after the fact is handled.** It is not — F12-e, filed
  in `RELAY.md`. A note edited from operative to office leaves the signed
  document with NO E/M while the screen shows one. Introduced by this change,
  and it moves the divergence from a WRONG field to an ABSENT one.
- **That a `-25` modifier no longer prints on an operative note.** It does —
  one production visit carries one, `modifiers` are untouched by design, and
  that divergence predates this change (ruling #127 records it as filed, not
  fixed).
