## ⚠️ A FINDING ABOUT THE PASSENGER HANDOFF ITSELF — #1002's INSTRUCTION IS UNBUILDABLE

`docs/deploy-declarations/t4-post-state-20260905.md` instructs that, on the
deploy that carries it, **"this file goes verbatim to
`docs/foundation/deploys/<YYYYMMDD>-<short-sha>.md`"**.

**Followed literally, that REFUSES this deploy — both ways round:**

| attempt | what `declaration_resolve` does |
|---|---|
| copy to `20260907-3869851c.md` | collides with THIS file → `exact_dup` → **exit 2, CANNOT TELL** |
| copy to `20260907-3869851c-PASSENGER-1002.md` | last dash-segment is `1002` — hex, but **4 characters**, and the resolver refuses anything under 7 → **exit 2** |

The resolver's recognised-kinds keep-list is `README`, `BASELINE-*`, `*-JUDGED`,
`*-RETROSPECTIVE`, `*-backfill-declaration`. **There is no passenger kind**, and
adding an unrecognised name to that directory refuses loudly by design.

**So #1002 is carried the way §2.5 actually requires — NAMED, not copied.** Its
declaration stays where it is, is cited by path above, and its expectations are
folded into the rows below. That is stronger than a verbatim copy, which would
have duplicated a document without connecting it to anything measurable.

⚠️ **Filed as a board item rather than fixed here:** either the resolver grows a
passenger kind, or the passenger-declaration template stops instructing a
handoff that cannot be performed. Fixing it inside a deploy would be a change
nobody declared.
