## ⚠️ FINDING FIRST: 15 OF 16 PASSENGERS SUPPLIED NO ROWS

`docs/foundation/deploys/rows/` contains exactly one file: `PR-999.md`. Under
ruling #184 **a passenger without rows is a FINDING, not a pass** — the deployer
can measure what a change TOUCHES, but only its author can say what it is
SUPPOSED to do and therefore what would be wrong.

This is the second occurrence: the `b54a3b3a` deploy found 8 passengers with
zero authored rows. The standing rule that rows are written at PR-open time was
made after that one and has not yet changed behaviour outside this lane.

**It does not block.** The rows below are DERIVED for every passenger, and the
derivation is named as such wherever it is weaker than an author's.

**`ADMIN-1`'s migration is declared here BY NAME rather than carried silently.**
That is the *overtaken, not overridden* hazard: nobody bypasses a gate — its
author's change simply reaches production inside somebody else's deploy, and
both parties behave correctly while an irreversible act goes unjudged.

`PRACTICE_SEAT_INVITED`, `PRACTICE_ROLE_CHANGED`, `PRACTICE_ADMIN_REFUSED`.

`ALTER TYPE … DROP VALUE`, which the migration's own header states. 153 → 156
enum values.
