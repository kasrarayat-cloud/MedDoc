## ⚠️ D4 — THE CHECK WAS MIS-DESIGNED, AND A CONTROL PROVED IT

`rosDocumentValue` and `isProseLabel` both read **0** in the shipped bundle.
That is **not** a failed deploy — they are **local, non-exported** functions, and
the bundler renames them.

**Discriminated with a control from a different era**, which is the only way this
could be settled:

| symbol | kind | shipped since | count |
|---|---|---|---|
| `resolveRosFinding`, `symptomsFor` | exported, pre-existing | months | **6, 8** |
| `inferTextKind`, `isScaffolded`, `normalizeLabel` | **local, pre-existing** | months | **0, 0, 0** |
| `readableRosToken`, `isEmptyText` | exported, NEW | this deploy | **9, 5** |
| `rosDocumentValue`, `isProseLabel` | **local, NEW** | this deploy | **0, 0** |

Three functions that have shipped for months read zero. **A local name never
survives into the bundle**, so the check could not discriminate presence from
absence and should never have been written that way.

**What settled it instead was behaviour**, and it is stronger than the grep would
have been: on the deployed code the pinned form compiles with `ros_gi_weight` =
`narrative_text`, and the certified production version records that kind. #216
demonstrably shipped.

**THE LESSON, FOR THE NEXT ROWS FILE:** a bundle-presence row must name an
**exported** symbol, or it is measuring the minifier. The two exported symbols in
this same row worked exactly as intended.
