## WHAT THIS FIXES

`enqueueAutoCertifyTwin` could never create a job — BullMQ refuses a custom job
id containing a colon, at `add()` time. Auto-certification was inert in every
environment. Proven by running the real backfill against production, which
refused before enqueueing anything.

## WHAT THIS DEPLOY DOES NOT CLAIM

- **That any template certifies.** The backfill is a separate, explicit act
  after this deploy is judged. The lifecycle fill-coverage gate has still never
  run against a real model, and both outcomes remain acceptable.
