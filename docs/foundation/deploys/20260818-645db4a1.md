**Item:** F12-a — E/M is suppressed on procedure and operative notes
(ruling **#123** part 2, as split by **#125**), with the note-text fallback and
the office counterweight of ruling **#126**.

**Written and committed BEFORE the deploy runs.** Every number below was
measured read-only against production on **2026-08-18**, before anything was
built, migrated or recreated. The post-deploy comparison is judged against this
file and nothing else.

## WHAT IS SHIPPING

**Code only. NO MIGRATION. NO NEW COLUMN. NO FLAG.**

The change is a **projection**: it decides whether an office-visit E/M level is
DISPLAYED and EXPORTED, plus one conjunction that stops a level being FROZEN
onto a signed record at sign time. It writes nothing to any existing row.

⚠️ **THE PAYLOAD IS THIS BRANCH AND NOTHING ELSE — checked, not assumed.** If
`main` has moved between the merge and the deploy, the deploy is shipping a
tree larger than this declaration's scope, and *"I deployed `main`"* is not the
same claim as *"I judged what I deployed."* That check is part of the
comparison below, not a footnote to it.

suppresses nothing, and this is a fix to something too permissive.** These rows
are the ones that can detect over-suppression, which ruling #123 calls worse
than the defect being fixed.

| # | row | required after |
|---|---|---|

| A2 | office visits that STOP printing a level (over-suppression) | **0** — the five in §2 are all operative by their own headings or their template; no other row may move |
| A3 | untemplated visits with NO operative markers that keep their level | **21**, unchanged — of which 4 bariatric-surgery and 1 GI carry a code and keep it |
| A4 | `transcribe_visits` count | **46** |
| A5 | `transcribe_md_patients` count | **34** |

| A7 | `emScoredCode` non-null count | **17** — the deploy writes no column |
| A8 | `cptCodes.em` blob count | **27** — suppression is a PROJECTION; the stored blob is untouched |
| A9 | `cptCodes.em.signedCode` count | **6** — the sign-route conjunction only affects FUTURE signs |
| A10 | `note_templates` count | **10** |

⚠️ **A7, A8 AND A9 ARE THE HONEST ONES.** This deploy does **not** clean up the

is an irreversible production mutation and belongs behind
`run-ruled-mutation.sh` with its own declaration — not as a side effect of a
deploy. **A comparison that showed these counts FALLING would be a finding, not
a success.**
