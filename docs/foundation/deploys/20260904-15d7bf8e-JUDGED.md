## ⚠️ THREE DEFECTS IN MY OWN DECLARATION, NAMED RATHER THAN LET PASS

A judgement that only reports the rows it passed is worth less than one that says
where the declaration itself was wrong. All three are mine.

### 1 · `audit_logs` was declared "expected to GROW". It held.

The declaration said *"expected to GROW (deploy activity itself writes rows). Its
growth is the instrument for the rows above."* **A deploy writes no audit rows**,
so the prediction was simply wrong.

instrument was NEVER EXERCISED.** Every clinical count held, so nothing needed
explaining, so the mechanism that would explain a movement was never asked a
question. **Its first real test is still ahead.** Row 17 is marked ✓ because the
count is consistent with a system where nothing happened — not because the
instrument was shown to work.

### 2 · I declared a co-tenant comparison for which I had captured no baseline.

The declaration promised *"co-tenant HTTP status unchanged"* and the baseline
section never recorded one. Row 20 is discharged **against the previous
judgement's record** (`20260903-376bae1e-JUDGED.md`, which documents
`307 / 410 / 404 / 200`), not against a measurement I took before the act.

That is weaker than the other rows and is marked as such here. *A declaration
that names a comparison must capture its own before-value; borrowing one from a
prior report is a recovery, not a design.*
