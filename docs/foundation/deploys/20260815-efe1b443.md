## WHAT SHIPS

A **document-visible** change: **every DOCX-derived surface now renders the
note's STORED numbers.**

`docx-generator.ts` used to emit a numbered line with
`numbering: { reference: 'plan-numbering' }` and only the text AFTER the marker,
letting Word paint the number. One numbering instance is shared by the whole
document, so a second numbered section CONTINUED the first — a note storing
POSTOPERATIVE FINDINGS 1/2/3 then RECOMMENDATIONS 1/2/3 exported as
RECOMMENDATIONS **4/5/6**. The marker is now emitted as literal text with a
hanging indent.

Second change in the same deploy: the preview fill-cache key moves
**`visitdoc:v2` → `visitdoc:v3`** — both the writer and `invalidateVisitFills`'s
SCAN pattern, together.

content was always the stored text — the export was the thing that was lying
about it.

believed** — the same regex form finds `## ` headings in all 42 non-null rows
(so the traversal reaches the column), and an impossible token (`9999999. `)
returns 0 (so it discriminates). A sweep that returns nothing and a sweep that
is broken produce the same output.

## MUST CHANGE

1. **image ids** for `transcribe-md` and `transcribe-md-worker`.
2. **The bytes of every DOCX-derived surface for the 18 visits above** — Word
   export, the pre-sign preview, and the signed document surface. The numbers
   they show become the numbers the note stores. For the **12** multi-section
   visits this is a VISIBLE correction; for the other 6 the rendered numbers
   were already right and only the MECHANISM changes (literal text instead of a
   Word numbering reference), plus a hanging indent.
3. **Redis preview-cache keys** move to the `visitdoc:v3:` prefix. Existing `v2`
   entries become unreachable and expire on their own TTL. **This is the point
   of the bump** — without it a doctor reloading the pre-sign canvas would be
   served PRE-FIX bytes (RECOMMENDATIONS 4/5/6) while `…/export/docx` returned
   1/2/3: two surfaces that agreed BEFORE the deploy disagreeing AFTER it.

## MUST NOT CHANGE

- **every clinical count**: visits **44**, signed **26**, patients **31**,
  templates **9**; `audit_logs` monotonic from **11445**.
- **migrations stay 104.** This change carries NO migration.
- **the twin tables stay 0 / 0 / 0.** Nothing here compiles, certifies or fills
  a twin. A non-zero would mean a doctor uploaded a `.docx` during the window —
  RC-2's intended behaviour, and it would need saying, not hiding.
- **the PDF EXPORT leg is byte-unchanged.** `…/export/pdf` runs
  `generateVisitPdf` (pdfkit), a SEPARATE builder this diff does not touch —
  ruling **#113** / RELAY **F3**. Verified by reading it: `renderSoap` has **no
  numbered-line branch at all**, so a `1. ` line falls through to the inline
  renderer and its literal marker was always printed. This deploy does not
  alter it.
  ⚠️ **Stated explicitly because the branch's own comment in `fill-cache.ts`
  reads as though `…/export/pdf` shares the fix.** Its OUTCOME claim is true
  (that route returns 1/2/3) and its implied MECHANISM is not — the PDF was
  never repainted, so nothing about it was "corrected". Recorded as a finding
  for F3 rather than corrected by a push that would have cancelled three
  in-flight runs.
- **the in-app `SoapBody` markdown surface** — it renders the stored text and
  was already correct. #112 records that this fix INVERTED which surface was the
  reference: the in-app view was the one telling the truth, and the war room's
  belief that Word rendered correctly was withdrawn as unverified.
- co-tenant status: `app` 307 · `admin` 404 · `quillmd` 200 · `www` 200 ·
  `pro` 410.

## ⚠️ WHAT WOULD MAKE ME ROLL BACK

- any clinical count moving.
- migrations reading anything but **104**.
- `app /api/health` not 200, or either container failing to settle.
- a re-exported visit still showing continued numbering (RECOMMENDATIONS
  **4/5/6**) — that would mean the built image does not contain the fix.
- a numbered line rendering with its marker MISSING (`. Delta finding`) or
  DOUBLED (`4. 4. Delta finding`) — the two ways a literal-text render can be
  wrong, and neither is caught by "the numbers look plausible".
