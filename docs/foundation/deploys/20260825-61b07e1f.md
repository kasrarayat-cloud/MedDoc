## ⚠️ THIS SUPERSEDES `20260825-bd1eeb57.md`, AND THE REASON IS MECHANISM NOT ERROR

That declaration was correct and is now **unresolvable**, because
`declaration_resolve`'s non-runtime allowlist is
`^(docs/|[^/]+\.md$)` — **fail-closed by design**. PR #842 landed
`scripts/check-hooks-installed.sh`, `scripts/retire-branch.sh` and one test file
between it and the head. None of those ships in the image; all three defeat a
carry-forward, correctly, because the resolver cannot know that.

⚠️ **THE RUNTIME PAYLOAD IS BYTE-FOR-BYTE THE SAME 16 FILES** — asserted by
diffing the two ranges' runtime sets, which came back identical. Nothing about
what reaches a patient changed between the two declarations; only the paperwork
had to catch up.

> **STRUCTURAL NOTE, worth having: in a repository with a live unattended loop, a
> declaration's carry-forward is defeated by ANY non-docs commit. The window
> between landing a declaration and firing the deploy is therefore a race, and
> the honest response is a fresh declaration each time — never a stretched one.**

The superseded file stays in place: it is the record of a judgement that was
prepared and correctly not used.
