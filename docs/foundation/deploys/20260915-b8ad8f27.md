## WHY THIS DEPLOY

Ruling #322 (S2-4): for a PDF-origin template whose compiled twin is CERTIFIED,
the visit export renders on the doctor's ORIGINAL PDF page using the TWIN's
resolved field values (anchors re-derived from the twin's fields, keyed by
fieldId), instead of the note-heading split. A value that cannot be placed, or a
non-certified/uncertain shape, falls back to the twin's STRUCTURAL styled render
with a coded reason — never a value on a guessed line. Preview and export share
the renderer. Flag-gated (native-docx + native-pdf) + fail-safe.

FIVE adversarial passes hardened it (one reader = S1's classifyParagraph; count,
bare-marker, exact-alias, inline/block and freshness guards; twin-or-styled,
never note-heading). The design is SAFE-BIASED: the doctor's page when certain,
the styled render otherwise.
