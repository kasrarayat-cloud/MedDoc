## 1. WHAT KIND OF DEPLOY THIS IS

**CODE-ONLY. NO MIGRATION.** The repo holds 96 migrations and the database has
96 applied; this change adds none.

**So the declaration is one line: nothing moves but the image ids.**

That is unusually strong for this item, and deliberately so. Everything B4 step 1
changes is reachable ONLY under `MOCK_AI_CALLS`, which production never sets:

- `deepgram-batch.ts` — production takes `mockRes ?? await fetch(...)` where
  `mockRes` is `null`, so the expression **is** the original `await fetch(...)`.

  unchanged.

row: `operation` becomes the call's purpose and `modelName` the model actually
requested, instead of the literals `transcribe_realtime` / `nova-3-medical`.

**3 Deepgram rows in the entire history** of `api_usage_events`. Every production
visit is `text_notes`. So the expected reading is that even the label change is
invisible today — it is correctness for the next audio visit, not a change to
anything now stored.
