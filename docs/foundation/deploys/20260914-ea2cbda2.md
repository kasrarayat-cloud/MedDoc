## WHY THIS DEPLOY

Owner finding (2026-09-14): the owner re-uploaded
`Colonoscopy_Operative_Template.pdf` and the Note-format preview came back a
SOLID WHITE page. Cause, named: pdf-lib's default save (`useObjectStreams:true`)
writes a cross-reference STREAM whose `/Root` reference is corrupt when a
continuation page is appended (`drawAppendedSection → doc.addPage`) to a
template that ITSELF uses xref streams — which ReportLab forms do. The browser's
pdfjs cannot recover and paints white. Isolated: `load+draw+save` fine;
`load+draw+addPage+save` corrupts. Root fix: `fillPdfTemplate` saves with
`useObjectStreams:false` (a classic xref table). This ALSO fixes a latent
signed-export corruption — the same engine feeds `export.ts`. Folded in the
#321 multi-blank re-pass fix.
