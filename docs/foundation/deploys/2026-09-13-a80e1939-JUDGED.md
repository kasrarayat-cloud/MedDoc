# JUDGED — a80e1939: an upload never displaces a working certified form

The owner's clarification of the re-upload displacement rule (fix 3), owned
end-to-end: built at the root, refuted, deployed, judged.

## The rule (owner's words, implemented)

Keep the picker dedupe (#1128). Add: **a save/upload never becomes the active
template when an ACTIVE, CERTIFIED form already exists for the same (doctor,
encounterType).** It lands as a **draft** — the certified form stays active — and
goes live only through **certification** or the **owner's explicit choice**. No
lineage supersede.

## Why it was needed

`saveNoteTemplateAction` activated on save and superseded the prior active
(one-active-per-slot). An uncertified upload thus knocked out a working certified
form; if its certification then failed (blocking mappings, a prose "form", a
converter outage) the doctor was left with no certified native form at all.

## The fix

- **Server**: read the single active row for the slot; hold the save as a draft
  when it is certified. Certification is recognised for **both kinds** — DOCX twin
  (`templateTwinCompiledVersion` CERTIFIED) and flat PDF
  (`styleProfile.pdfNativeCertified`) — checked in code (a flat-PDF form has no
  twin row). A held DOCX draft still auto-certify-enqueues and goes live via
  certification (which supersedes); a held PDF draft goes live via explicit
  choice. A doctor's first form (nothing certified) still activates on save.
- **UI honesty**: three save surfaces (note-format-manager onConfirmFormat /
  onRetryCert, the persistent `ConfirmCard` cert-failure banner, template-review-
  editor) stop claiming "Format activated" for a held draft — keyed off the actual
  status. The held notice is cleared with the pending upload so it cannot outlive
  it.

## Adversarial refutation pass (mandatory on this path)

The **first** implementation shipped a twin-only guard. The pass **CONFIRMED
(7/7 verdicts)** two real gaps, both fixed before merge:
- **clinical-harm** — the twin-only guard silently displaced PDF-native certified
  forms (cert stored in `styleProfile`, no twin row) → the guard now checks both
  cert kinds; the gate has a dedicated pdf-native arm.
- **correctness** — the persistent `ConfirmCard` banner hardcoded "Your format is
  active", shown for a held draft → held-aware banner.

**Scoped out (matches the owner's "same encounter type"):** a certified catch-all
(encounterType null) shadowed by a new specific-type upload — different slots, and
a specific-type template taking precedence over the catch-all for its own type is
arguably desired, not a displacement (the catch-all is not deactivated). Flagged
for the owner; extend only on request.
