# §2.5 ROW — PR #1014, `ros.*` registered

**Written at PR-open time, per the standing rule.** Runtime change:
`apps/transcribe-md/src/lib/template-twin/concept-registry.ts`.

## THE ONE ROW THAT PREDICTS A DIFFERENCE

| # | row | before | after |
|---|---|---|---|
| 1014-V1 | `isRegisteredConcept('ros.<system>')` | **false** | **true** |

## WHAT THAT CHANGES AT RUNTIME, STATED AS A CAPABILITY NOT A COUNT

The mapping **proposer** stops nulling `ros.*` candidates
(`semantic-mapping/index.ts:266,518`). On any template compiled or re-proposed
**after** this ships, a control the compiler or the model reads as a ROS clause
may now carry a `ros.<system>` concept where it previously carried `NULL`.

⚠️ **NO EXISTING ROW CHANGES BY ITSELF.** Stored mappings are not rewritten by
this deploy; `factSatisfiesMapping` never consulted the registry, so nothing
already filling stops filling. The change is visible only where a proposal is
computed — a new upload, a re-compile, or a re-proposal.

⚠️ **AND THAT IS THE HAZARD WORTH NAMING**: a mapping hand-written as `ros.*`
BEFORE this ships would fill correctly and then be **nulled at the next
compile**. After this ships it survives. So this must land before any ROS
mapping is written, not after.

## MUST NOT CHANGE

- **Every clinical count** — visits, signed, patients. This ships no migration
  and writes no row.
- **Applied migrations**: unchanged.
- **Certified mappings on every existing compiled version**: unchanged. The
  registry is read at PROPOSAL time, never at fill time.
- **`approvedMappingsSha256` / `compiledStructureSha256`** on any certified
  version: unchanged — the registry contributes to neither.

## THE FINDING RULE

**A difference this row does not name is THE FINDING**, whatever its explanation
sounds like afterwards.
