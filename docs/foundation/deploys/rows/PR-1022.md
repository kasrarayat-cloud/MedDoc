## ⚠️ CORRECTION — 1022-C3 WENT RED, AND THE MECHANISM WAS NOT THE ONE DECLARED

**Appended before the merge, never rewritten.** The row predicted the gate
would **REFUSE** this PR (exit **1**) for carrying runtime files with no rows.

**Measured on run `34052168551`:**

    🔴 no merge base
    ##[error]Process completed with exit code 2

**Exit 2 is CANNOT TELL, not refusal.** The gate never reached its rows check at
all — it could not compute a diff, and fail-closed correctly rather than passing
on a broken instrument.

> **A row that predicts RED and gets RED is not thereby satisfied.** The
> declaration named a mechanism, and the mechanism was different. Read quickly,
> a red step here looks exactly like the gate working; it was the gate unable to
> run. That is the whole reason §2.5 asks for a falsifier rather than an
> outcome.

### THE CAUSE

`actions/checkout@v4` defaults to a **depth-1** clone. A `git fetch --depth=200`
of the base branch on top of that still shares **no common ancestor** with the
PR head, so `git merge-base` returns nothing.

⚠️ **AND THE ANSWER WAS ALREADY IN THE REPOSITORY, ONE FILE OVER.**
`e2e.yml:65` carries `fetch-depth: 0` with the comment *"the predicate diffs
`base...HEAD`; a shallow clone would fail CLOSED"* — naming this exact failure
mode. A second, shallower spelling was written anyway. **This is the
one-normaliser-two-callers lesson in its cheapest form: the house had solved it,
and the fix was to read rather than to invent.**

### THE FIX, AND WHY IT IS TWO CHANGES

1. **`fetch-depth: 0`** on the checkout preceding the gate.
2. **The base is `github.event.pull_request.base.sha`, not
   `origin/${{ github.base_ref }}`** — the same source `e2e.yml` uses. A branch
   ref *moves*: if the base advances while a run is queued, `origin/main` names
   a tree the PR was never diffed against and the runtime file set changes
   underneath the answer. A sha cannot drift.

**Both arms proved locally against a sha base:**

    PR_NUMBER=1022  → 🟢 4 runtime file(s), rows supplied for PR #1022   exit 0
    PR_NUMBER=9999  → 🔴 names a DIFFERENT PR … expected PR-9999.md      exit 1

**Exit 1 is the refusal C3 meant.** A new arm pins the wiring, and removing
`fetch-depth: 0` reds it — because a permanently-red gate is the state somebody
eventually "fixes" by deleting the step.

### WHAT THIS COSTS THE ROW

**1022-C3 is judged a FINDING.** Its prediction and its outcome agree on the
colour and disagree on the cause, and the corrected wiring has **not yet been
observed green in CI** at the time of writing — only locally. The next run on
this branch is what discharges it, and that run's exit code is the evidence, not
this paragraph.
