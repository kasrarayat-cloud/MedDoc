# §2.5 AUTHOR ROWS — PR #1015, REVIEW-DEFAULTS item 1

**Written at PR-OPEN time, before the act**, per the ADMIN-1 board filing and
ruling #184: a passenger without author rows is a FINDING, not a pass.

**Lane:** Design/Admin. ⚠️ **THIS PR CARRIES A MIGRATION** —
`20260906000000_review_defaults_scaffold_insert`.

    ALTER TYPE "AuditAction" ADD VALUE IF NOT EXISTS 'DEFAULT_INSERTED_BY_DOCTOR';
    ALTER TYPE "AuditAction" ADD VALUE IF NOT EXISTS 'DEFAULT_INSERT_UNDONE';
    ALTER TABLE "template_twin_field_overrides"
      ALTER COLUMN "selectedOptionOrdinal" DROP NOT NULL,
      ALTER COLUMN "optionValue"          DROP NOT NULL,
      ADD COLUMN  "overrideKind" TEXT NOT NULL DEFAULT 'option',
      ADD COLUMN  "insertedText" TEXT;
    + CHECK template_twin_field_overrides_kind_shape

⚠️ **THE TWO ENUM VALUES ARE PERMANENTLY IRREVERSIBLE.** Postgres has no
`ALTER TYPE … DROP VALUE`. Two are added rather than one because an undo
emitted under the insert's label makes every action-level rollup count a
reverted assertion as an assertion — which defeats the only thing the
irreversible add was bought for.

**Appended, never rewritten. The original pair is quoted here so the mistake is
legible, because the mistake is the point.**

| | before | after |
|---|---|---|
| as written at PR-open | **158** | **160** |
| **as measured** | **156** | **158** |

**MEASURED, three ways that agree:**

    -- production, meddoc-pro-postgres-1
    SELECT count(*) FROM pg_enum e JOIN pg_type t ON t.oid=e.enumtypid
      WHERE t.typname='AuditAction';                                    -- 156

    -- main's schema, which ALREADY CONTAINS the two values this PR adds
    awk '/^enum AuditAction \{/{f=1;next} f&&/^\}/{f=0} f' \
      packages/db/prisma/schema.prisma | grep -cE '^[[:space:]]*[A-Z][A-Z0-9_]*'
                                                                        -- 158

    -- the set difference, both directions
    schema - db = {DEFAULT_INSERTED_BY_DOCTOR, DEFAULT_INSERT_UNDONE}
    db - schema = {}   (empty — nothing in production is missing from the tree)

### THE MECHANISM, AND IT IS GENERALISABLE

**The "before" was taken from `schema.prisma` on the branch being shipped.**
That file already carries the two new labels — adding them is what the PR *is* —
so the number read back was the **AFTER**, and "after" was then computed as
that plus two. Both figures describe a state that has never existed anywhere.

> **A §2.5 "before" read from the tree under deployment is not a before. It is
> the after, measured early.** The only instrument that can answer *"what is
> true now"* is the running system.

This is the WATCHED-SET failure in its cheapest costume: the query was correct,
the arithmetic was correct, and the universe was wrong. The same shape has now
been recorded three times in this programme — a grep of `origin` for a file that
is local, a grep of `main` for a gate that lives on a branch, and this.

### WHY IT MATTERS MORE THAN AN OFF-BY-TWO

`ALTER TYPE … ADD VALUE` is **permanently irreversible** — this file says so at
the top. The deploy would have landed on **158**, and 158 scores as a **FAILED
must-change** against a row demanding 160. That is the worst possible moment to
meet a wrong number: the act is done, it cannot be undone, and the pressure is
to explain the figure rather than believe the instrument.

⚠️ **AND THE FALSIFIER WAS WRITTEN WELL ENOUGH TO FIRE.** N5 says any movement
other than the two added labels means something else altered the type. Judged
literally against the original C1, a correct deploy would have been read as a
failure — a false rejection, not a false green. The row was honest; its inputs
were not.

**Found by re-deriving the row against production during a state
reconstruction, before the deploy. Nothing was deployed on the wrong pair.**

## ⚠️ WHAT THESE ROWS CANNOT DETECT, SAID PLAINLY

A derived row cannot see the thing this PR is actually about: whether a stored
default ever lands on a field the encounter DENIED. That is not observable from
a schema or a bundle — it needs the clinical walk on QA, and the arms in
`gate-review-defaults-insert` are what stand for it between deploys. Named here
rather than implied as covered.
