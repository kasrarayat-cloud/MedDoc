**Written before the act**, per the ADMIN-1 board filing
(`docs/foundation/board/ADMIN1-ROWS-AT-PR-OPEN.md`) and ruling #184.

**Lane:** custom-file. **⚠️ MIGRATION-CARRYING** —
`20260907000000_r217_concept_scope_column`. Runtime files: the Prisma model, the
certification writer, the draft INSERT, and four loaders.

## MUST CHANGE

| # | row | before | after | falsifier |
|---|---|---|---|---|

## MUST NOT CHANGE

| # | row | expectation | falsifier |
|---|---|---|---|
| **1037-N1** | rows with a NON-NULL `conceptScope` | **0 of 185**, before AND after | ⚠️ **THE DE-CERTIFICATION ROW.** The migration has no `DEFAULT` precisely so existing rows stay NULL. A single non-null row means the migration back-filled, every mapping's attestation sha moved, and all 185 certified mappings are orphaned |
| **1037-N2** | `certificationStatus` across compiled versions | **CERTIFIED 3 of 4**, unchanged | if certification moved on a code+migration deploy, the attestation hash moved — which is exactly what N1 exists to prevent |
| **1037-N3** | twin field definitions / mappings | **185 / 185**, certified **185** | a migration that adds a column must not touch a row |
| **1037-N4** | clinical counts — visits **58**, signed **40**, patients **0** | unchanged | never omitted, per §2.5 |
| **1037-N5** | `AuditAction` enum cardinality | **156**, unchanged | this migration adds a column, not a label. Movement means a second migration rode unnamed |

⚠️ **N1 IS THE WHOLE POINT OF THE MIGRATION'S SHAPE, AND IT IS NOT COSMETIC.**
`canonicalSha256` hashes `[]` as a value and refuses `undefined`. A `DEFAULT '[]'`
would have rewritten all 185 rows into a value, moved every attestation sha and
de-certified every template in one statement — silently, because nothing throws.
The column is nullable with no default and the read-back OMITS the key, so a row
that predates the column hashes exactly as it did before the column existed.

    psql -tAc "SELECT count(*) FROM _prisma_migrations
               WHERE migration_name LIKE '%r217%';"                          # 0 -> 1

    psql -tAc "SELECT count(*) FROM template_twin_semantic_mappings

    psql -tAc "SELECT \"certificationStatus\", count(*) FROM template_twin_compiled_versions

⚠️ **THE COLUMN COUNT IS THE POSITIVE CONTROL AND ALSO A CHECK**, which is
legitimate here only because its BEFORE and AFTER are both stated (22 → 23). A
control whose expected value does not move would prove the query runs and
nothing else.
