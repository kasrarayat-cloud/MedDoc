# §2.5 AUTHOR ROWS — PR #999 (rulings #191 + #192)

**Written at PR-OPEN time, per the standing rule, not at declaration time.**
The deployer composes; the author supplies what a deployer cannot: what the
change is *supposed* to do, and therefore what would be a **FINDING**.

⚠️ **THIS PR CARRIES A MIGRATION, SO ITS DEPLOY TAKES THE STRICT
COMMITTED-FIRST DECLARATION** — ruling #198. The declaration's commit timestamp
must provably precede the act.

## THE MIGRATION

`20260905120000_r191_unmentioned_policy`

```sql
ALTER TABLE "template_twin_semantic_mappings"
  ADD COLUMN "unmentionedPolicy" TEXT;
```

**Nullable, no default.** Metadata-only on PostgreSQL 16 — no table rewrite, a
brief ACCESS EXCLUSIVE lock. No backfill, and **a backfill would be a defect**:
NULL is the meaning "nobody ruled a policy", which is the fail-closed state.

⚠️ **#194 COLLAPSED THE VALUE SET TO `NULL | 'omit'`.** The `'keep'` half was
designed, built, adversarially tested across three rounds and then DELETED — its
premise was refuted, not merely its mechanism. Nothing in this deploy can write
`'keep'`; row 999-5b checks that nothing did.

## ⚠️ A VISIBLE CHANGE — THE ONE THING A DOCTOR WILL SEE

**Filled dropdown controls no longer display the template prompt in Word.**

`w:showingPlcHdr` asserts *"what you are looking at IS the placeholder"*, and
Word acts on it by re-displaying the template's own prompt. Its removal lived
inside `sdtBoundedClearPatches`, which only the `value === null` branches call,
so **every FILLED control kept the flag** and the doctor's own dictated value
was displayed as `Choose an item.`

| # | row | before | after |
|---|---|---|---|
| 999-V1 | `showingPlcHdr` surviving a FILLED render of `WM IOV Template.docx` | **28 of 28** | **0 of 28** |

**Verification is that measurement**, re-run against the deployed image's own
compiler and renderer: compile the tracked blank fixture, resolve every
`single_select` to `allowedOptions[1]`, render, and count the flag in
`word/document.xml`. It needs no visit, no patient and no clinical record —
the fixture is a BLANK customer form, which is why it is tracked.

⚠️ **AND IT IS THE ONLY ROW HERE THAT PREDICTS A DIFFERENCE.** Everything below
predicts sameness. A visible change that is not declared in advance is
indistinguishable after the fact from a regression, and this one alters what a
doctor sees on a signed document.

## THE FLAG-IS-INLINED ROW, STRUCTURAL

There is no `NEXT_PUBLIC_*` flag in this change. The observable is the shipped
bundle's resolver behaviour, which cannot be established without mutating a
record, so it is **NOT claimed structurally** and is left to the QA walk. An
unverified step named honestly is worth more than a green tick bought with a
patient's record.

## ⚠️ THE ROW THAT WOULD HAVE CAUGHT THE DEFECT THIS PR FIXES

999-5 is the important one. Under the shape #192 rejected, the column arrived
`NOT NULL DEFAULT 'keep'`, which would have made **every existing mapping**
report a declared keep — silently opting every certified template into printing
its own default content. A census of non-null values immediately after the
deploy is the cheapest possible detector, and it has exactly one correct
answer, fixed here, before the act.
