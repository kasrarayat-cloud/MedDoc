# §2.5 AUTHOR ROWS — PR #999 (rulings #191 + #192)

**Written at PR-OPEN time, per the standing rule, not at declaration time.**
The deployer composes; the author supplies what a deployer cannot: what the
change is *supposed* to do, and therefore what would be a **FINDING**.

⚠️ **THIS PR CARRIES A MIGRATION, SO ITS DEPLOY TAKES THE STRICT
COMMITTED-FIRST DECLARATION** — ruling #188. The declaration's commit timestamp
must provably precede the act.

## THE MIGRATION

`20260905120000_r191_unmentioned_policy`

```sql
ALTER TABLE "template_twin_semantic_mappings"
  ADD COLUMN "unmentionedPolicy" TEXT;
```

**Nullable, no default.** Metadata-only on PostgreSQL 16 — no table rewrite, a
brief ACCESS EXCLUSIVE lock. No backfill, and **a backfill would be a defect**:
NULL is the meaning "nobody declared a policy", which is the fail-closed state.

## THE FLAG-IS-INLINED ROW, STRUCTURAL

There is no `NEXT_PUBLIC_*` flag in this change. The observable is the shipped
bundle's resolver behaviour, which cannot be established without mutating a
record, so it is **NOT claimed structurally** and is left to the QA walk. An
unverified step named honestly is worth more than a green tick bought with a
patient's record.

## ⚠️ THE ROW THAT WOULD HAVE CAUGHT THE DEFECT THIS PR FIXES

999-5 is the important one. Under the shape #192 rejected, the column arrived
`NOT NULL DEFAULT 'keep'`, which would have made **every existing mapping**
report a declared keep — silently opting every certified template into printing
its own default content. A census of non-null values immediately after the
deploy is the cheapest possible detector, and it has exactly one correct
answer, fixed here, before the act.
