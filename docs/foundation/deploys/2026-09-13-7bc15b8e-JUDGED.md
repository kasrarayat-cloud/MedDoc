## The owner finding

A new visit created on the certified **Operative Note** (`8e22a23d`) showed the
chromeless SOAP editor with **no PDF/Word export at all**.

## Cause — named, measured read-only and structurally (issue CODES only)

| step | evidence (live production, before the fix) |
|---|---|
| recorded template | `8e22a23d-eefe-4f0d-8e3d-d7fd381a2fe2` — "Operative Note", CERTIFIED twin |
| the one ambiguous field | `Surgeon` (`ttf_5e2a8db5…`, concept `procedure.surgeon`) → `ambiguous / experiencer_not_approved` |
| blocking issue | that ambiguity added a blocking `FIELD_AMBIGUOUS` |
| render | `fill-engine` withheld the verified native render (`render: null` on `!validation.valid`); the manifest's `outputObjectKey` is null, `roundTripVerified` false |
| why HIDDEN, not a named miss | `previewVisitDocumentAction` returned a bare `miss('no_render')`, and a bare miss makes `VisitDocumentSurface` render nothing and step aside to the chromeless editor — taking the PDF/Word surface with it |

**Deeper cause.** The resolver's experiencer gate hard-coded the **single** concept
`visit_metadata.referring_physician` as the only clinician-subject concept whose
facts may carry `experiencer: 'other'`. `procedure.surgeon` is the signing
clinician — minted `'other'` exactly like the referrer by `withOperativeRecordFacts`
— but was not admitted, so **every** certified operative note blocked on the
Surgeon field. The synthetic round-trip could never catch it: record-derived
fields never fill synthetically (there is no record in a synthetic proof).

## The three fixes (root)

1. **(2) What blocked the fill — the crux.** Shared
   `OTHER_EXPERIENCER_CLINICIAN_CONCEPTS = {referring_physician, surgeon}` is the
   one source of truth for "whose subject is a clinician"; the resolver gate reads
   it. Surgeon now resolves (record-derived → `record_derived`, non-blocking), the
   native render is produced, export works.
2. **(1) The export surface is never hidden.** A blocked / failed / no-tenant fill
   on the certified path now **degrades to the styled document** (same paginated
   surface, same export the doctor would download) with a named reason, instead of
   a bare miss. New reason `native_fill_blocked` (a withheld render is not a draw
   failure). The surface speaks the reason on a rendered styled document — in PDF
   **and** Word mode and when the converter is down — never the generic "set up a
   form" hint to a doctor who has one.
3. **(3) Re-upload displacement.** A re-upload mints a new lineage with the SAME
   name, so the picker accumulated indistinguishable certified duplicates (owner
   practice: 2× "Gastroenterology Consultation", 2× "GI Consultation Note", all
   the owner's, all `encounterType` null). `displacedByReupload` collapses
   same-`(doctorId, encounterType, name)` certified rows to the practice default,
   else the active row, else the newest. Display-only and reversible — no template
   row is edited or retired.

> ⚠️ **OWNER DECISION — fix (3) is an INTERPRETATION.** The previous finding's
> exact displacement-rule text could not be located in the ledger/canon, so (3)
> is: **picker-dedupe, default > active > newest-certified**, chosen because it is
> low-risk, reversible, and needs no migration or data mutation. If a lifecycle
> SUPERSEDE (retiring older lineages' certification, like `maxActivePerSlot`) was
> intended, that is a larger, irreversible change I did **not** make. Residual
> limit: minted twins all carry `encounterType: null`, so one doctor's two
> genuinely-different same-named certified twins still collapse to the survivor —
> unavoidable without a distinguishing signal, and already indistinguishable to
> the doctor pre-fix. **Please confirm which rule you meant.**

## The existing blocked visit heals itself

No data change is needed for the owner's visit. `previewVisitDocumentAction`
re-runs the twin fill on every mount (the fill cache is written only on success),
so the next open resolves the Surgeon (fix 2) and renders the native document with
export; and even a fill that still blocked for any other reason now degrades to
the exportable styled document (fix 1).
