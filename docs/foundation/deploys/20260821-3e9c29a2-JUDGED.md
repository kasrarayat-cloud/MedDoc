## ⚠️ THE DEPLOY REFUSED ONCE FIRST, AND THE REFUSAL WAS CORRECT

The first invocation was made **from the worktree** — my shell's cwd had
persisted into `/opt/meddoc-pro/.f5i-wt` from an earlier `npx tsc` run. The
script read `git rev-parse HEAD` as **`766aac04`** (the worktree's detached
head) rather than `d7cc0246`.

F9's rollback gate refused before anything happened:

    🔴 REFUSING — service 'transcribe-md' has no running container.
    🔴 ROLLBACK TAGGING FAILED — the deploy must not proceed.
       Nothing has been built, migrated or recreated. Production is untouched.

⚠️ **IT CAUGHT A MISTAKE IT WAS NOT DESIGNED FOR.** F9 exists to stop a deploy
with no way back. What it actually prevented here is the hazard canon names as
*"YOU CANNOT SIDESTEP IT BY DEPLOYING FROM A WORKTREE"* — `docker-compose.yml`
carries RELATIVE bind mounts (`./Caddyfile`, the two `infra/` scripts), so
`docker compose up` from another directory **re-points the ingress config bind
at that directory**, and reaping the worktree later leaves it dangling.

**The tell was that compose found no running containers** — because the project
name derives from the directory, so it was looking at a different project
entirely. Re-run from `/opt/meddoc-pro` with HEAD at the cited `d7cc0246`, it
proceeded normally.

> **The Bash cwd is a deploy input.** MASTER already records it changing which
> `vitest` config resolves and which copy of a script runs; this is the same
> trap reaching the production deploy, and only a guard written for another
> purpose stood between it and a re-pointed ingress bind.
