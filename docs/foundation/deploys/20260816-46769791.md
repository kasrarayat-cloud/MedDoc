substantive declaration at `docs/foundation/deploys/20260816-6e6edf73.md` —
before the act, tracked, with every number fixed while it was still true. That

`deploy-prod.sh` derives its declaration path from
`git rev-parse --short HEAD` of the tree it runs in. `main` moved from
`6e6edf73` to `46769791` when the F5-a **citation** PR (#691) merged, so the
committed declaration no longer matches the filename the gate demands.

⚠️ **THIS IS A STRUCTURAL PROBLEM, NOT A ONE-OFF, AND IT IS FILED AS F10.**
Whenever a citation or docs PR lands between a feature merge and its deploy —
which is the programme's normal cadence — a pre-committed declaration can never
match HEAD, because the commit that would carry it *is itself* what moves HEAD.
The deploy gate is deliberately `present` rather than `strict` for exactly this
reason (runbook §2.5 / ruling #96(b)); this file is written under that
allowance, uncommitted at deploy time, and **committed immediately afterwards
with the judgement.** Said plainly rather than implied: **the "committed before
the act" property belongs to `20260816-6e6edf73.md`, and to this file only by
inheritance.**
