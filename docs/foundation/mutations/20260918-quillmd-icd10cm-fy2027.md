# Declared delta: import ICD-10-CM FY2027 beside FY2026-April — 2026-09-18

CDC publishes ICD-10-CM per federal fiscal year. Its release page states that **FY27 codes apply to healthcare services
provided from 1 October 2026 through 30 September 2027**, and that the release *"replaces the FY26, April 1, 2026,
release"* — prospectively. September services keep FY2026-April.

This act imports the FY2027 codes as a **new** release. It does not replace, rewrite, retire or delete the existing
one. It runs after the date-of-service activation
(`docs/foundation/mutations/20260918-quillmd-service-date.md`), so the application already selects a release by the
encounter's date of service rather than by today's date.

## The command

    cd /opt/meddoc-pro && bash scripts/run-ruled-mutation.sh \
      --declaration docs/foundation/mutations/20260918-quillmd-icd10cm-fy2027.md -- \
      rebuild/.venv/bin/python rebuild/manage.py import_terminology \
        --system ICD-10-CM \
        --path rebuild/.runtime/terminology/icd10cm-codes-2027.txt \
        --sha256 3c0583a38ee0e848f7dc0ac8ce88e8f001bbba8c6385ed825d44d46f6e5297c9 \
        --release-version FY2027 \
        --effective-from 2026-10-01 --effective-until 2027-09-30 \
        --expected-count 74879 \
        --source-url https://ftp.cdc.gov/pub/Health_Statistics/NCHS/Publications/ICD10CM/2027/icd10cm-code-descriptions-2027.zip

The importer independently refuses: a non-CDC/CMS provenance host, a URL carrying credentials or a query, a checksum
mismatch, a declared count that differs from the file, fewer than 70,000 codes (an addendum or subset), an order file
or addendum format, invalid UTF-8, a duplicate code, an oversized description, an effective period overlapping an
existing release of the same system, and any database whose name does not begin with `quillmd_`.

The new release must read exactly: system `ICD-10-CM`, version `FY2027`, `effective_from` `2026-10-01`,
`effective_until` `2027-09-30`, `license_reference` empty, `sha256` the text hash above.

⚠️ **The clinical counts are declared even though this act has no reason to touch them.** A terminology import that
moves an encounter, patient or suggestion count has done something nobody asked for.

**Boundary check, after the act.** `2026-09-30` must select `FY2026-April` and `2026-10-01` must select `FY2027`,
read back through `core.coding.applicable_releases` against a throwaway in-memory encounter shape — **no encounter is
created, modified or coded**, and no suggestion row is written.

## What this act must not do

- It must not delete, rewrite or shorten FY2026-April, or change its effective dates. Existing encounters and any
  future suggestion for a service date on or before 2026-09-30 depend on it.
- It must not enable CPT. `CPT_LICENSE_ID` is unset, `CPT_LICENSE_EXPIRY` is unset, and no CPT release exists or is
  created. CPT stays disabled pending licensing.
- It must not contact any provider, or read or write any clinical content.

**Reversibility.** `Code.release` is `PROTECT`, so the new release cannot be deleted while its codes exist; removing
this import means deleting 74,879 code rows and then the release row, which is why it is declared rather than simply
run. Nothing existing is altered, so the act is additive: the rollback is a deletion of exactly what it created,
identified by `release_id`.
