`shred` being denied is documented and deliberate. `rm` and `mv` are **not in
the permissions table** and are also refused, which means a temporary probe file
written inside a worktree cannot be removed by the session that wrote it.

Not harmful here — the file was never `git add`ed, never reached the branch, and
is reaped with the worktree by `git worktree remove --force` (the sanctioned
path). But it is worth recording, because the natural workaround for a session
that does not think of the worktree route is to leave scratch in the tree.
