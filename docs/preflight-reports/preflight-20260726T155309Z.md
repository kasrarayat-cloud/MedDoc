## Deviation from the skill's auto-fix, and why

The matrix calls for `docker image prune -af --filter "until=168h"` when images
reclaimable > 5 GB. **That was not run.** `-a` deletes every image not currently
referenced by a container — which is precisely what a rollback tag is. It would
have destroyed `pre-surgery-20260725`, `pre-formonly-20260724`,
`pre-pdfnative-20260723` and ~20 others: the images we would need if a promotion
had to be undone. The `until=168h` filter does not save them; it only spares the
newest week.

Dangling-only pruning freed 26 GB and reached the same place with nothing lost.
**36 `:pre-*` rollback images verified present afterwards.**

Suggested skill amendment: replace the blanket `-af` with dangling-only plus an
explicit `--filter "label!=rollback"`-style exclusion, or tag rollback images
into a repository the prune filter skips.
