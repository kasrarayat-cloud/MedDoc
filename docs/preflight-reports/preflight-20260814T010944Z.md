Check 2's `Images reclaimable > 5 GB` trigger was met (65.32GB) and the
prescribed fix is `docker image prune -af --filter "until=168h"`.

**It was not run, and it must not be run on this host without a named
exception.** `docker image prune -a` removes every image not referenced by a
running container — **including tagged rollback images**. This host carries the
`DEPLOYMENT_RUNBOOK.md` §3 rollback tag table as docker tags, and 20+ of them

    :pre-emrehome-20260728 / :pre-rounds-20260802 class

delete the rollback path for that deploy. The trigger exists to relieve disk
pressure; **there is none** — disk is 66%, a full 14 points below the yellow
band. Reclaimable is not the same as safe to reclaim.

**Follow-up filed (not tonight):** the skill's Check 2 auto-fix needs a
`--filter "label!=rollback"`-shaped exclusion, or the rollback tags need to move
to a registry that a local prune cannot reach. Priced by the asset behind the
symptom: the asset is *the ability to roll production back*, not disk space.
