## Deviation from the skill's Check-2 auto-fix (deliberate)

The skill's trigger "Images reclaimable > 5 GB → `docker image prune -af --filter until=168h`"
fired (92.14 GB reclaimable, 88%). **It was NOT run as written.**

`docker image prune -a` removes every image not referenced by a *running container* —
including **tagged** ones. The 92 GB of "reclaimable" images here is almost entirely the
deliberate rollback-tag history (`meddoc-pro-transcribe-md{,-worker}:pre-*`). The
`until=168h` filter would have preserved only the last 7 days and **deleted every rollback
tag older than 2026-07-20** — `pre-ultrasound-20260617`, `pre-skin-beta-20260615`, and the
rest of the recorded rollback line.

Destroying rollback images immediately before a production deploy is the opposite of what
this check exists to protect. The safe subset (dangling/untagged only) was run instead and
freed nothing, because nothing is actually free. Disk is passing on its own merits (79%,
61 G available — ample for the two image builds this task needs), so no further reclaim is
warranted.

**Follow-up for the skill owner:** Check 2's image-prune trigger should exclude
`pre-*` tags (e.g. prune dangling only, or add an explicit tag-preserve filter) rather than
relying on a 168h window that silently expires rollback history. Not fixed here — this
preflight does not edit skills.
