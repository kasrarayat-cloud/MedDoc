## What ACTUALLY constrains the run

A single Batch D subagent will hit `tsc --noEmit` repeatedly. On this Next.js project, tsc peaks ~600-800 MB. With 507 MB available + 2.7 GB swap free:

- **Will it OOM?** No — kernel will swap pages out to satisfy tsc's allocation.
- **Will it be slow?** Yes — swap thrashing on each tsc cycle could 2-5× wall-clock.
- **Will it fail?** Unlikely — node's V8 is tolerant of swap-backed memory; failure mode is "slow" not "crash".

So the literal question is: **fast outage vs slow no-outage**.
