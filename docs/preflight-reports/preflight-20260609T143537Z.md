    Disk is healthy (47%, 152G free) so there is zero disk pressure forcing it, and pruning the
    >72h-old cache now would discard the npm-install / base layers the OOM-sensitive `next build`
    can reuse — keeping them lowers memory + wall-clock for the rebuild. Builder-cache prune is the
    *only* prune the deploy recipe sanctions; it runs AFTER a verified build.

    explicitly prohibits `image prune -a`. Disk is healthy, so no safety need overrides the prohibition.
