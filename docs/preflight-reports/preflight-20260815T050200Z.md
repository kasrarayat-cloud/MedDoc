## ⚠️ CHECK 5 — THE ZERO WAS BLINDNESS, AND THE POSITIVE CONTROL IS WHAT SAID SO

The first read of this check looked like a clean pass: grepping `journalctl -k`
for `out of memory|killed process` produced **no output**. That is exactly the
shape the canon warns about — *a check run to prove nothing happened is the one
most likely to be believed without scrutiny.*

Controlled:

    journalctl -k --since "24 hours ago" | wc -l   ->  4
    journalctl -k                        | wc -l   ->  4     <- same number, whole history

Four lines for *all kernel history* is not a quiet box. Reading them:

    Hint: You are currently not seeing messages from other users and the system.
          Users in groups 'adm', 'systemd-journal' can see all messages.
    -- No entries --

So the instrument returns zero for **every** needle. It cannot distinguish "no
OOM kills" from "no access to the journal", and neither could this report if the
control had been skipped. **Recorded as cannot-tell.** An unrunnable check is
`2`, never a pass.

Mitigating evidence, stated as what it is — weaker than the check it replaces:
all nine containers report `Up 7 days` / `Up 3 hours` / `Up About an hour` with
no restart churn, and 20.8 GB of 32 GB is free. A recent OOM kill of a container
would normally show as a restart. That is an inference, not a measurement.
