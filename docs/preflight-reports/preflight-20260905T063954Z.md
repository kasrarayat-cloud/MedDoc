## Why no auto-fix ran

- **Images 57.26 GB reclaimable does NOT trigger `docker image prune -a`** —
  ruling #137 forbids it in any form, because it deletes unused TAGGED images
  and this host holds **191 `pre-<sha>-<date>` rollback tags**, the documented
  and unrebuildable rollback path for every past deploy. The sanctioned

## ⚠️ THE FINDING THIS RUN EXISTS TO SURFACE: SWAP IS FULL

**4091 of 4095 MB used. 4 MB free.**

RAM is not short — 22.3 GB available — so nothing is starving *now*. What this
says is that memory pressure ALREADY happened and the pages never came back.
It is the direct, measured explanation for the behaviour the owner named:
**background pollers being reaped with four sessions on the box.** Three of
this session's own watchers were killed mid-watch, and each looked like an
unexplained harness quirk at the time.

> **A FULL SWAP IS NOT A CAPACITY PROBLEM, IT IS AN EVIDENCE PROBLEM.** It does
> not stop work; it silently changes which of your processes survive. A killed
> poller reads exactly like a finished one to whoever is watching the
> notification, and that is how a watcher stops being a control.
