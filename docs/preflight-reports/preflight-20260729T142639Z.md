## Deliberate deviation — the image prune was NOT run

Check 2's trigger (images reclaimable > 5 GB) fired at 116.6 GB. The prescribed
auto-fix is `docker image prune -af --filter "until=168h"`. It was **not** run,
for two reasons:

1. **`-a` removes unused *tagged* images, not just dangling ones, and this box is
   multi-tenant.** 30+ `voiceassistmain-agent:git-*` images belong to a co-tenant.
   Pruning another tenant's rollback history is outside this task's authority, and
   the skill itself puts non-meddoc containers out of scope.
2. **Disk is green.** 70% used with 86 G free is comfortably inside the pass band,
   so the prune buys nothing this run — and the run's whole purpose is a reboot
   proof, which should observe the box as it actually is, not as freshly-swept.

QuillMD's own rollback tags would have survived the 168 h filter (the oldest,
`:pre-verifierfix-20260727`, is 3 days old), so no QuillMD capability was at risk
either way. 11 dangling images exist; they were left alone for the same
minimal-change reason.

**Recommendation for the user, not an action taken:** if disk pressure ever
matters, prune with an explicit repository filter — `docker image prune -af
--filter "until=168h" --filter "label=..."` or an explicit `docker rmi` list —
never a bare `-af` on a shared host.
