- **A NEW L3 FIELD CARRIES A `.default()`, OR IT BREAKS THREE THINGS AT ONCE** — `ExtractedEntities` is one Zod object and a field declared without a default becomes a **required key**, breaking three unrelated things in the same instant: **every mocked run** (the MOCK_AI fixture returns only `{chief_complaint, hpi}` and relies on the rest defaulting, so every QA/E2E run `SCHEMA_FAIL`s), **module load** (`sample-preview-transcript.ts` calls `.parse()` AT MODULE LOAD, so the import itself throws and presents as an unrelated file being unimportable), and **every resumed job** (`worker.ts` resumes with `entities as ExtractedEntities` — a **CAST, not a parse**). ⚠️ **The third is the dangerous one:** the first two fail loudly and now, the cast fails **silently and later**, on jobs already in flight, with the type system asserting the absent key is present. The same reasoning reaches the hand-mirrored `EncounterEntitySnapshot`, whose new members must be `?:` for the identical reason. → `docs/canon/133-a-new-l3-field-carries-a-default.md`
- **A FIELD KIND AND A CONCEPT ARE INDEPENDENT AXES** — a ruling specifying `total_time_minutes` as *“an L3 field, number”* looks to contradict the controls it must fill, which compile `narrative_text` / `expectedDataType: 'text'`. It does not: **`expectedDataTypeForFieldKind` is a pure switch over the COMPILER's field kind and never looks at the concept**, so the concept says what a field MEANS and the kind says what SHAPE the control is. A number-valued L3 fact projected as a string fills a narrative control perfectly. ⚠️ **The trap is the other direction and it is real** — on the same form `Age` compiles `kind: number`, and the resolver's number arm **refuses any value carrying a unit**, so `"61-year-old"` fails `number_contains_unapproved_unit` and only a bare `61` resolves: **the kind constrains the VALUE, not the meaning.** When a ruling calls a concept “a number”, ask which axis it means — reading it as the control's `expectedDataType` sends you hunting a conflict that is not there, or changing a compiled kind to remove one. → `docs/canon/134-a-field-kind-and-a-concept-are-independent-axes.md`
