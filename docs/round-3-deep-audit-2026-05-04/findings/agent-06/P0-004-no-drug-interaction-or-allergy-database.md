## Issue

Layer 7c (Rx drafting) generates prescriptions and emits structured
`warnings[]` objects. The system prompt (lines 82-101) instructs the
model to flag:

- Allergy matches → CRITICAL severity
- Out-of-range dosing → CRITICAL
- Contraindication with documented condition → CRITICAL
- Drug-drug interaction with current med list → MAJOR
- Duplicate-therapy → MAJOR

**Every one of these is generated by Claude alone.** There is no
RxNorm lookup, no FDB / First Databank, no Lexicomp, no Drugbank, no
NIH RxNav, no pediatric mg/kg calculator, no QT-prolongation matrix.
The "warnings" rendered to the doctor in the right rail
(`rx-warnings-rail.tsx`) are pure model output.

## Evidence

1. `grep -rn "interaction\|drug.*db\|interaction.*check\|RxNorm\|lexicomp\|drugbank" apps/transcribe-md packages/` returns nothing
   relevant — no external DB integration anywhere.

2. `07c-rx-drafting.ts:135-141` — the user prompt feeds entities (which
   contain the patient's reported medications + allergies, also
   model-extracted) and the SOAP. That's the entire input. The prompt
   asks Claude to identify interactions "with the patient's current
   medication list" — but Claude is not deterministic on
   interaction lookups. Three failure modes are routine:

   - **Missed interaction**: Claude knows about warfarin + metronidazole
     (textbook). Less famous interactions (e.g. SSRIs + tramadol →
     serotonin syndrome) it may miss in a 1-shot call when the
     transcript only mentions "patient on Zoloft" three minutes
     before the doctor says "ok let's add tramadol for pain".
   - **Hallucinated interaction**: Claude can confidently flag a
     non-existent interaction, scaring the doctor into deviating
     from a correct prescription.
   - **Allergy match miss**: if the entity-extraction layer (L3)
     normalized "amoxicillin" → "penicillin family allergy" but the
     new Rx is "augmentin", the cross-class match depends on Claude
     knowing the family relationship. No deterministic backup.

3. **Pediatric dosing (mg/kg) is entirely model-trusted.** The
   pediatrics specialty guidance asks the model to "use age-appropriate
   language" and to "document growth parameters" — neither of which
   is dose calculation. There is no `if (specialty === 'pediatrics')
   { check_mg_per_kg(rx, weight) }` anywhere in the pipeline. A 3-year-
   old's weight isn't even a required field in the visit creation flow.

4. **No QT-prolongation check** for the high-risk co-Rx patterns
   (azithromycin + ondansetron + SSRI is on the dashboard medication
   keyterms list — the pipeline transcribes the words, then trusts
   the model to know the QT cumulative-risk math).

5. **Rx warning override audit** (`rx-warning-audit.ts`) records when
   a doctor overrides a critical warning to sign — but this is a
   compliance log on top of model-generated warnings. It does not
   add a deterministic check.

6. **The warning rail UI** (`rx-warnings-rail.tsx`) has UI for
   `critical | serious | moderate | info` — but the supply of warnings
   is L7c output. Empty warnings array → "No interaction warnings"
   text (line 98) — and the doctor sees "no warnings" even when the
   model just missed one.

## Risk

P0 because:

- A single missed allergy → adverse drug reaction is a Joint
  Commission sentinel event.
- A pediatric dosing error (10x dose) is a top-3 cause of
  inpatient pediatric harm in the literature.
- A QT-prolongation co-Rx in a patient with baseline long-QT is a
  routine cause of preventable cardiac arrest.
- Pre-pilot positioning ("our AI checks interactions") would be
  inaccurate in any marketing/compliance description; HHS/OIG and
  state pharmacy boards may review marketing claims if a harm event
  occurs.

The smoke test cannot exercise this — it would require a fixture
visit with a known interaction pair and a deterministic check that
the warning fires. None exists.

## Recommended Fix (plan only)

The right answer is hard (license a clinical DB; integrate
First Databank or NIH RxNav; build a maintenance pipeline). The
**minimum viable safety floor** before pilot is:

1. **NIH RxNav (free, public)** for interaction lookup. POST a list
   of RxCUIs (resolved from drug name → RxNorm), receive a list of
   interactions. The RxNav SDK is a 50-line Node module. After L7c,
   call RxNav with `[...current_meds, ...new_rx_drugs]`, merge the
   structured interactions into `warnings[]` with `severity: 'major'`
   and a `source: 'rxnav'` tag. **Hallucinated** model warnings get
   filtered out; **missed** real warnings get added.

2. **Hard allergy regex match.** For each `prescriptions[i].drug`,
   normalize to RxNorm class, check against
   `entities.allergies[].substance` normalized to class. A
   normalized class match at all → CRITICAL warning, no model
   judgment.

3. **Pediatric mg/kg validator** for `specialty === 'pediatrics'`:
   require visit weight, look up max-mg/kg from a small static
   table (top-50 peds drugs), enforce.

4. **Code-side dose range check** for the top-100 outpatient drugs:
   one static `{drug, min_mg, max_mg, max_per_24h}` table, run
   after L7c, emit CRITICAL warning on out-of-range.

5. Add a hard-stop bit on prescriptions.json: if `warnings[]`
   contains any `source: 'rxnav'` or `source: 'allergy_class_match'`
   entry of severity CRITICAL, set `visit.signBlocked = true` until
   the doctor uses the override flow.

This finding pairs with P0-002 (codes) and P0-001 (empty audio):
the pattern is "model is the only line of defense for clinical
correctness". For pre-pilot positioning, that pattern needs at
least one deterministic backstop on each axis.
