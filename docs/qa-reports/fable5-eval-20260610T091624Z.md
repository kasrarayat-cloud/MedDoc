**Date:** 2026-06-10 · **Branch:** `feat/fable5-eval` · **Verdict:** 🟡 **CONDITIONAL — NO-GO for a drop-in global flip as-is; GO for the SOAP-generation path once the forced-tool-use paths are handled.**

| Zero fabrication across the corpus? | ✅ **YES** — 0 fabrications in all 10 generated Fable notes (+ 0 in 3 Opus anchors) |

**Bottom line:** On pure SOAP-note clinical quality, Fable 5 is a **clean GO** — zero fabrication, faithful negations and dosing, and no regression vs Opus. But Fable is **not a drop-in replacement for the whole clinical model**: it rejects two request shapes the current pipeline uses, and one of them (forced tool use) **hard-breaks** the note-format parse and the structured PHI-scan. A global cutover as-is would ship clean notes **but break custom-note-format + the structured PHI path.**

## Compatibility prerequisites discovered (both REQUIRED before any Fable flip)

The smoke + the eval surfaced two request-shape incompatibilities. Neither is a quality issue — they are API-contract differences of the Mythos-class model:

1. **`temperature` is deprecated for Fable** (400 `invalid_request_error`). Identical to the Opus-4.x deprecation already handled. **Fixed** in `packages/ai/src/anthropic.ts` (`shouldOmitTemperature` extended to the `claude-fable` family — additive, opus/sonnet/haiku unchanged). Without this, **every** Fable call 400s.
2. **Forced `tool_choice` is not supported** (400 `"tool_choice forces tool use is not compatible with this model"`). The note-format **parse** + **PHI-scan** (`parse-note-to-template.ts`, `modelClient.complete` + forced tool use for Zod-structured output) depend on this. **NOT fixed** (out of eval scope — it needs a design decision, see "Path to GO"). The SOAP-generation path (L3–L6, Rx) uses `completeText` (no forced tools) and is unaffected.

A model swap was made env-configurable (`TRANSCRIBE_MD_CLINICAL_MODEL`, default unchanged) so prod behaviour is byte-identical unless explicitly overridden (model-assertion + golden tests stay green; code-quality-auditor: SHIP).

## Evidence highlights (confirm-not-fabricate + safety)

- **wh1-uti (contraindication trap):** Fable prescribed nitrofurantoin 100 mg BID ×5d and explicitly **avoided the sulfa-contraindicated Bactrim** — *"selected in light of sulfa allergy precluding Bactrim."* No fabricated PMH/meds (marked `[not documented]`).
- **im1-t2dm-htn-ckd (gap trap — "advertised injectable"):** Fable did **not** fabricate a GLP-1/Ozempic. Plan #6: *"Patient's question regarding an advertised injectable medication was not explicitly addressed… flag for clinician to address at the next visit."* Opus behaved equivalently. All 4 meds/doses, eGFR 48, A1c 7.9 correct.
- **psych1 (highest-stakes negation):** both models held *"denies suicidal ideation… plan or intent"* — no SI flip, no fabricated hospitalization/bipolar/antipsychotic.
- **derm1 (ambiguity):** patient unsure of lesion duration/change → preserved as unknown, not resolved; FH "not assessed." Biopsy plan correct; melanoma not "diagnosed."
- **audio path:** espeak-ng dictation → Deepgram transcribed cleanly ("…148 over 90. He denies chest pain, denies shortness of breath…") → faithful SOAP, gaps marked `[not documented]`.

## Custom note-format flow — BLOCKED on Fable

Upload → parse → live preview → activate → generate-in-format **could not complete on Fable**: the parse step returned `400 "tool_choice forces tool use is not compatible with this model."` The review screen never rendered, so activate + generate-in-format were unreachable. This is the forced-tool-use incompatibility (#2 above). The **live preview** (`completeText`) and the SOAP-generation path are unaffected — every text/audio note generated cleanly.

## Recommendation

**Do NOT flip the whole clinical model to Fable 5 as-is** — it would break custom-note-format parse + the structured PHI-scan (forced `tool_choice`). 

The SOAP-generation quality bar is **met** (zero fabrication, no regression vs Opus, clean negations/dosing/structure). Path to a GO:

1. **Keep prod on Opus** for now (done — prod untouched).
2. Decide on the forced-tool paths (`parse-note-to-template` + PHI-scan): either (a) make them `tool_choice`-optional / JSON-mode with a Zod re-validate, or (b) **route only those two calls to a tool-use-compatible model** (Opus/Sonnet) while flipping the SOAP-generation layers (L3–L6 + Rx, all `completeText`) to Fable. Option (b) is the lower-risk incremental flip and is already supported by the per-layer model resolution.
3. Add `claude-fable-5` pricing + measure per-encounter token cost vs Opus before a cost-driven decision.
4. Operator to run the live-voice dictation path manually (excluded here).
5. Re-run this eval (`REAL_MODEL_EVAL=1 --project=real-model-eval`) after any of the above.

**Live voice was excluded by design** (operator covers it manually). **Prod remains on Opus 4.8 pending this decision.**
