The walker doesn't submit the new-visit form (per the v3.2 brief —
would create real visits + invoke the AI pipeline). So the closure
proof is split:

1. **Migration acceptance** (the schema accepts the new enum value):
   ```
   docker exec ... psql -tA -c "SELECT enumlabel FROM pg_enum
   WHERE enumtypid = '\"AuditAction\"'::regtype AND
   enumlabel = 'VISIT_CREATED';"
   → VISIT_CREATED
   ```

2. **End-to-end shape acceptance** (a direct `INSERT INTO audit_logs`
   with `action = 'VISIT_CREATED'::"AuditAction"` succeeds):
   ```
   INSERT 0 1
   qa_f10_verify_1778036842 | VISIT_CREATED
   ```
   Verification row deleted post-test (HIPAA append-only doesn't
   apply to fixture rows the agent writes).

3. **Call-site shape** (5 unit tests in
   `apps/transcribe-md/tests/actions/create-visit-audit.test.ts`):
   - `emits VISIT_CREATED with the right targetType + targetId`
   - `audit metadata carries inputMode + specialty + patientId; no PHI`
   - `audit emits AFTER the visit row is created (not before)`
   - `audit failure does NOT break the create flow (fire-and-forget)`
   - `does NOT emit when input validation rejects`

   All 5 pass.

The natural live-traffic check would surface a `VISIT_CREATED` row
the next time a doctor (or the agent's future submit-flow walker)
creates a visit.
