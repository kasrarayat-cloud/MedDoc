## F-8 (top priority) — root cause: capability gap, NOT a regression

**Reproduction:** 3 phrasing variants (new-start, continue-far-apart, continue-adjacent) through the real pipeline → the amlodipine + simvastatin-40 interaction fired in **0/3**. Warnings emitted were unrelated minors.

**Root cause (two parts):**
1. **The "it fired on 2026-06-14" memory was a mockup.** The remembered warning text ("guideline max is 20 mg/day with amlodipine — myopathy/rhabdomyolysis") is a **hardcoded string literal** in the static design concept `landing-monolith/components/concepts/soap/data.ts:36` (`staging.quillmd.com/concepts/soap` drawer mock, screenshot `c3f-02-drawer-desktop.jpeg`). The real product never produced it. (`c3real-1d-review-critical-rx.jpeg` shows the warfarin×NSAID warning from the MOCK_RX_WARNINGS test fixture — also not organic.)
2. **The product had NO drug-pair capability anywhere.** The deterministic tier (`validateRxDose`) is single-drug-only (four codes; `DoseRangeEntry` has no interaction field — simvastatin's flat cap is 40 mg, so 40 mg is "in range"); the L7c prompt files interactions under **major** (non-gating), and at temp 0.1 the LLM simply missed the pair. A contextual cap ("max 20 mg/day WITH amlodipine") was inexpressible.

**Fix (phrasing-independent by construction):** new deterministic pair floor `checkDrugInteractions` in `@meddoc/ai` (`packages/ai/src/data/drug-interactions.ts`) — 6 curated rules with cited bases:
| Rule | Severity | Basis |
|---|---|---|
| simvastatin >20 mg/day + amlodipine | critical (major if dose unverifiable — caution-first) | FDA simvastatin label 2011 |
| simvastatin >10 mg/day + verapamil/diltiazem | critical (same mechanics) | FDA simvastatin label 2011 |
| warfarin × NSAID (7 members + brands) | critical | warfarin label / classic severe DDI |
| methotrexate × trimethoprim/Bactrim | critical | antifolate additive toxicity |
| ACEi × potassium-raisers | major | hyperkalemia monitoring |
| opioid × benzodiazepine | major | FDA 2016 boxed warning (sometimes intentional) |

Checked against **drafted prescriptions ∪ current-medication list** (entities), brand-name aware, deduped per rule/pair. Wired into the 07c floor as `[deterministic]`-prefixed warnings — **additive only** (auditor-verified 3 ways: append-only, fail-soft entities parse, positional warning ids unshifted). The sig parser now reads once-nightly phrasings (nightly/QHS/bedtime) so "simvastatin 40 mg nightly" yields a verifiable mg/day (additive: previously null = silent skip). The critical-Rx sign gate is byte-identical and consumes the new criticals through the existing per-warning coverage.

**Battery proof (real pipeline, fix-pack images):**

## F-6 — spurious "Click Retry" on every ultrasound visit

**Root cause:** `detectIncompleteAutomation` pass 2 (empty-output watchdog, `automation-incomplete.ts`) treated "column null because the layer was flag-DISABLED" the same as "ran successfully and emitted nothing" — its guard only excluded `'failed'`, not `'skipped'`. E/M is suppressed by design for imaging (`cpt_coding: {status:'skipped'}`, `cptCodes` null) → every ultrasound visit got *"Auto-coding incomplete — cpt-coding: no E&M code emitted (status:ok). Click Retry to reprocess."* — the hard-coded "(status:ok)" text lied, retry was deterministically futile (banner re-stamped every cycle, capped at 5 by the retry budget), and there is not even a Retry button on the READY view.

**Fix:** pass 2 now requires the layer's recorded status to be `'ok'`. SOAP visits byte-identical (their status IS `ok`); DB-blip defense preserved (re-read failure keeps scores `ok` → still trips); the same latent false-flag for `TM_ENABLE_ICD_CPT=false` is fixed. Cannot alter note bytes (auditor-verified: flows only into `needsReview`/`reviewReason` + audit metadata). 2 new canaries (skipped-cpt-imaging, both-skipped) + 27 existing builder tests green.

**Proof:** fresh ultrasound reflux visit → reviewReason contains **no** cpt item / no "Auto-coding incomplete"; `E/M null`; `cpt_coding: skipped`; report structure Exam→Impression intact.

## L6 — verdict: FIX (generation-side), shipped

**Mechanism (evidence-backed):** the "fabrication gate" here is L6b's own `tm_polish_gate` judge (draft vs polished ONLY — deliberately no transcript, no critique channel since iteration 1). Under anchoring: L4b demotes transcript-supported content to the lane → L5 (which sees the full transcript) flags the holes as fixable omissions whose fixes say "Add X" (X ≈ the demoted lane text) → L6 applies them → L6b rejects ANY addition regardless of transcript truth → the ENTIRE polish falls back to draft. All persisted `L6_FABRICATION_REJECTED` audit metadata shows genuine `kinds:["addition"]`, `gateError:null` — the gate did its job; it was being fed unpassable input. This was the **pre-registered known cost** ("polish-survival 1/12 … survival tuning = follow-up", reconciliation 2026-06-11) amplified to ~100% by anchors-on.

**Fix (touches neither gate nor verifier):** `runLayer6Polish` partitions fixable issues before the model call — additive-class (add-verb heuristic + novel-content-terms fallback vs the draft; removal fixes never deferred) are **deferred to the review banner** ("Auto-polish deferred N auditor fixes that would add content not in the draft…"; their content already sits in the adopt-flow lane), only rewording-class fixes reach `tm_polish`. All-deferred → the pre-existing passthrough (no polish/gate calls at all, ~3¢/visit saved). The L6b gate remains the unchanged backstop for anything misclassified. 8 partition canaries + all 38 pre-existing polish tests green.

**Proof:** ultrasound visit's banner now reads "deferred 5 auditor fixes…" instead of the blanket rejection; clean SOAP control: **0 `tm_polish` calls, 0 rejections** (passthrough) vs 17/17 blanket rejections in the previous matrix.
