### 🟡 The single Layer-4 review item — Rx CSS-only structural decision

The Batch D subagent migrated the Rx warning card via **CSS-only overrides** in `globals.css` rather than via the Strategy A `theme` prop pattern that B+C used. The .tsx file (518 LOC) is byte-for-byte unchanged. The migration is achieved through 216 lines of CSS scoped to `.qm-cl-app .qm-warn-*`.

Why this is interesting:
- **Pro:** absolute zero risk to the highest-stakes clinical-trust component. Every class, every ARIA attr, every event handler, every keyboard shortcut, every override-modal flow preserved literally. 28/28 tests still green.
- **Pro:** the .qm-warn-* family was always severity-driven (red/amber/blue rgb triplets), not accent-driven. Color scoping via CSS is the natural tool for "same JSX, different palette".
- **Pro:** the Rx commit message itself is an exhaustive design audit — region-by-region, token-by-token, including the rationale that the violet `--accent-bright` token never appeared in the .qm-warn-* family at all.
- **Caveat:** the Rx card now relies on being mounted inside `.qm-cl-app` to render in Clinician colors. If a future code path mounts it outside (e.g., a Radix portal that doesn't carry the Clinician scope, or a legacy admin view that bypasses AppFrame), the card falls back to the legacy dark style. The visit-detail tree (where it currently renders) is fully covered, so this is a forward-looking caveat, not a current bug. Subagent already addressed the modal-portal case for sign-and-send / edit-draft / archive / delete by wrapping their portal contents in `.qm-cl-app` themselves.
- **Open question for user:** does the CSS-only path satisfy the Phase-2 plan's intent for the Rx card, or does the user want the same Strategy-A `theme` prop shape applied (which would require touching the 518-LOC .tsx)? The subagent's read of the spec ("preserve every semantic class / 518-line structure exactly / preserve every ARIA attr / data-testid") landed on CSS-only as the strictest interpretation. **This is the REVIEWABLE-tagged commit at `1aeeb36`** — surface to user explicitly.
