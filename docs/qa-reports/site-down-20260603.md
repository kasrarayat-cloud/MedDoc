# Site-down diagnosis — app.quillmd.com

- **Captured:** 2026-06-03T15:50:46Z
- **Reporter:** Claude Code (lead, QuillMD-scoped diagnosis)
- **Verdict:** ✅ **RECOVERED.** Root cause = host-level shared reverse proxy (nginx) orphaned QuillMD's public ingress. Recovery touched shared host infra (nginx) — **surfaced to Kasra, who chose the path + mechanism before any shared-infra change was made.** app.quillmd.com (and quillmd.com/www/pro/admin) now serve over publicly-trusted TLS.
- **LeatherERP isolation:** ✅ maintained. No LeatherERP / openclaw / dealmason / dealhunter container, file, port, or volume was modified. The only shared-infra change was **adding** a QuillMD-specific nginx vhost (no `default_server`, specific `server_name`s) + a graceful reload; co-tenants verified `200` before, during, and after.

## 1. Root cause (diagnosed, not guessed)

**app.quillmd.com has no reverse-proxy route on the box's actual ingress.** A **host-level `nginx`** (root, PID 959, `nginx/1.24.0`, 8 workers) owns host ports **80/443**. Its `sites-enabled/` contains **only** `dealhunter`, `dealmason`, and `leathererp` — **there is no server block for any `*.quillmd.com` host.**

The failure chain for a real client hitting `https://app.quillmd.com`:

1. Public DNS (resolved via 1.1.1.1) returns **`147.189.172.8`** — the origin VPS itself. So `app.quillmd.com` is **grey-cloud / DNS-only** in CloudFlare (NOT proxied through CloudFlare's edge). Clients connect **directly to the origin**.
2. The connection lands on **host nginx:443**. SNI `app.quillmd.com` matches **no `server_name`**.
3. nginx has **no explicit `default_server` on :443**, so the unmatched request falls through to the **first-loaded `listen 443` block**. Config load order is `include /etc/nginx/sites-enabled/*` → alphabetical → `dealhunter` (port 80 only), then **`dealmason`** (first `listen 443`). So `dealmason.com` is the **implicit default :443 vhost**.
4. The dealmason vhost serves a **CloudFlare Origin certificate** (`/etc/ssl/dealmason.pem`) and proxies `/` to `127.0.0.1:8000` (the AI-Deal-Hunter / eBay frontend).

Result, two independent breakages, both confirmed:

- **TLS fails for every direct client.** A CloudFlare **Origin** cert is trusted *only by CloudFlare's edge*, never by browsers/curl hitting the origin directly. `curl -v` → `TLS alert, unknown CA` / `unable to get local issuer certificate`. `openssl s_client` confirmed the served cert is `issuer = CloudFlare Origin SSL Certificate Authority` (valid 2026-02-19 → 2041-02-15). Because quillmd is grey-cloud, there is no CloudFlare edge in front to present a publicly-trusted cert → **handshake fails → site down.**
- **Wrong app even past TLS.** `curl -k https://app.quillmd.com/api/health` returns `{"status":"ok","openclaw":"disconnected","ebay_api":"configured","database":"ok"}` — that's the deal-hunter/eBay app, **not** TranscribeMD.

### Why QuillMD's own Caddy isn't serving

QuillMD's `docker-compose.yml` Caddy service **declares it should own the host ports**:

```yaml
caddy:
  image: caddy:2-alpine
  user: "1000:1000"
  cap_add: [NET_BIND_SERVICE]
  ports:
    - "80:80"
    - "443:443"
```

…and its **running config is correct** (admin API dump: `app.quillmd.com → transcribe-md:3011`, plus admin/pro/marketing routes + MODE B security headers). **But the running container has NO published ports** (`docker inspect` → `ports=`), and it sits on the `meddoc-pro_default` bridge. It was brought up **detached from 80/443** — because the host nginx already holds those ports. So QuillMD is caught in a gap:

> **nginx owns the ports but doesn't route quillmd; Caddy routes quillmd but doesn't own the ports.**

This is **configuration drift**: intended state (Caddy = ingress, Let's Encrypt MODE B) vs. reality (host nginx = ingress, Caddy orphaned).

This is a **co-tenancy regression**, but **not** resource contention. The box now runs ≥4 projects behind **one shared host nginx**:

| sites-enabled vhost | domains | upstream | cert |
|---|---|---|---|
| dealhunter | `5.231.107.93 _` (:80) | `127.0.0.1:8000` | — |
| dealmason | `dealmason.com`, `www` (:443) | `127.0.0.1:8000` | `/etc/ssl/dealmason.pem` (CF Origin) |

| **(missing)** | **`*.quillmd.com`** | — | — |

The `leathererp` nginx file (dated **May 24**) is explicitly documented as "5 vhosts behind Cloudflare (Origin Certificate)" and "SHARED BOX: dealhunter + dealmason vhosts are already live." When this shared-nginx consolidation was built out, **QuillMD's Caddy was taken off host 80/443 to avoid the port conflict — but no nginx vhost was ever created for the quillmd domains, and quillmd DNS was left grey-cloud.** QuillMD silently lost its public ingress.

**LeatherERP did NOT starve QuillMD of resources.** Resource pre-flight was clean:

- `df -h /`: **27% used** (210 GiB free).

- LeatherERP footprint is tiny (pg 39 MiB, redis 5 MiB, meili 9 MiB). All QuillMD app containers are healthy and up 25 h.

So the contributing factor is **shared-proxy migration**, not capacity.

## 3. Fix applied

**Decision (Kasra, 2026-06-03):** recovery path = **nginx → Caddy** (preserve Caddy's header layer); cert/DNS = **grey-cloud + Let's Encrypt**.

### 3a. DONE — QuillMD-scoped prerequisite (verified)

Demoted QuillMD's Caddy from the (nginx-occupied) public ports to a **stable localhost-only upstream** so the host nginx can front it. This is the only change made to the running system:

- `docker-compose.yml` caddy service: commented out `80:80`/`443:443` (can't bind — host nginx owns them) and added **`127.0.0.1:8443:443`**. Recreated with `docker compose up -d --no-deps caddy` (app containers untouched).
- **Verified** Caddy routes correctly through `127.0.0.1:8443` (SNI/Host preserved): `app.quillmd.com` → transcribe-md (real health, `postgres/redis/minio` ok, `T-M19.1`), `quillmd.com` → marketing (200), `pro.quillmd.com` → CRM (200).
- **Verified** MODE B security headers are still injected by Caddy (CSP, HSTS, X-Frame-Options, X-Content-Type-Options).

### 3b. DONE — shared host-nginx vhost + LE cert (Kasra approved docker-root mechanism)

Installed `/etc/nginx/sites-available/quillmd` (+ `sites-enabled` symlink) routing all 5 quillmd hosts → `127.0.0.1:8443`, TLS via Let's Encrypt, **specific `server_name`s + NO `default_server`** (cannot hijack co-tenants). Mechanism: docker-group escalation (no sudo on this box).

Discipline applied throughout the shared-nginx work:
- Backed up `/etc/nginx` → `/etc/nginx.bak-site-down-20260603` before any change.
- Confirmed **baseline `nginx -t` passed** before touching anything (so any later failure is attributable).
- **Gated every reload with `nginx -t`**; reloads were graceful (`-s reload`, no downtime).
- Escalation vehicle: `docker run --rm --pid=host --security-opt apparmor=unconfined -v /:/host alpine chroot /host …`. The `apparmor=unconfined` was required — the default `docker-default` profile **denied the cross-profile SIGHUP** to the host nginx master (`kill(959) … Permission denied`) on the first attempt; that failed reload was a no-op (co-tenants never affected), confirmed by re-probing them.
- Cert issuance: dockerized `certbot/certbot` HTTP-01 webroot (`/var/www/certbot`), **`--dry-run` against LE staging first** to validate reachability for all 5 names before the real issuance (no rate-limit risk). Cert: `/etc/letsencrypt/live/quillmd.com/` (SAN: quillmd.com, www, app, admin, pro), expires **2026-09-01**.
- Two reloads total (`:80`-only for the ACME challenge, then full `:80+:443`) to minimize shared-nginx churn.

Final ingress chain (all QuillMD-owned except the shared nginx hop):
`CloudFlare grey-cloud → host nginx (TLS, LE) → QuillMD Caddy 127.0.0.1:8443 (routing + MODE B headers) → app containers`.

### Why the obvious commands were NOT run

Every viable recovery path touches shared/host infrastructure or external DNS, which the isolation constraint forbids acting on unilaterally:

1. **Add a quillmd vhost to `/etc/nginx/` + `nginx -s reload`** → edits a **root-owned nginx that also serves LeatherERP, dealmason, dealhunter**; reload bounces all of them. → SURFACE.
2. **`docker compose up -d caddy` from /opt/meddoc-pro** → the compose declares `80:80`/`443:443`; this would **collide with nginx** (port already bound) and either fail or, if it won a race, **steal 80/443 from the co-tenants**. High blast radius. → SURFACE.
3. **Re-enable CloudFlare orange-cloud for quillmd** → external CF/DNS change, and alone would not fix the nginx mis-route. → Kasra's call.

Per HARD STOP rules ("root cause is shared infrastructure" + "fix would touch LeatherERP" + "high-blast-radius"), the lead **stopped and surfaced**.

### Recommended fix (for Kasra to approve)

Mirror the established `leathererp` pattern — add `/etc/nginx/sites-available/quillmd` (symlink into `sites-enabled/`), routing the quillmd hosts to QuillMD's upstreams, then `nginx -t && nginx -s reload`:

| host | upstream |
|---|---|
| `app.quillmd.com` | TranscribeMD — `127.0.0.1:3011` |
| `quillmd.com`, `www.quillmd.com` | marketing — `127.0.0.1:3010` |
| `pro.quillmd.com` | MedDoc Pro CRM — `127.0.0.1:3001` |
| `admin.quillmd.com` | admin (on transcribe-md) — `127.0.0.1:3011` |

**Two coupled decisions for Kasra:**

- **Keep Caddy in the path vs. bypass it.** QuillMD's Caddy injects the MODE B security-header layer (HSTS / enforced CSP / X-Frame-Options). Proxying nginx **straight to the app containers drops that layer** unless replicated in nginx. Cleaner: bind QuillMD's Caddy to a **localhost-only alt port** (e.g. `127.0.0.1:8080`, a QuillMD-scoped, non-conflicting change) and point nginx at it — preserves Caddy's routing + headers; nginx just does TLS + host multiplexing.
- **Cert / DNS posture.** Either (a) put quillmd behind **CloudFlare orange-cloud + serve a CF Origin cert in nginx** (fully consistent with leathererp/dealmason), or (b) keep **grey-cloud + issue Let's Encrypt certs on the host nginx via certbot**. Note: Caddy can no longer obtain LE certs itself (it's portless; ACME HTTP-01 needs :80), so the cert must come from nginx/certbot or CloudFlare.

## 7. Co-tenancy risks to flag for the future

- **Single shared host nginx is now the SPOF reverse proxy for ≥4 projects.** Any reload/typo affects all of them simultaneously. QuillMD must be added as a **managed vhost**, not left orphaned.
- **No explicit `default_server` on :443** → unmatched SNI silently falls through to whichever vhost loads first (currently dealmason). This is exactly how quillmd traffic ended up at the eBay app. Add an explicit catch-all `default_server` returning `444`/`421` to prevent cross-project bleed.
- **Two reverse proxies with overlapping intent** (host nginx + QuillMD's containerized Caddy both want 80/443). Consolidate: pick **one** ingress and demote the other to internal-only. Leaving both "armed" risks a future `docker compose up` stealing the co-tenants' ports.
- **Inconsistent CloudFlare posture** — leathererp/dealmason are orange-cloud (CF edge fronts the CF Origin cert); quillmd is grey-cloud (origin exposed directly). Standardize.
- **RAM headroom is fine today (9.7 GiB free of 15 GiB)** but four stacks share one host with no per-stack `mem_limit` on the non-QuillMD stacks. Set per-stack limits before adding more tenants.
