## 1. Verdict

Sixteen of nineteen failures are harness drift, two are specs that should be retired, and **one is a real product defect**. Every DEFECT/RETIRE claim was put to three independent skeptics and all three claims survived 3/3 — nothing was overturned. The defect is a capability loss, not a data or gate failure: signed visits can no longer be archived. One correction to the framing of the whole exercise: **the defect did not ship on 2026-08-02 with the flag flip** — it shipped on 2026-08-03 with the R2 deploy (`e1375027`, `docs/rounds/RELAY.md:394`), and the two RETIREs are older still, dating from the C3 promotion (2026-06-15) and the read-only-paper work (2026-07-28). Rounds did not break these; the flag-ON run is simply the first run that ever looked. Also worth saying plainly: **the known `/dashboard` → `/board` 307 (`src/config/rounds-redirects.ts:46`) explains zero of the nineteen directly.** Six failures are the same *family* — the home surface was renamed — but every one of them reaches `/board` through a server-computed destination (`src/lib/recovery-href.ts:30-32`) or an in-content link, never through the config redirect. The redirect is what killed the nightly `product-separation.spec.ts`; it is not what killed these.

## 2. Headline — one thing shipped broken

**A doctor cannot archive a signed note.** Under the shipped flags, `/visits/[id]` for a SIGNED visit renders `<RoundsSigned>` (`src/app/visits/[id]/visit-ready-view.tsx:1203 → :1262 → :1265`), and `RoundsSignedProps` (`src/components/rounds/signed.tsx:39-60`) has no actions slot — `rg -n "visitActions" src/` returns 9 hits and none is in `signed.tsx`. The `visitActions` node is consumed at exactly one place, `visit-ready-view.tsx:1127`, inside `if (isReviewDocView() && !isSigned)` (`:848`). The control is not hidden; it is not in the DOM.

Concretely: opening any of production's **16 signed visits** shows the signed paper and the safety trail with no "Visit actions" disclosure and no Archive control anywhere — and there is none on `/board`, `/visits` or the patient page either (`src/app/board/page.tsx:90` filters `archivedAt: null` with no status filter, so signed notes stay on the doctor's landing screen). The only UI caller of the endpoint is `src/app/visits/[id]/visit-lifecycle-actions.tsx:287`; the only other "Archive" affordance in the app is the lucide icon on `src/app/dashboard/show-archived-toggle.tsx:58`, on a route that 307s to `/board`. HIPAA retention forbids deleting a signed note, so archiving is the only disposal available and it is now unreachable. Read-only prod counts: `16 | 0 | 26` (signed | archived | total).

Cause is the R3.4 "coverage assumed" shape AGENTS.md already records. `git show e1375027 -- .../page.tsx` deleted `{roundsChrome && (<details data-testid="rounds-visit-overflow">{lifecycleActions}</details>)}`, which sat outside `VisitBody` and was gated on `roundsChrome` **alone, with no status condition** — so it rendered for SIGNED — and moved it into `RoundsStage`, which signed visits never mount. The comment R2 left behind names the exact controls it thought it preserved: *"A destructive control (archive, delete) … Same node, same actions, same `data-testid` — only the position moved"* (`src/app/visits/[id]/page.tsx:531-541`). True for unsigned visits, false for signed ones. Nothing is corrupted, no gate is weakened, and the failure is silent — no error, just an absent control.

Second-order, currently hypothetical: because archive requires SIGNED, every archived visit is a signed visit, so `ArchivedBanner`'s Unarchive (`visit-lifecycle-actions.tsx:160-181, 236-273`) is stranded too. With 0 archived rows today, nobody is stuck.

## 5. What would make these fixes wrong

The drift fixes are cheap, and that is exactly the risk: a re-point that resolves is not a re-point that proves anything.

- **`/dashboard` → `HOME_URL_RE` is a vacuity trap in one specific place.** `15-auth-mfa.spec.ts:62` asserts `not.toHaveURL(/dashboard/)` to prove a password-only login is refused. Flag-ON, a login that *wrongly succeeded* lands on `/board` and satisfies "not /dashboard". The spec's stated high-severity auth guard is already green and already vacuous. Fixing only `:68` and leaving `:62` ships a passing test that cannot fail.
- **Never re-point a sign control at a bare `/sign/i` name.** Under Rounds there are two dialogs open at once — `gate-flow.tsx:228` carries `role="dialog"` and so does the Radix modal — so `getByRole('dialog')` goes strict-mode-ambiguous, and #1's `:71` "dialog hidden" assertion would pass against the wrong node. Scope to `getByTestId('review-doc-signbar')` and `getByTestId('rounds-gate-attest')`.
- **#12/#13 cannot be re-pointed as-is.** The spec's own non-vacuity guard at `:60-65` asserts `sign-attestation` is present; under Rounds the gate collects attestation upstream and the modal correctly drops its copy (`sign-and-send-modal.tsx:148`, `helpers/sign.ts:27-30`), so `count === 0` is *right*. A naive re-point trips the guard; a fixer who then deletes the guard has removed the thing that stops the test being meaningless. And the Gate-3 overlay is `position: fixed; overflow-y: auto` (`rounds-tokens.css:1071-1084`), so a raw `y + height <= vh` assertion is now the wrong measurement — the invariant to assert is *reachability*, not on-screen geometry.
- **#6's scoping matters more than it looks.** The current failure is a strict-mode violation, not a product miss, and the assertion has been **vacuously green flag-OFF for weeks** — the one-shot check resolved against the note-format privacy blurb `<b>the note itself is never saved</b>` before the profile span ever existed. Scoping to `#profile` with `{ exact: true }` is what makes it observe the thing it names for the first time.
- **#15 must not simply drop the `#main` scope.** That scope was deliberate (comment at `:39-43`) to avoid hitting nav chrome. Removing it and matching a name regex will hit the top bar — which is fine only if the assertion is *about* the top bar. Say so, or the next reader assumes the breadcrumb still exists.
- **#2: open the disclosure, do not force `open` via CSS or JS.** The collapsed state is the product decision (`stage.tsx:137-142` — "one deliberate click away instead of one stray one"). A test that bypasses it stops guarding that decision.
- **#16/#17: prefer the testid, not the visible string.** `rounds-patients-search` exists; the patient-summary line at `patients/[id]/page.tsx:455-457` does **not** have one, so a text regex is currently the only handle — add the testid before writing the assertion, or the next copy edit re-reds it.
- **Structural, and the one that will bite twice:** five specs each hand-roll the sign walk. Fixing them five times recreates the hand-kept-list failure AGENTS.md already records. One `openSignFlow(page)` helper, with a regex over both labels so a flag-OFF rollback build is not a false red — the shape `helpers/home.ts:30` already uses for `/board` vs `/dashboard`.
