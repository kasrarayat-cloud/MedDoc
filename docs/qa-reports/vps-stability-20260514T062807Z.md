## 6 — Preventive fix applied

**Disk cleanup:** done above. The build cache was the proximate driver of disk creep — it grew ~13% (57 G → 76.9 G during prior session) and would have hit 90% (block threshold) within 1–2 more heavy build cycles.

**SSH keepalive fix:** **NOT yet applied** — requires `sudo` to edit `/etc/ssh/sshd_config` and reload `sshd`. Surfacing to Kasra. Recommended block to add (or uncomment + change):

```
# /etc/ssh/sshd_config
ClientAliveInterval 60
ClientAliveCountMax 5
TCPKeepAlive yes
```

Then `sudo systemctl reload ssh`. Existing sessions inherit the new policy on next reconnect.

**Alternative (client-side, works for Kasra without VPS root):** add to `~/.ssh/config` on his laptop:

```
Host 147.189.172.8 vps quillmd-vps   # or whichever alias he uses
  ServerAliveInterval 60
  ServerAliveCountMax 5
  TCPKeepAlive yes
```

Client-side keepalives are sufficient — the client will probe the server, keeping the flow alive across NAT/router idle timeouts. This is the **lowest-risk fix** since it requires no root on the VPS.

**Memory pressure (secondary):** No immediate action. Current available RAM is 8.7 GB and load is 0.4. If swap rises again under future build pressure, drop worker concurrency `CONCURRENCY=2 → 1` temporarily, but no need now.
