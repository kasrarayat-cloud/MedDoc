# CPT licensing handoff for QuillMD

Prepared 15 October 2026. No executed CPT agreement, licensed catalogue or licensed selection criteria have been supplied to this implementation. The retained coding result reports CPT unavailable because its protected entitlement manifest is missing. This handoff is not a license, application submission or purchase; ICD-10-CM acceptance does not establish CPT readiness.

QuillMD is a clinician-facing web application for US outpatient/office coding assistance. It extracts concepts from saved documentation, retrieves dated authoritative candidates, asks the configured AI provider to resolve those candidates, validates the selection locally and requires clinician approval. Coding records remain separate from finalized clinical documents and original Word exports. The workflow submits no claims. Current live acceptance uses authorized synthetic cases; broader deployment requires its own stated scope.

AMA's FAQ requires a license appropriate to the product/use and distinguishes internal-use from distributor arrangements. A codebook purchase does not grant electronic-product rights. AI retrieval requires the applicable agreement/addendum and product approvals; training/fine-tuning and uploading the data file into public or unrestricted AI systems are prohibited. Output distribution depends on the agreement, which controls over the FAQ. Reviewed 15 October 2026; FAQ updated 14 July 2026. [AMA licensing and AI FAQ](https://www.ama-assn.org/practice-management/cpt/cpt-licensing-frequently-asked-questions-faqs).

The owner should supply the contracting entity, contact, territories, hosting/subprocessors, intended organizations and counted users, and internal-use versus customer distribution. Request written coverage and a quote for:

- **Product/users:** QuillMD and all authorized users, including development, testing, deployment and maintenance; confirm user counting, royalties and notices.
- **Display/distribution:** official codes, descriptors, instructions, reviewed suggestions and retained coding records. The existing gate also requires `clinical_export` rights; that request does not imply the current workflow alters the original export. Specify permitted recipients.
- **AI inference:** local retrieval and sending selected codes, descriptors, instructions and supporting documentation to a named contracted provider. The accepted provider is Anthropic. Request explicit provider-processing/retrieval permission, permitted retention and geography; an API account establishes none of these rights. No training, fine-tuning or model improvement is requested or authorized by the application.
- **Storage:** licensed search/rule structures, selected outputs, exact request/response audit evidence and protected backups. Confirm retention, termination/deletion terms and permission to transform supplied criteria into the application's rule schema.

Use the official [licensing application](https://compliance.ama-assn.org/hc/en-us/requests/new?tf_7275193547287=new_dist&ticket_form_id=7268856900759) or [licensing support](https://compliance.ama-assn.org/hc/en-us/requests/new?ticket_form_id=28108580935319). Neither was submitted during this work.

Request a dated electronic catalogue **and authoritative selection criteria**, including updates/errata and needed historical service-date coverage. AMA lists data files and additional coding guidance as distinct offerings. [AMA coding resources](https://www.ama-assn.org/practice-management/cpt/cpt-coding-resources).

The supported catalogue is a UTF-8 `code,description` CSV with exact SHA-256, count, version, effective interval and credential-free HTTPS provenance. Companion `quillmd-cpt-rules-v1` JSON supplies licensed index entries, per-code instructions and referenced criteria. Procedures require current performed-patient evidence and required details. Office E/M requires setting, new/established status and qualifying documented MDM or total practitioner time. Thresholds and qualifying terms must come from licensed material; unsupported vendor semantics require reviewed adapter work, never invented criteria.

After genuine materials arrive, follow the existing [protected provisioning commands](coding-cpt-integration.md#private-evidence-provisioning) and [declared import command](coding-cpt-integration.md#supported-import-and-readback):

1. Prepare the closed entitlement manifest with executed-agreement, rules and human permission-review hashes. Bind exact product/user/distribution/AI scope, current validity and dated release. A bare license ID/expiry cannot enable CPT.
2. Provision byte-identical copies for import and runtime identities: new `0700` directories, regular single-link `0600` files, no symlink components, verified UID/GID and actual readability. Copy only the manifest and its three referenced files; compare hashes. Keep licensed content outside tracked/public directories.
3. Set each identity's `QUILLMD_CPT_ENTITLEMENT_MANIFEST` to its absolute protected copy through the declared environment procedure. Default: `/opt/meddoc-pro/rebuild/.runtime/owner-contracts/cpt-entitlement-v1.json`.
4. Rehearse the actual feed/rules in an isolated database, then run the documented owner-role `import_terminology --system CPT` through `run-ruled-mutation.sh`. Retain import audit and provenance; imports make no provider requests.

Acceptance requires runtime `cpt_status(service_date)` to report available, license verified and dated release verified, with no missing requirements. Verify catalogue/rule hashes and counts, idempotent repeat import, and refusal of changed evidence or wrong dates. Exercise performed-procedure/E/M positives and planned/history/negated, ambiguous or incomplete evidence refusals. Separately authorized synthetic live acceptance must preserve clinical/export history and bind displayed selections to approval without an extra request. Keep CPT unavailable until these checks pass.
