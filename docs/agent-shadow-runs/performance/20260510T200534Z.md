### Phase 4 — Route TTFB

#### `PERFORMANCE_FINDING_002` — `audit_logs.metadata.responseTimeMs` zero rows

```sql
SELECT COUNT(*) FROM audit_logs WHERE metadata->>'responseTimeMs' IS NOT NULL;
-- 0
```

The `data-sources.md §1` for the Performance Auditor lists
`audit_logs.metadata` carrying `responseTimeMs` (emitted by
`withApiHandler`) — but in production, zero rows carry that
field. Either:

- `withApiHandler` does not emit response time, OR
- Emit path is wired but the metadata key name is different, OR
- The methodology's assumption was aspirational.

Phase 4 (route TTFB) emits `NO_DATA` for all three high-traffic
routes (`/visits`, `/visits/[id]`, `/visits/[id]/record`).

**Operator action:** decide whether to wire response-time
capture into `withApiHandler`'s audit log emission. Until then,
Phase 4 cannot produce signal — even after pilot traffic
ramps.

### Phase 5 — Bundle size

#### `PERFORMANCE_FINDING_003` — `app-build-manifest.json` absent; methodology data source incorrect

The methodology specifies reading
`apps/transcribe-md/.next/app-build-manifest.json`. That file
doesn't exist in the production container (`/app/apps/transcribe-md/.next/`).
Files present:

```
BUILD_ID
app-path-routes-manifest.json   ← lists 29 app routes (incl. /visits, /visits/[id])
build-manifest.json             ← top-level pages-router (mostly empty for App Router)
node_modules/
prerender-manifest.json
required-server-files.json
routes-manifest.json
server/
static/                          ← total: 2.5MB (all routes)
```

Next.js App Router emits per-route bundle composition via
`_buildManifest.js` (inside `static/<BUILD_ID>/`) or via
`react-loadable-manifest.json` — not via the
`app-build-manifest.json` the methodology assumed.

**Total `.next/static` size:** 2.5MB across all routes. Per-route
gzipped bundle size for the three high-traffic routes
(`/visits`, `/visits/[id]`, `/visits/[id]/record`) cannot be
computed without rewriting the data-source against the actual
manifest shape.

**Severity:** advisory at agent tier; the auditor's data-source
spec needs a one-line correction (the agent docs reference an
artifact that's not what App Router emits).

**Operator action:** either (a) update the methodology to read
`react-loadable-manifest.json` + the `_buildManifest.js` glob, OR
(b) wire a bundle-size capture step into CI that emits a
per-route JSON to a known path. Option (b) is more durable
because Next's manifest formats have shifted across versions.
