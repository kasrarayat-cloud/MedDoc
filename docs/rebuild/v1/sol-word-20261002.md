## Import and binding behavior

Explicit legacy/v3 imports receive the same provenance as auto imports. The fingerprint covers writer, parser, sandbox, layout and qualified-helper code plus installed parsing dependencies and the qualified WM binary manifest. Generation and export refuse a different processor under the same name. Historical empty manifests are retained as historical contracts; they are not retroactively reported as qualified new imports.

Auto compares physical answer destinations before paid generation. Compatible legacy forms keep their exact fields. V3 is selected for additional destinations only when the comparison preserves existing legacy destinations; silent omissions are reported and a retained incomplete/uncertain legacy choice blocks generation. This does not assert automatic whole-document completeness. The default remains legacy; private auto opt-in requires the lead's qualification decision. Stored encounter mappings never switch engines when the new-import setting changes.
