**Mapping expectations (7 forms, 45 areas, 23 controls).** Clinically and structurally, every expected answer area and control is right. Three are weak, and one piece of form wording should change (f6b's note). No expectation looks reverse-engineered from the engine: f3.A2/A3/A4 and f5.C2 are graded against it. The main problem is (c), whether the expectations can be tested through the app path.
- The model-assisted mapping path at 8e3dcfd0 cannot produce several of the frozen 'right' outcomes:
  - It has no `multi_choice` kind (`core/mapping_wire.py:14`, `core/mapping_assistance.py:38`).
  - A `not_answer` or `uncertain` verdict keeps the existing field (`mapping_assistance.py:173`).
  - Options must be printed at the target slot (`mapping_assistance.py:143,148`).
- As a result, f3.A2/A3/A4 and f5.C2 can never be graded 'right'. The frozen grader reads only the field list and never the review's unresolved records, so a correct model hold scores the same as doing nothing.
- f4's seven coded rows can only be reached through the deterministic layout proposal. The layout-path builder found that no deployed configuration runs it.

Three further problems:
- **f2 passes only because of one word.** The form passes only because its owner line ends in 'taken', a word the engine has a special rule for. With any other owner line, even 'Kinds of leave (all that occurred)', the engine maps the nine boxes as a single choice. That happens with or without the earlier '(please tick one)'.
- **f1.A2 cannot catch its own defect.** Its identity check cannot detect the guidance-leak label that the README calls discriminating.
- **f6b's note has a plausible answer.** The administrative note for the all-missing control plausibly answers A4 (the dressing appointment moved to Thursday afternoon).

**Notes expectations (16 cases).** The CONTRADICTION, SIDE, DENIAL, CORRECTION and missing-field expectations are clinically right, and the default-path leaks are honestly recorded. Five items need changing:
- **N06 Plan:** the reference selection is the earlier model's retained pick, which includes a non-plan sentence. That makes the field look as desired while the correct plan-only selection is held.
- **N05:** a silent blank is accepted as correct model behaviour for a J field.
- **N11/N12:** these are labelled S but are held today.
- **Supported-control desired texts:** these copy the engine's label-stripping output rather than an independent expectation.
- **N02 'worse' forbidden entry:** it is recorded as caught on field_relations. Replayed alone (the other fields selecting nothing), it is adopted. It is the only listed selection whose outcome changes when replayed alone.

Every notes form has all-zero fingerprints and overlapping zero-length anchors. The cases can therefore only run through the generation layer, never through upload, review and export.

**Wording check** (normalized substring of 25 characters or more against the 80 `dev/groundtruth/*.json` files). It is not clean. There are 4 distinct overlaps in provider-bound files, all short generic phrases:
- the N03 label shares 'this patient is subject to' with D31 A39;

- the f1 question shares 'Is the patient currently' with D31 A22 (25 only with a boundary space);
- the f5 declaration shares 'confirm that the patient' with D30 A62 / D31 A51 (26 only with boundary spaces).

A broader pass that adds options, contexts and titles found nothing more. A supplementary pass against all dev slot text found generic header words, plus 'within the hospital grounds' in f2, which D31 also prints. Rewording 3 strings (N03 label, f1 question, f5 declaration) clears the label check. f2's leave options also need rewording if the supplementary slot-text pass should come back clean too.
