## Next bounded D10 experiment

Current `layout_source.prepare` finds exact source character offsets in `segments`, splits runs using the existing property-preserving `_split_at`, and inserts bookmark starts at those boundaries. For smart tags it lifts only a start before their first child to before the unchanged wrapper. Current end boundaries require a carrier, causing the D10 failure.

A distinct next experiment is bookmark starts at the first and last REAL source characters, with end coordinates derived from the last glyph's actual PDF geometry/advance. The previous nonempty-range attempt DID NOT test this strategy; it moved bookmark ends across paragraphs and Writer omitted many ranges. Header labels are actual text glyphs.
