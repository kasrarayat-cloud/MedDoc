Refutation R1: an empty export fails the model_check stage; stage_passed requires its evidence retained

R1 (MEDIUM, lens: evidence), reproduced here first: with the product's finalize writing a 0-byte export, the
authenticated export answered 200 with an empty body whose sha256 (e3b0c442...) equals the finalized record's.
Both `if exported and export_sha != ...` and `if exported:` were skipped on the empty body, so the hash
comparison, the export.docx retention and the DOCX checks never ran, and run_model_check returned PASS with
reasons [] and wrote stage-model_check-passed.json with no export retained. RED before the fix:
test_an_empty_export_fails_the_stage_and_keeps_what_the_export_returned -> 'PASS' != 'FAIL'.

Root cause: checks guarded by the truthiness of the value they check. Fixed in rebuild/ops/sonnet5_qa.py:
- the export block: a non-200 is 'the authenticated export failed (<status>)'; on a 200, whatever came back is
  retained as export.docx (zero bytes included) and EVERY check runs on it. Emptiness is its own problem
  ('the authenticated export is empty: no export evidence was retained'), because an empty body's hash equals
  a record finalized from an empty file. The finalized-record hash comparison and export_checks are
  unconditional (empty -> 'not a valid DOCX'). export.json now records the status.
- defence in depth, in _decide: a stage about to pass is held to RETAINED_EVIDENCE (case files, request
  capture, provider result, records, both answer snapshots, export.docx, export.json, billing audit); a file
  that is missing, empty, a link or not regular fails the stage, and the reasons reach the manifest. A stage
  already failing is not held to it (it stopped early; naming files it never reached would bury why).
  With the ORIGINAL R1 export block restored, this gate alone fails the stage:
  ['the retained evidence export.docx is missing'].
No existing guard was weakened; the passed record's checks list gains 'evidence retained'.
