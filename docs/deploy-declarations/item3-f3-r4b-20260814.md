# §2.5 DEPLOY DECLARATION — item 3 + F3 + R4b

**Written and committed BEFORE the act.** Branch `fix/r4b-em-card-host`.

⚠️ **THIS DEPLOY CHANGES RUNTIME BEHAVIOUR IN THREE PLACES.** Unlike R5 — which
was a deletion whose gate had never fired — every one of these alters what the
product does on the next visit that runs.

| # | change | what actually differs at runtime |
|---|---|---|
| 1 | **the never-editorialize clause** | two new rules in `globalRules`, so **every L4 prompt** (SOAP *and* imaging) and **the L6 polish prompt** carry text they did not carry before. The model's input changes on every visit. |
| 2 | **the review banner** | `reviewReason` wording on structure-fail visits — L4 *and* L6 |
| 3 | **L4's write path** | review state moves from a plain `update` (REPLACE) to `applyAdditiveReviewState` (CONCAT) |

**MIGRATION:** one, DATA-only, idempotent, one row —
`20260814120000_resync_system_default_template_never_editorialize`. It re-syncs
the persisted system-default singleton to the TS constant. **Generated from the
TS source, never hand-transcribed.** No schema change.

⚠️ **NOTHING READS `globalRules` FROM THE DATABASE.** Both builders bind the TS
constant; the row is provenance. So the migration cannot change model behaviour
— but an unapplied one is drift, and the drift guard would go red.

## MUST CHANGE

- image ids for `transcribe-md` and `transcribe-md-worker`
- migrations **102 → 103**
- the shipped L4 + L6 prompts contain the clause (grep the built bundle)
- `/visits/[id]`: the E/M level card renders on the Rounds palette, not cream

## MUST NOT CHANGE

- **every clinical count**: visits 40, signed 25, patients 29, templates 9 —
  and `audit_logs` monotonic from 11360
- **⚠️ THE ALLERGY-CONFLICT REASON SURVIVES — A DECLARED ROW.** It is 0 today, so
  the number must stay 0 **for the reason that no conflict has occurred**, not
  because a banner ate it. If a conflict arises after this deploy, that visit's
  reason must contain BOTH the allergy sentence and any banner, allergy FIRST.
  This is the row F3 exists for, and it is the one to check first if anything
  looks wrong.
- **the 4 existing reviewReasons carrying the retired vocabulary are NOT
  rewritten.** No backfill. They are historical rows and stay exactly as they
  are; only newly-written reasons use the new wording.
- E/M and attestation gates, sign refusals, export bytes: untouched
- no clinical row moves

## MOVING BY DESIGN

- newly-written `reviewReason` values are longer and differently worded, and
  **bounded** — five names then "and K more"
- a structure-fail visit that already had a reason now shows BOTH, concatenated

## ⚠️ WHAT WOULD MAKE ME ROLL BACK

- any clinical count moving
- an allergy-conflict reason observed WITHOUT its earlier text
- a banner claiming content is unsupported (the wording says "could not be
  found"; "the dictation supported" must appear nowhere)
- a note containing meta-commentary about the template — the clause is meant to
  reduce that, and would be evidence it did the opposite
