- `note_templates` gains `sourceObjectKey` and `sourceSha256`, **NULL on all 9

## MUST NOT CHANGE

- **every clinical count**: visits 42, signed 25, patients 29, templates 9;
  `audit_logs` monotonic from 11382. **A deploy that moves a visit, patient or
  signature count has done something nobody asked for.**
- **NO EXISTING TEMPLATE IS MUTATED.** The aggregate fingerprint must read
  `64da402e2e65e86b21b61ebec9e010ce` afterwards — same ids, versions, statuses,
  `updatedAt` values and content digests. The migration adds two NULLABLE
  columns and touches no row's content.
- **NO VISIT CONTENT MOVES.** `soapDraft`, `soapFinal`, `reviewReason`,
  signatures: untouched. RC-2 does not run on the clinical generation path at
  all.
- **NO CERTIFICATION STATE IS INVENTED.** `certificationStatus = 'CERTIFIED'`
  stays **0**. `MAPPINGS_NOT_READY` is unchanged and still refuses. Compiled ≠
  certified, and nothing in this deploy certifies anything.
- no fill runs, no export bytes change, no native export path is enabled

## ⚠️ THE TWIN TABLES ARE EXPECTED TO STAY 0 — AND THE FIRST NON-ZERO IS A DOCTOR'S ACT, NOT THIS DEPLOY'S

`template_twin_source_artifacts` and `template_twin_compiled_versions` are **0**
now and **must still read 0 immediately after the deploy.** Compile-on-upload is
triggered by an upload; deploying it triggers nothing.

**They will stop being 0 on the first `.docx` a doctor uploads through
Settings → My Note Format after this deploy, and that is correct.** When it
happens:

- it contradicts every earlier report saying *"prod holds zero compiled
  versions"* — those were true when written and are superseded by a doctor's
  action, not by a defect;
- the row it creates is a **DRAFT** (`NEEDS_CONFIRMATION` or `UNSUPPORTED`),
  never certified;
- **a non-zero count in this deploy's own post-check IS a finding**, because
  nothing in the deploy should have uploaded anything.
